# Правила продукта Unica

В `rules/` — атомарные обязательства, согласованные владельцем.
Они не являются полным описанием продукта. Отсутствие записи не
отменяет существующие гарантии и их содержательные тесты.

Критерии правила, его предложение, изменение, отмену и разбор расхождений
с кодом или тестом задаёт
[unica-rules](../.agents/skills/unica-rules/SKILL.md). Формат записи описан ниже.

Правила сгруппированы по области продукта:

- `rules/core/` — границы слоёв и зависимости ядра;
- `rules/workspace/` — границы проекта, исходники и согласованность состояния;
- `rules/analysis/` — поиск, индексы, диагностика кода и справка;
- `rules/runtime/` — выполнение заданий, их состояние и журналы;
- `rules/mcp/` — инструменты и формат общения с MCP-клиентом;
- `rules/lsp/` — дверь LSP для редакторов: её граница с MCP, запись, адреса документов и ответы;
- `rules/distribution/` — установка, запуск и воспроизводимость поставки;
- `rules/platform/` — границы кода, зависящего от ОС и приложения-хоста.

Каждая запись содержит `id` и саму гарантию. Подтверждающий тест сам называет
правило пометкой `rule: <ID>` (в Rust — `/// rule: <ID>` над тестом, в Python —
строка в docstring). Тесты правила перечисляет
`python scripts/dev/rule-marks.py tests <ID>`, а в отчёте Allure они несут
метку `rule`. Поле `gap` со ссылкой на issue обозначает
известный разрыв реализации или подтверждения принятой гарантии; вид разрыва
уточняется в записи и issue.
Отсутствие теста само по себе не доказывает нарушение продукта.
Критерии устранения разрыва описаны в issue.

Правило можно найти по предмету, пути исходника или имени теста через `rg`.
История изменений доступна в Git.
