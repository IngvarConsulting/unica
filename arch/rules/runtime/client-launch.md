# Запуск клиента выполняется одним вызовом

`run` с `op: "launch"` запускает клиент одним вызовом и доступен
без набора исходников. Операция имеет режим `terminal`; `dryRun` необязателен.
Общие ограничения полей ревизии задаёт [словарь run](../mcp/run-operation-names.md).
`dryRun: true` возвращает план
без запуска; ответ раннера, сообщающий о запуске во время preview,
отклоняется.

Закрытые аргументы — `clientMode`, `debugUrl`, `webDebugUrl`, `execute`, `applicationParameter`,
`waitForExit`, `waitTimeoutMs`. Для `thin` аргумент `debugUrl` задаёт готовый
локальный HTTP-адрес сервера отладки с явным портом. Раннер получает ровно
этот адрес. При отказе запуска Unica не запускает клиента повторно без
отладки. Квитанция с PID и `debugState: "requested"` подтверждает запуск
с запросом отладки. Подключение клиента к серверу подтверждает DAP.

Для отладки веб-клиента IDE вызывает `web.publish` с аргументом `prepareDebug`
и явным `dryRun`. Аргумент содержит локальный HTTP-адрес сервера отладки
для DAP. Предпросмотр возвращает план. Исполнение подготавливает управляемую
публикацию либо проверяет маршрут внешней. Ответ различает `ideUrl` для IDE,
`debuggerUrl` для веб-клиента и `url` страницы. Если маршрут внешней публикации
недоступен, ответ содержит `data.runnerCode: "route_unavailable"` и называет
настройку владельца. Повторная подготовка исправной публикации сохраняет
работающие службы и сообщает `publicationChanged: false`.

IDE подключает DAP и добавляет `WEBClient` к выбранным типам автоподключения
до запуска браузера. Затем `launch` с `clientMode: "web"` принимает подтверждённый
`debuggerUrl` в аргументе `webDebugUrl`. Без этого аргумента доступен обычный
запуск той же публикации. Поле `providerDispatched` подтверждает передачу URL
системному браузеру. Подключение предмета, остановку на точке и шаг подтверждают
события DAP.

`applicationParameter` — точная строка `/C`
для enterprise-клиента: пустая строка отличается от отсутствия, NUL и
`designer` отклоняются. Параметр может сопровождать `execute` и не отражается
в публичном ответе. Ожидание завершения поддерживается для `thin` с
`execute` на `.epf` либо явным `applicationParameter`, `waitForExit`
и положительным `waitTimeoutMs`. Ответ называет версию и источник
платформы, PID и исход ожидания. Команда раннера, пути установки и журналов,
вывод клиента и строка соединения в него не переносятся.

При истечении `waitTimeoutMs` раннер завершает клиент. Подтверждённый
таймаут возвращает `provider_failed` с PID и исходом ожидания в `data`,
без записи в `changed` и предложения повторить запуск. Неуспешная
квитанция проходит общие проверки сеанса и ожидания; текст ошибки
провайдера не подтверждает таймаут.

Сведения о сеансе подтверждает провайдер. Проверки исполняют адаптер
с управляемыми ответами раннера, без запуска настоящей платформы 1С.

При запуске без ожидания Unica владеет деревом процессов до полного чтения
и проверки квитанции раннера. Отказ или отмена до передачи владения завершают
принадлежащие запуску процессы. Проверенная квитанция разрешает отделить
клиент от Unica; эта передача упорядочена с отменой. После неё отмена
не завершает подтверждённый сеанс и не заменяет результат запуска отказом.
Аварийное завершение между внешним эффектом и сохранением результата
обрабатывается по [правилу квитанций](invocation-at-most-once.md).
