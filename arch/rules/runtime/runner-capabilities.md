# Известная операция не обещает поддержку всех её режимов

`support.state` различает `supported` и `limited`.
Ограниченная операция сообщает адаптер, причину и `supportedArgs`.
Неподдерживаемый запрос получает отказ до допуска исходников и запуска
платформы, а не успешный preview.

Словарь публикует операции, доступные в установленном комплекте Unica. Операции разработки
`push`, `pull`, `fetch` и `infobase.create` имеют статус `limited` с точной схемой
аргументов и описанием отсутствующих гарантий. `upload`, `apply` и `reset`
в каталоге не перечислены: `upload` раннера применяет конфигурацию БД,
а `push --no-apply`, `apply` и `reset` раннера адаптер ещё не исполняет.
Их вызов получает отказ `unsupported_operation`, причина называет этот разрыв. Границы
операций описывает [совместимый цикл разработки](compatible-development-cycle.md).
Старые имена не становятся алиасами.
Верхнеуровневый `infobase` поддерживает только `origin`; другая цель
не заменяется им молча. Общие поля режима и условия исполнения задаёт
[словарь run](../mcp/run-operation-names.md).

Для отладки Designer ищет в словаре строку `debug-server.start` с полем
`contractVersion: 2`. Вместе с ней доступна операция `debug-server.stop`.
При установке через bootstrap словарь показывает обе операции ещё до
первой загрузки раннера, если поставка подтверждает точную совместимую
версию и артефакт для текущей платформы. Сам запрос словаря ничего
не скачивает. Первый запуск доставляет раннер штатным способом и проверяет
его бинарник перед выполнением. Если сведения о поставке неполны, версия
несовместима или установленный бинарник повреждён, обе операции скрыты,
а прямой вызов возвращает `unsupported_operation` до обращения к ИБ.

Для `debug-server.start` Designer передаёт только `args.ownerPid`.
В ответе `action: prepared` поля `url` и `infoBaseAlias` указывают адрес
и базу для отладчика. Поле `scope` сообщает доступность отладки клиента или
клиента и сервера. Поле `owner` называет подтверждённого владельца сервера
(`runner`, `cluster`, `standalone` или `external`). Для заимствованного сервера
`release` равен `null`.
Каждый запуск со своим локальным сервером возвращает отдельную операцию
`release` с токеном сеанса. Завершение одной аренды сохраняет процесс,
пока им пользуется другая. Предпросмотр возвращает `action: planned`
без адреса и токена.
