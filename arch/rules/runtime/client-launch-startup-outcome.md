# Запуск клиента предприятия сообщает подтверждённый исход входа

Интерактивный `launch` клиента `thin`, `thick` или `ordinary` без
`waitForExit` отвечает после наблюдения за стартом: раннер следит за
процессом и журналом регистрации ИБ ограниченное время. Ответ содержит
`startup.outcome` и связан с этой попыткой:

- `started` — журнал подтвердил вход этой попытки, клиент продолжает работу;
- `auth_failed` — журнал подтвердил отказ аутентификации этой попытки;
- `start_failed` — процесс завершился с ненулевым кодом без отказа
  аутентификации, в том числе после входа;
- `closed` — процесс завершился с кодом 0 без события отказа;
- `unconfirmed` — окно истекло, журнал недоступен или событие нельзя
  однозначно отнести к попытке.

`auth_failed` отвечает отказом `provider_unavailable` с уточнением
`credentials_rejected`, как [отказ пользователя ИБ](runner-environment-layer.md),
`start_failed` — `provider_failed`; в `data` остаются PID, платформа
и `startup`. Остальные
исходы успешны; живой сеанс (`started`, `unconfirmed`) записывается
в `changed`. Признак берётся из типизированного ответа раннера: время жизни
процесса, общий код выхода и текст клиента отказ входа не подтверждают.
`startup` содержит только исход, время события с точностью до секунды и код
выхода; пароля, командной строки и вывода `/Out` в нём нет.

Если журнал регистрации базы недоступен (серверная ИБ, подключение `/WS`),
`unconfirmed` отдаётся сразу после старта клиента, без ожидания окна.

Ожидание исхода входит в один вызов: не уложившийся в окно прямого ответа
запуск продолжается [заданием](initial-submit-result.md). Передача владения
клиентом по [контракту запуска](client-launch.md) происходит после проверки
ответа с исходом.
