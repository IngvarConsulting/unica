# Вызов, который уничтожает данные, исполняется с согласия человека

Исполняемые `push` с `force:true`, `infobase.restore` с `mode: replace`,
удаление установленного расширения, а также `pull` с `force:true` над набором
с несохранёнными правками или не под git исполняются только с согласия
человека. Unica спрашивает его по [правилу вопроса](../mcp/human-choice.md)
до допуска вызова и до запуска раннера: вызов, ставший фоновой задачей,
спросить уже не может.

Без согласия вызов отменяется отказом `cancelled`, база и исходники не
меняются. Клиент, который спрашивать не умеет, исполняет вызов как прежде.
Одноразовое согласие относится только к тому вызову, о котором спрашивали:
другой набор, файл или аргумент требует нового вопроса. Исключение — явно
сохранённое человеком разрешение на `push` с `force:true` для конкретной
базы, описанное ниже. Выбор варианта другого вопроса,
который сам перезаписывает данные, — «Перезаписать базу» при расхождении базы
и набора и «Заменить данные базы данными из «<файл>»», когда загружаемая база
уже есть, — засчитывается как согласие на этот вызов. Выбор «Перезаписать
исходники» при расхождении базы и набора согласием не засчитывается:
несохранённые правки проверяет вопрос `pull`. Превью не спрашивает.

`push` с `force:true` спрашивает «Перезаписать базу «<имя>» исходниками
набора «<набор>»?», для нескольких наборов — «…исходниками наборов «<a>»,
«<b>»?». Вариант — «Перезаписать базу»: изменения, сделанные в базе после
последнего обмена, пропадут. Код вопроса — `infobase.push_force`.

Когда фактическую базу можно однозначно определить из соединения `File=`
или пары `Srvr`/`Ref`, вопрос предлагает также «Разрешить для этой базы и
запомнить». Вариант называет адрес базы без учётных данных. Только этот
ответ человека сохраняет разрешение; модель не может передать его как
аргумент инструмента. Одноразовый вариант остаётся первым, и клиент без
поддержки вопросов разрешение не сохраняет. Превью его также не сохраняет.

Разрешение принадлежит локальному пользователю, хранится вне проекта и
переживает перезапуск и обновление Unica. Оно действует для загрузки любых
наборов через `push` с `force:true` только в ту же базу: файловый путь
разрешается относительно проекта и канонизируется; сервер и имя серверной
базы сравниваются без объединения разных адресов сервера. Логин и пароль
разрешение не определяют и в нём не сохраняются. Неоднозначное соединение,
подстановка переменных, raw argv и автономный сервер сохраняют одноразовый
вопрос. Смена цели между вопросом, ответом и запуском провайдера не даёт
разрешения новой базе. Отсутствующий, повреждённый или отозванный файл
разрешения не разрешает запись. Удаление файла отзывает разрешение.
Восстановление DT, удаление расширения, `pull`, завершение сеансов и
перезапуск сервера это разрешение не покрывает.

`infobase.restore` с `mode: replace` спрашивает «Заменить данные базы «<имя>»
данными из «<файл>»?». Вариант — «Заменить данные»: данные и конфигурация базы
пропадут. Код вопроса — `infobase.restore_replace`.

Удаление установленного расширения — `push` с `delete` — спрашивает «Удалить
расширение «<расширение>» из базы «<имя>»?». Вариант — «Удалить расширение»:
данные расширения в базе пропадут. Код вопроса — `extension.delete`.

`pull` с `force:true` спрашивает, только если в каталоге набора есть
несохранённые правки или каталог не под git; чистый набор не спрашивает. При
правках — «В исходниках набора «<набор>» есть несохранённые правки, файлов:
<N>.» Вариант — «Перезаписать исходники»: правки пропадут, файлов: <N>. При
отмене — «Сохраните правки в git и повторите». Не под git — «Исходники набора
«<набор>» не под git: несохранённые правки проверить нельзя.» Вариант —
«Перезаписать исходники»: правки в файлах набора пропадут. Код вопроса —
`source.pull_unsaved`. Если число правок изменилось, прежнее согласие не
годится, и вопрос задаётся заново.
