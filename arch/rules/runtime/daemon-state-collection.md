# Каталоги демонов прежних сборок убираются, живые не трогаются

У каждой сборки свой каталог состояния демона
([идентичность демона](daemon-identity.md)), поэтому в общем корне состояния
копятся каталоги сборок, которые больше не запускаются. Демон при старте
в фоне убирает их и не задерживает этим свою готовность. Ошибка уборки
не влияет на запуск.

Кандидат — только каталог `daemon-p5-<идентичность>` другой сборки: настоящий
каталог, а не ссылка, без изменений в нём и его прямых элементах не меньше
семи дней. Каталог удаляется, только если удалось взять обе его блокировки:
блокировку запуска, которую держит запускающий демон frontend, и полномочие
квитанций, которое живой демон держит всё время жизни. Занятая блокировка
оставляет каталог на месте. Осмотр кандидата его не создаёт.

Каталог сначала переименовывается в корзину `.trash-daemon-*` и только потом
удаляется, без перехода по ссылкам. Прерванная уборка оставляет либо целый
каталог под прежним именем, либо корзину, которую уберёт следующий запуск.
Где блокировки сами закрепляют свой каталог (Windows), они отпускаются перед
переименованием: процесс, успевший открыть блокировку, срывает переименование.

Frontend другой сборки, открывший каталог в момент переименования, получает
отказ этого запуска и не пишет в корзину; следующий запуск создаёт каталог
заново. Для этого две сборки должны стартовать одновременно после недели
простоя одной из них.

Каталоги снятого протокола (`daemon-p3-*`) и всё прочее в корне не трогаются:
их блокировки этому коду не принадлежат, и доказать, что их демон не жив,
он не может. Такие каталоги удаляют вручную, когда хосты закрыты.
