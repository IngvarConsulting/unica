# Домен не импортирует файловые API, окружение и управление процессами

Пакет `unica-domain`, самостоятельные семантические пакеты (объявление
`file-io = "domain"`) и модули `src/model/` компонентов со сценарием приложения
не используют `std::fs`, `std::env` и `std::process`. Явные файловые вызовы
через стандартные типы `Path` и `PathBuf`, например `Path::exists(path)`,
также запрещены.

Чистые операции над путём, например соединение компонентов, допустимы: они не
обращаются к файловой системе. Явно адресованный файловый вызов запрещён и
через псевдоним стандартного типа. Вызов методом вида `path.exists()`
распознаётся по типу получателя в `src/` самостоятельных пакетов с этим
ограничением, включая `#[cfg(test)]` и код под признаками. Модули `src/model/`
других компонентов проверяются только по тексту, и вызов методом там не
распознаётся.

Пакеты, объявившие в `[package.metadata.unica]` `file-io = "none"`, —
Designer-кодеки (`unica-<семейство>-designer`) и пакеты, которые читают
исходники только через порты, — также не используют `std::fs` и явные
файловые вызовы через `Path` и `PathBuf` в `src/`, включая модули
`#[cfg(test)]`. Исходники они читают через порты чтения, которые выдаёт
владелец workspace, а не открывают файлы в обход него. `std::env`
и `std::process` им доступны. Тесты, которым нужна файловая система,
находятся в `tests/` пакета. Пакет, на который ограничение уже
распространено, не снимает его своим объявлением: для этого нужно изменить
проверку. Новый пакет вступает в ограничение объявлением.

Сторонние файловые крейты (`walkdir`, `fs-err`, `tempfile`, `tokio`
с признаком `fs` и подобные) в этих пакетах тоже запрещены. Обычная или
build-зависимость на них отвергается по манифесту, в том числе когда
признак `fs` открывает `[features]`. Путь к ним в `src/` отвергается даже
через dev-зависимость, а переименованная dev-зависимость на такой крейт
отвергается по манифесту. Dev-зависимости остаются доступны тестам в `tests/`.
