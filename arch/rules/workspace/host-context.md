# Рабочую папку вызова ограничивает приложение-хост

Множество папок, в которых может работать вызов, задаёт контекст хоста вне
аргументов инструмента. Модель не называет папку вне этого множества; внутри
него она может выбрать папку аргументом `workspace` предметного инструмента.
Метаданные текущего вызова имеют приоритет над переменными окружения,
захваченными при запуске frontend. Контекст и выбор одного вызова не изменяют
папку следующих вызовов или других frontend общего демона.

Адаптер запрашивает у Codex `codex/sandbox-state-meta` и читает `sandboxCwd`
из `_meta` вызова: абсолютный путь либо локальный `file://` URI. Это множество
из одной папки. Клиент, объявивший MCP `roots`, отдаёт их на каждый вызов без
таких метаданных: в сессии до протокола 2026-07-28 — ответом на `roots/list`,
с протокола 2026-07-28 — ответом на запрос ввода, который Unica задаёт каждому
предметному вызову. Множество — все переданные roots,
локальные `file://` URI. Без выбора рабочей папкой остаётся первый root: первым
Claude Code ставит каталог проекта сессии, а не каталог оболочки после `cd`.
Roots спрашиваются заново, поэтому папка, открытая сессии позже, доступна
со следующего вызова; управление заданиями рабочей папки не требует и roots
не спрашивает. Пустой список или сорванный обмен — ошибка, таймаут, закрытый
транспорт — контекста не передают.

Переменные окружения захватываются при запуске frontend, стоят ниже roots и
дают множество из одной папки: Claude Code передаёт `CLAUDE_PROJECT_DIR`,
ZCode — `ZCODE_PROJECT_DIR` или совместимый `CLAUDE_PROJECT_DIR`. Если обе
переменные заданы, они должны указывать на одну папку. Расхождение roots
с переменной ошибкой не считается. Переданная хостом папка должна существовать.

Каждой папке множества Unica выдаёт имя пространства по тому же правилу, что
пространствам адреса документа в [двери LSP](../lsp/document-address.md).
Выбор — это имя пространства и, если нужно, подпапка внутри него; путь или
URI выбором не являются даже для разрешённой папки. Выбранная подпапка после
разрешения ссылок и junction лежит в своём пространстве; демон получает этот
разрешённый путь. Файл
проекта выбранной папки не берётся из каталога выше папки множества. Иначе,
как и при некорректном переданном контексте, — отказ `invalid_state` без
подстановки другой папки. Ответ человека на вопрос вызова и начатого им
задания исполняется в той же папке, пока frontend помнит это задание. Упакованный плагин требует контекст хоста; его технический cwd не
становится рабочим пространством. Прямой запуск бинарника без этого требования
сохраняет fallback на cwd запуска. Каталог демона остаётся служебным, а рабочая
папка передаётся в каждое предметное обращение явно.

Каждый ответ с `workspaceRoot` называет рядом в `workspaceRootOrigin` канал,
выбравший каталог (`requestMetadata`, `clientRoots` с root, где лежит
каталог, `startupEnvironment` с именем переменной, `launchCwd`), явный выбор
(`selected`) и сам запрошенный каталог: корень может оказаться его предком.
`unica.view {}` без выбора перечисляет множество в `available`: имя
пространства и папку, есть ли в ней `v8project.yaml` и вложенные папки со своим. Если клиент в сессии
до протокола 2026-07-28 объявил roots, но канал запуска остался главным, ответ
называет причину из закрытого набора (`empty`, `error`, `timeout`, `closed`)
без текста ошибки клиента. Для каналов, захваченных при запуске, ответ
подсказывает, как перейти к другому проекту. Канал объясняет каталог и
в идентичность запроса не входит.

Особенности приложений сосредоточены в [адаптере хоста](../platform/host-integration.md).
Разделение состояния сохраняет [идентичность workspace и профиля](source-profile-state-isolation.md).
