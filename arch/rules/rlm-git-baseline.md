# Актуальность данных индекса проверяется от его Git-основы

Для исходников в Git индекс RLM хранит репозиторий, полный хеш базового коммита
и сведения о фактически проиндексированных отклонениях от него. Локальные
правки не запрещают индексацию и не теряются при записи её исходного состояния.

Текущее состояние сравнивается с проиндексированным, а не с новым `HEAD`. Ответ
указывает основу индекса и затронутые изменениями файлы в области запроса:
изменённые, добавленные, удалённые или переименованные. Сравнение охватывает
прежние входы индекса и нынешние исходники, подлежащие индексации: подготовленные
к коммиту и остальные локальные правки, в том числе новые неотслеживаемые
и игнорируемые файлы. Отсутствие нового файла в старом индексе не исключает
его из сравнения.

Совпадение файла с проиндексированным состоянием подтверждает актуальность
данных о его содержимом на момент проверки. Для связей между файлами и вывода
об отсутствии совпадений учитываются также зависимые входы; неизменность
одного файла не доказывает актуальность всего результата.

Если исходное состояние, полноту сравнения или отсутствие гонки подтвердить
нельзя, актуальность явно обозначается как неизвестная. Это не мешает
[чтению пригодного индекса](rlm-stale-results.md).
