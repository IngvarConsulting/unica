# Комментарий метода конфигурации отдаётся полями, не теряя текста

Метод конфигурации приходит не только подписью: рядом с текстом его
документирующего комментария Unica отдаёт этот комментарий полями —
описание, параметры, возвращаемое значение, пример, варианты вызова и
«см. также». Параметр несёт имя, типы, описание и ключи коллекции, которые
комментарий описывает вложенно.

Разделы читаются по стандарту разработки 1С: заголовок раздела на краю
комментария, запись на отступе первой записи своего раздела, строка глубже
продолжает описание записи, строка `- Тип - …` добавляет записи
альтернативный тип. Раздел, которого стандарт не называет, остаётся под
своим заголовком среди прочих разделов, а не исчезает.

Типы комментарий называет текстом, и текстом они и приходят: что текст
означает, решает прикладная модель конфигурации, а не справка по коду.
Запись, называющая параметр без типа, остаётся параметром с пустыми типами:
недокументированный тип не выдумывается.

Текст комментария остаётся в ответе рядом с полями. Комментарий, написанный
не по стандарту, полей не даёт, но доходит до потребителя целиком: разбор
добавляет поля и никогда не заменяет собой написанное человеком. Положения
полей — те же, что у статьи справки платформы, по
[трём состояниям](article-field-states.md): пустое поле и неразобранный
раздел различимы, причина и сырой текст неразобранного раздела приходят
рядом, а ответ называет версию схемы формата.

Устройство комментария читается одним разбором: справка по коду и
прикладная модель типов не могут понимать один комментарий по-разному.
