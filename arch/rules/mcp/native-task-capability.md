# Встроенные задания MCP доступны только клиенту с Tasks capability

В канонической поверхности v0.13 ответ `CreateTaskResult` и методы `tasks/*`
доступны только при протоколе `2026-07-28` и явно объявленной клиентом
Tasks capability. Для прямого запроса это объявление относится к самому
запросу. Метаданные отдельного запроса не повышают legacy-сессию до нового
протокола.

Вызов `2026-07-28` без Tasks в самом `tools/call`, ставший заданием, ждёт
его завершения и отвечает тем же итогом, что и `unica.task.result`.
Исполняемый `unica.run push` ждёт одно ограниченное окно наблюдения.
Если принятому `push` требуется больше времени, клиент получает квитанцию
с тем же `taskId` и продолжением на [`unica.task.result`](mcp-tool-profiles.md).
Короткий `push` получает терминальный ответ в исходном вызове.

При ожидании клиенту с `progressToken` идут `notifications/progress`.
Отмена исходного вызова во время ожидания запрашивает отмену задания.
Потерянное чтение повторяется для того же задания в пределах окна.
Если задание больше не удаётся наблюдать, ответ сообщает отказ с исходом
`needsHuman`. Для `push` временный сбой наблюдения в пределах
ограниченного окна может завершиться выдачей уже принятой квитанции.

Проекция задания, его получение, обновление, отмена и опрос не запускают
предметную операцию повторно.
