# Конвейер тестов: размер вне теста, результат из джобы, исследование — не тест

**Решение.** Тест несёт размер — `small`, `medium`, `large` — объявленный вне
его кода, в профилях запуска, и исполняемый сроком. Ворота конвейера выбирают
по размеру и контуру: pull request — `small`, очередь слияния и push в линию —
`small` с `medium`, тег и ночь по сдвинувшейся линии — `large`. Каждая джоба
отдаёт `allure-results` с метками, планом и подписью прогона; сайт складывает
их и хранит как единственную долговременную память. Доказательство, которое не
меняется от правок кода, — `research`: проводится один раз, закрепляется
артефактом и записью, в workflow не попадает.

**Что чинит.** Конвейер выбирал, что гонять, по одному признаку — какие файлы
изменились — и не различал доказательство на каждую правку от доказательства
раз в релиз. Машинного результата не оставлял никто, гейт видел джобы, а не
тесты; отключённый тест исчезал из поля зрения без следа.

**Чем держится.** Умный отбор теряет до 55% отказов, пакетирование — ни
одного; 84% переходов «прошёл → упал» — нестабильность; размер как объективный
признак предсказывает её лучше слов «модульный» и «интеграционный». Профили
nextest дают объявление вне теста для 4 555 тестов без правки одного. Проба на
26 тестах показала: адаптер Allure для Rust не видит отключённых и ломается под
процессом на тест, а JUnit приходит без меток — поэтому результат пишет джоба.

**Цена.** Переводчик JUnit → `allure-results` в `run-tests.py` и класс
результата для `unittest` — наш код. Объявление размера по именам и путям
разъезжается с деревом при переименовании — против этого страж состава.
Расстановка размеров по тестам остаётся отдельной работой с отдельной ценой
ошибки.
