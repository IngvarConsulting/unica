# Узел файловой природы отдаёт содержимое, а не свойства

**Решение.** У узлов три природы, и слоты ответа зависят от неё: составной узел
несёт `props` и `branches`, ветка — `items` и продолжение, а узел, чья суть есть
содержимое файла, несёт `content`. Постраничность внутри `content` режет по
строкам, не по байтам. Модуль BSL — частный, структурированный случай такого
узла; прочие файловые узлы отдают текст как есть.

**Почему.** Без этого слота просмотр модуля формально не определён: у модуля нет
ни веток, ни свойств в обычном смысле — у него есть текст. Байтовое окно
проверено и не годится: на модуле БСП оно разорвало строку на всех девяти
границах и поделило кириллицу пополам, потому что в UTF-8 она занимает два
байта.

**Цена.** Форма ответа перестаёт быть одинаковой для всех узлов: читатель
обязан посмотреть на природу прежде, чем искать слот. Дисциплина слотов это
удерживает — имена фиксированы, меняется только их набор, — но однообразия
больше нет.
