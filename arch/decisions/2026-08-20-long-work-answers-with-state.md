# Доставка зависимости отвечает состоянием раньше, чем её обрывает хост

**Решение.** Когда предметный вызов должен доставить отсутствующий движок,
сервер ждёт доставку ограниченное время. Дождался — выполняет исходный вызов.
Не дождался, но может ответить без движка — возвращает доступный результат и
называет недостающее. Не дождался и ответить нечем — возвращает **успешный**
результат с состоянием `working`, описанием работы и интервалом повтора. Клиент
повторяет тот же предметный вызов с теми же аргументами.

**Доставка принадлежит серверу.** Отмена вызова её не отменяет, следующий
вызов присоединяется к той же доставке, а не начинает вторую. Список
инструментов полон всегда: холодный кеш поверхность не сужает.

**Почему в исходном вызове.** Доставка — условие выполнения предметной
операции, а не выбранная пользователем долговременная runtime-работа. Отдельный
идентификатор превратил бы холодный кеш в дополнительный публичный workflow.

**Почему раньше хоста.** Хост обрывает вызов своим сроком, и его ответ —
`Request timed out` без слова о том, что работа шла. Ответить самим — единственный
способ, которым вызывающий узнаёт состояние: чужой срез уносит наш ответ целиком.

**Почему не прогрессом.** Замер 20.08: семь уведомлений отправлено, в стенограмме
сессии их ноль при том же маркере в терминальном результате — дважды. Прогресс до
модели не доходит и срок хоста не сдвигает. Он остаётся ради человека у экрана.

**Граница.** Явно выбранные `unica.runtime.job.*` остаются отдельным контрактом
для долговременных runtime-операций. Это решение их не отменяет и не обобщает
ответ доставки на построение индекса или другую фоновую работу.

**Цена.** Первый ответ может быть содержательно пуст, и агент обязан повторить
исходный вызов. Клиент отличает это состояние от ошибки по `ok: true`.
