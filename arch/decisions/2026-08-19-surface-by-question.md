# Вход отвечает на вопрос, а не обслуживает предмет

**Решение.** Публичная поверхность делится по вопросам вызывающего, а не по
видам объектов: один вход — один вопрос, вопросы не пересекаются, и ни один
предмет не заводит собственного входа. Словарь операций живёт в данных, а не в
каталоге инструментов. Перечень входов эта запись не содержит: каждый вход
описан своим решением и заменяется отдельно.

**Почему.** Выбор инструмента — задача припоминания, и её надёжность падает с
длиной списка. Замер 18.08: каталог из 71 инструмента стоит 56 314 токенов на
эпизод, то есть 95–97 % его стоимости, при том что сама работа укладывается в
целевые бюджеты. Деление по предмету умножает список на число видов, деление по
вопросу — нет.

**Почему перечень вынесен.** Прежняя запись называла число и восемь имён, из-за
чего добавление входа отменяло вместе с ними и принцип. Замена решения не должна
требовать правки соседей; значит счёт и состав — не часть этого решения.

**Цена.** Состав поверхности перестаёт читаться одной записью: чтобы узнать
перечень, нужен индекс по префиксу `ENTRY-`. Взамен добавление, замена и правка
входа стоят одной записи каждая.
