# Attach к серверу отладки 1С

Запустите `unica dap` как DAP-адаптер по stdio. Для `attach` передайте
абсолютный путь к рабочему пространству Unica с исходниками тестовой базы
и порт уже запущенного локального `dbgs`.

```json
{
  "rootProject": "/absolute/path/to/workspace",
  "infoBaseAlias": "DefAlias",
  "debugServerPort": 19550
}
```

Unica обнаруживает наборы исходников по `v8project.yaml` или по структуре
рабочего пространства. Поле `sourceSet` можно опустить. Если оно передано,
имя должно совпадать с одним из обнаруженных наборов.
Сохранённые исходники должны соответствовать загруженной базе и расширениям.
Алиас и порт по умолчанию — `DefAlias` и `1550`. Клиент 1С
должен быть запущен с HTTP-отладкой и адресом этого сервера. После
`initialized` отправьте `setBreakpoints` и `configurationDone`.

В `Source.path` передаётся квалифицированный адрес Unica, например
`main:DataProcessor.Обработка.Module.Object` или
`main:DataProcessor.Обработка.Form.Форма.Module.Form`. Строки и колонки
начинаются с единицы. Поддерживаются общие и объектные модули, сохранённые
BSL-модули форм и модуль управляемого приложения из основной конфигурации
и расширений. В сеансе доступны безусловные точки, стек, локальные переменные,
шаг, продолжение и отсоединение.

Локальные переменные относятся к выбранному кадру стека. Раскрываемые
значения возвращают `variablesReference` для запроса именованных свойств,
например вложенных полей структуры. Ссылки действуют до продолжения
исполнения или смены остановки. На новой остановке запрашивайте их заново
через `stackTrace`, `scopes` и `variables`.

Запускайте клиент для этого сценария с
`/DEBUG -http -attach /DEBUGGERURL http://127.0.0.1:19550`, подставив порт
из `attach`. Ответ `setBreakpoints` подтверждает принятие списка сервером.
Фактическая строка исполнения приходит в стеке после остановки.
