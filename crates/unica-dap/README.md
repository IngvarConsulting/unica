# Attach к серверу отладки 1С

Запустите `unica dap` как DAP-адаптер по stdio. Для `attach` передайте
абсолютный путь к рабочему пространству Unica с исходниками тестовой базы
и порт уже запущенного локального `dbgs`.

```json
{
  "rootProject": "/absolute/path/to/workspace",
  "infoBaseAlias": "DefAlias",
  "debugServerPort": 19550
}
```

Unica обнаруживает наборы исходников по `v8project.yaml` или по структуре
рабочего пространства. Поле `sourceSet` можно опустить. Если оно передано,
имя должно совпадать с одним из обнаруженных наборов.
Сохранённые исходники должны соответствовать загруженной базе и расширениям.
Алиас и порт по умолчанию — `DefAlias` и `1550`. Клиент 1С
должен быть запущен с HTTP-отладкой и адресом этого сервера. После
`initialized` отправьте `setBreakpoints` и `configurationDone`.

В `Source.path` передаётся квалифицированный адрес Unica, например
`main:DataProcessor.Обработка.Module.Object` или
`main:DataProcessor.Обработка.Form.Форма.Module.Form`. Строки и колонки
начинаются с единицы. Поддерживаются общие и объектные модули, сохранённые
BSL-модули форм и модуль управляемого приложения из основной конфигурации
и расширений. В сеансе доступны безусловные точки, стек, локальные переменные,
шаг, продолжение и отсоединение.

`attach` определяет наборы рабочего пространства и проверяет имя явно выбранного
набора. Подходит сохранённая конфигурация или расширение в формате Designer
с файлом `Configuration.xml` в корне набора. Набор может не содержать ни
одного BSL-модуля. Для подключения адаптер
регистрируется на `dbgs` и передаёт ему настройки автоподключения. На этом
этапе адаптер не перечисляет модули и не читает их дескрипторы или BSL.

При постановке точки адаптер проверяет регистрацию и сохранённый BSL по
адресу из `Source.path`. В `dbgs` он передаёт UUID владельца, UUID свойства
модуля и имя расширения. Поиск владельца по всей выгрузке при этом не нужен.
Сервер принимает весь список точек одним запросом. Поэтому адаптер также
перепроверяет адреса остальных установленных точек. Если владелец исчез или
у него изменился идентификатор, его старые строки исключаются из списка.
Если два выбранных адреса имеют один полный идентификатор, запрос отклоняется.

При остановке на точке, по ошибке или после шага адаптер читает имя каждого кадра.
Например, `Документ.Заказ.Форма.Основная.Форма.ПриОткрытии()` указывает
на модуль формы «Основная» документа «Заказ». Для общего модуля адаптер
принимает `ИсправлениеДокументов.ПриСозданииНаСервере(...)` и полное написание
`ОбщийМодуль.ИсправлениеДокументов.Модуль.ПриСозданииНаСервере(...)`.
В имени кадра расширения перед именем модуля может стоять имя расширения
через пробел. Адаптер сверяет его с `extensionName` в идентификаторе кадра.
Кадр `Обработка.МассоваяПроверка.МодульОбъекта.Выполнить()` указывает
на модуль объекта встроенной обработки «МассоваяПроверка».
Чтобы показать файл, адаптер сверяет полный идентификатор кадра с сохранённым
модулем. Если кадр содержит только имя метода и платформа сообщила
о срабатывании установленной точки, адаптер сверяет её строку и идентификатор
по известному адресу.

Для остальных кадров адаптер ищет неизвестные идентификаторы вместе. Если
поиск нашёл единственный адрес, на следующем шаге достаточно проверить его
регистрацию, BSL и идентификатор. Изменение владельца или состава наборов
требует нового поиска. Когда источник недоступен или остаются несколько
подходящих владельцев, в стеке видны имя кадра и строка без пути к файлу.
Выгрузка должна соответствовать запущенной ИБ. Изменение UUID другого
модуля во внешнем редакторе может остаться незамеченным, пока адаптер
пользуется ранее найденным адресом.

При шаге внутрь вызова (F11) из конфигурации в подключённую внешнюю
обработку адаптер ищет модуль объекта среди выгруженных внешних обработок
проекта. Если имя и идентификатор совпали у одной обработки, её строка
открывается по адресу вида `epf:ExternalDataProcessor.Импорт.Module.Object`.
При отсутствии подходящих исходников или нескольких совпадениях кадр
сохраняет имя и строку. Из него можно продолжить шаги или вернуться
в вызывающий модуль (Shift+F11).

Локальные переменные относятся к выбранному кадру стека. Раскрываемые
значения возвращают `variablesReference` для запроса именованных свойств,
например вложенных полей структуры. Ссылки действуют до продолжения
исполнения или смены остановки. На новой остановке запрашивайте их заново
через `stackTrace`, `scopes` и `variables`.

Запускайте клиент для этого сценария с
`/DEBUG -http -attach /DEBUGGERURL http://127.0.0.1:19550`, подставив порт
из `attach`. Ответ `setBreakpoints` подтверждает принятие списка сервером.
Фактическая строка исполнения приходит в стеке после остановки.

## Предметы отладки

После `attach` редактор может отправить дополнительные DAP-запросы:

| Запрос | Аргументы | Ответ |
| --- | --- | --- |
| `unica/debugTargets` | `{}` | `{targets, types, autoAttachTypes}` |
| `unica/attachDebugTarget` | `{id}` | `{threadId}` |
| `unica/setAutoAttachTypes` | `{types}` | `{autoAttachTypes}` |

Каждый элемент `targets` содержит UUID цели `id`, тип платформы `type`
и признак подключения к текущему адаптеру `connected`. Для подключённой
цели возвращается `threadId`. Имя пользователя `name` и номер сеанса
`sessionNumber` возвращаются, если их прислал сервер.

По умолчанию автоматически подключаются `Client`, `ManagedClient` и
`ServerEmulation`. Чтобы заменить набор, передайте массив типов из
`types` ответа `unica/debugTargets`. Пустой массив отключает новые
автоподключения. Изменение набора сохраняет уже подключённые потоки.
Ручное подключение возвращает существующий поток при повторном запросе.
Если цель исчезла из списка сервера, запрос подключения завершается ошибкой.
