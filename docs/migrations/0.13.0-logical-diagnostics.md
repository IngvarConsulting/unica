# 0.13.0 — логическая адресация диагностик

`unica.code.diagnostics` перешёл на provider-neutral результат и логические цели 1С. Это прямое переключение без совместимости со старой формой: `cwd` по-прежнему выбирает workspace, но не является целью; цель задаётся точным `sourceSet` и, для `findings`, логическим `metadataPath`.

| Было | Стало |
| --- | --- |
| `mode=analyze + sourceDir` | `action=analyze + sourceSet` |
| `mode=file + path` | `action=findings + sourceSet + metadataPath` |
| `mode=status` | `action=status + sourceSet` |
| `mode=catalog` | `action=catalog + sourceSet` |
| `mode=workspace` | `analyze`, либо `status` и логические `findings` |
| `codes[]` | `filter.codes[{provider, code}]` |
| `minSeverity` | `filter.minSeverity` только для `analyze` и `findings`; `catalog` это поле не принимает |
| `rangeStart/rangeEnd` | объект `range` с нулевыми end-exclusive координатами |
| `config/format/detail/maxFiles` | удалены |

Пример полного анализа набора исходников:

```json
{"action":"analyze","sourceSet":"main","timeoutSeconds":900}
```

Пример чтения диагностик одного модуля:

```json
{
  "action": "findings",
  "sourceSet": "main",
  "metadataPath": "CommonModule.Продажи.Module",
  "filter": {
    "codes": [
      {"provider": "bsl-analyzer", "code": "UnusedLocalVariable"}
    ]
  }
}
```

Для старого `mode=file` сначала разрешите физический файл через
`unica.source.locate`. Если он соответствует модулю или объекту метаданных,
передайте полученный `sourceSet + metadataPath` в `findings`. У неадресуемого
служебного файла прямого точечного аналога нет: запускайте `analyze` для его
набора исходников и отбирайте элементы по безопасному относительному
`location.path`; не восстанавливайте цель из раскладки файла самостоятельно.

Публичный `data` больше не повторяет формат конкретного анализатора. Входного
selector-а `providers` нет: план исполнения строится внутренне, а секции
`providers` в результате сообщают происхождение и полноту. Читайте плоский массив
`items`; переход выполняйте по общему `location`, причину неадресуемости — по
соседнему `locationReason`, а точное место внутри логической цели — по `focus`.
`partial`, `resourceFailure` и `unaddressable` — разные состояния и не
доказывают отсутствие проблем.
