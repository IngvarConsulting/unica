# 0.13.0 — логическая адресация диагностик

`unica.code.diagnostics` перешёл на provider-neutral результат и логические цели 1С. Это прямое переключение без совместимости со старой формой: `cwd` по-прежнему выбирает workspace, но не является целью; цель задаётся точным `sourceSet` и, для `findings`, логическим `metadataPath`.

| Было | Стало |
| --- | --- |
| `mode=analyze + sourceDir` | `action=analyze + sourceSet` |
| `mode=file + path` | `action=findings + sourceSet + metadataPath` |
| `mode=status` | `action=status + sourceSet` |
| `mode=catalog` | `action=catalog + sourceSet` |
| `mode=workspace` | `analyze`, либо `status` и логические `findings` |
| `codes[]` | `filter.codes[{provider, code}]` |
| `minSeverity` | `filter.minSeverity` |
| `rangeStart/rangeEnd` | объект `range` с нулевыми end-exclusive координатами |
| `config/format/detail/maxFiles` | удалены |

Пример полного анализа набора исходников:

```json
{"action":"analyze","sourceSet":"main","timeoutSeconds":900}
```

Пример чтения диагностик одного модуля:

```json
{
  "action": "findings",
  "sourceSet": "main",
  "metadataPath": "CommonModule.Продажи.Module",
  "filter": {
    "codes": [
      {"provider": "bsl-analyzer", "code": "UnusedLocalVariable"}
    ]
  }
}
```

Публичный `data` больше не повторяет формат конкретного анализатора. Читайте `providers` и плоский массив `items`; переход выполняйте по `location`, а точное место внутри логической цели — по `focus`. `partial`, `resourceFailure` и `unaddressable` — разные состояния и не доказывают отсутствие проблем.
