# Регрессия кириллических путей в `code.diagnostics`

## Контекст

Issue #462 зафиксировал, что опубликованная версия 0.11.0 повреждала кириллические
пути в console/raw-stdout отчёте полного анализа. PR #425 уже устранил этот маршрут:
default-вызов `unica.code.diagnostics` запускает `bsl-analyzer analyze --format jsonl`,
разбирает UTF-8 JSONL и возвращает типизированные данные без `stdout`.

## Решение

Добавить один регрессионный тест полного `BslAnalyzerMcpAdapter` analyze-маршрута с
подменой только внешнего процесса. Тест подаёт реальный JSONL-контракт с кириллическим
`file.path` и проверяет потребительский результат:

- команда принудительно содержит `--format jsonl`;
- успешный результат не содержит `stdout`;
- типизированный item содержит неизменный путь
  `CommonModules/РеактивныйКлиент/Ext/Module.bsl`.

Подмена процесса исключает зависимость CI от платформы и наличия упакованного
`bsl-analyzer.exe`, оставляя реальными маршрутизацию адаптера, потоковый разбор,
нормализацию пути и формирование публичной нагрузки.

## Проверка

Запустить целевой тест отдельно, затем весь тестовый модуль `diagnostics_jsonl` и
связанные тесты `diagnostics_analyze`. Тест должен ловить возврат к console-формату,
публикацию raw `stdout`, потерю typed payload и повреждение кириллического пути.
