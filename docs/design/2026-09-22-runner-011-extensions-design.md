# Раннер 0.11 и расширения информационной базы

Поручение владельца: обновить раннер до последнего выпуска нашего форка и
завершить A-8 из #871. На момент работы последний выпуск — v0.11.0,
commit e57f8459b61a9fb2c279b5e65c59b4f67e045dd9. Бинарные суммы берутся из
опубликованного v8-runner-assets.json. Выпуск Unica этим изменением не делается.

## Совместимость раннера

В 0.11 сняты `selection` и глобальный `builder`. Три операции CF/DT проверяют
квитанцию `provider {selected, origin, skipped?}`, включая совпадение preview
и apply; revision включает её целиком. Публичный план называет выбранного
исполнителя и вид происхождения, не возвращает пути override и прозу о
пропущенных кандидатах. Списка альтернатив у раннера больше нет, Unica его
не выдумывает. Существующие проектные файлы не переписываются автоматически:
из примеров убран builder, документирован переход на providers по операциям.

## Расширения

Слой `extension` и пять глаголов предусмотрены
DEC.2026-09-15.RUN-NAMES-READ-AS-LAYER-AND-DIRECTION. Все пять операций
исполняются до admission исходников, через Task и поставляемый раннер.

| Операция | Аргументы | Результат |
| --- | --- | --- |
| extension.list | нет | сведения обо всех установленных расширениях |
| extension.info | name | сведения ровно об указанном расширении |
| extension.create | name, namePrefix, synonym?, purpose? | регистрация пустого расширения |
| extension.delete | name | удаление указанного расширения |
| extension.activate | name, active | включение или выключение активности |

Загрузка и обновление содержимого CFE остаются `cf.import` с `extension`;
регистрация пустого расширения не выдаётся за установку содержимого CFE.
`purpose`: customization/add-on/patch; `synonym` — NStr.

Решение владельца в #871 от 16.09 сохраняет previewApply даже для списка:
чтение базы запускает платформу, аутентифицируется и оставляет след в журнале.
Это не чтение исходников, к которому относится INV.WIRE.PREVIEW-IS-MUTATION-ONLY.
Preview вызывает только --dry-run, проверяет provider_dispatched=false и
пустой inventory либо ровно один шаг с ожидаемыми target/action. Проза
plan/message не участвует в решениях. Apply повторяет preview и проверяет
ifRev по идентичности рабочего пространства, аргументам, обоим файлам конфигурации, версии раннера и квитанции
исполнителя. План не является снимком состояния базы: preview в базу не ходит,
проверки существования и допустимости действия принадлежат платформе.

Ответ inventory ограничен размером процесса и количеством записей, проверяет
типы, уникальные имена и предмет запроса. Возвращаются только поля платформы;
префикса в ответе платформы нет — он находится в исходниках расширения,
доступных через source.export. Результат изменений явно приписан провайдеру,
Unica не заявляет независимую проверку состояния базы. Секреты, сырые команды,
stdout/stderr и проза планов в успешный ответ не попадают. База и учётная запись показываются из
структурной конфигурации с учётом local overlay; пароль не читается в публичную
проекцию, секреты в connection маскируются, сырой CLI-вариант connection
не выводится. Относительная цель остаётся явно объявленной относительно workspace.

## Проверка

До адаптации воспроизведён отказ трёх операций на новой квитанции и отсутствие
семейства extension в каталоге. Живой поставляемый бинарь воспроизвёл отказ
старого builder и несовместимость CI-проверки с новым полем provider у build.
Регрессионные тесты проверяют revision fence, subject/action, отмену, отказы,
контракт аргументов, маршрутизацию до source admission и отсутствие сырой прозы.


## Результат живой проверки

На macOS с 1C 8.3.27.2074 и ibcmd пройден цикл list → create → info →
activate(false) → info → activate(true) → delete → list через опубликованный
раннер и затем через собранный Unica MCP / compatibility Tasks. Финальный список
пуст, info подтвердил изменение active. Платформенные ответы закреплены в
`tests/fixtures/v8_runner_011/`; пути машины в прозе заменены на /workspace и /platform.
Проверены SHA-256 всех трёх опубликованных бинарей 0.11.0. Проверки partial-load
и bounded external EPF выполнены на реальном darwin-arm64 бинаре раннера со
стендовыми исполняемыми провайдерами из CI-проверки.

Через Unica с тем же раннером выполнены preview/apply для cf.export,
infobase.export и source.export; получены CF, DT и XML-исходники тестовой базы.
Для infobase.import, cf.import, source.import, artifact.build и client.run
проверен preview. Их apply эта живая проверка не покрывает.

Особенность машины: /Applications/1cv8.localized/.../1cv8 — launcher, который
возвращается раньше дочернего процесса. С ним init преждевременно сообщил об
отсутствии 1Cv8.1CD, а агентский режим не запустился. Проба продолжена с настоящими
утилитами из /opt/1cv8/8.3.27.2074. Поведение launcher не исправляется этим PR.
