# Runtime не требует отдельного skill

## Проблема

`plugins/unica/skills/v8-runner` повторяет старую поверхность
`unica.runtime.execute`, включая снятые из v0.13 `syntax` и `test`. После
появления словаря `unica.run {}` эта инструкция перестала быть источником
контракта и может направить модель к отсутствующим операциям.

## Выбор

Удалить публичный skill `v8-runner` вместе с его локальными references.
Runtime остаётся возможностью единственного MCP-сервера `unica`: модель сначала
вызывает `unica.run {}`, читает `implemented` и `argsSchema`, затем использует
только опубликованный контракт. Внутренний бинарник `v8-runner`, его lock,
лицензия, provenance и adapter остаются частью поставки.

Предметные skills могут ссылаться непосредственно на `unica.run`, но не должны
предлагать вызвать удалённый skill или угадывать аргументы нереализованной
операции.

## Альтернативы

- Переписать отдельный runtime skill под v0.13: оставляет второй источник
  словаря и неизбежный дрейф между prompt и `tools/list`.
- Скрыть skill только из одного host-манифеста: каталог skills общий для Codex
  и Claude Code, поэтому получится разная поверхность одного пакета.
- Удалить сам движок: смешивает prompt-маршрутизацию с внутренним runtime и
  лишает `unica.run` реализации.

## Проверка

CI запрещает каталог `plugins/unica/skills/v8-runner` и явные инструкции
`Use the v8-runner skill` в основных runtime-документах. Provenance продолжает
связывать внутренний runtime-контракт с закреплённым исходником движка, но не
объявляет удалённый skill адаптированной точкой входа.
