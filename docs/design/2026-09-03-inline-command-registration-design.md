# Команды объектов регистрируются инлайном, без файла-дескриптора

Контекст: `unica.view main:Catalog.Номенклатура` и любой
`unica.find` на дампе УТ 11 (платформа 8.3.27.2074) падали закрытым отказом
`not_found: metadata owner … does not register Command.НовыйЭлемент`.

## Что наблюдали

- В дампе 48 159 файлов нет ни одного `Commands/<Имя>.xml`, зато 567
  `Commands/<Имя>/Ext/CommandModule.bsl`. Полный дескриптор команды лежит
  внутри `ChildObjects` владельца: `<Command uuid="…"><Properties><Name>…`.
  Так же описывает формат `plugins/unica/references/specs/1c-config-objects-spec.md`
  (раздел 6.5): «Отдельного файла `Commands/<Имя>.xml` платформа не создаёт».
- Парсер регистраций `platform_xml_owner::registrations` брал только текст
  элемента (`<Form>Main</Form>`), поэтому инлайн-команда не попадала в
  регистрации, и owner admission любого владельца с командами проваливался.
  Доказательство владельца для `Catalog.X.Command.Y` дополнительно требовало
  файл `Catalogs/X/Commands/Y.xml`, которого не существует.
- Фикстуры v13 моделировали команды текстовой ссылкой плюс отдельным файлом
  дескриптора — то есть закрепляли форму, которой платформа не пишет.
  v0.12 `meta.info` инлайн-команды читал правильно.

## Решение

- Регистрация `ChildObjects` — это текст элемента, а при его отсутствии
  `Properties/Name` вложенного определения. Формы и макеты остаются
  текстовыми ссылками с дескрипторами; команда регистрируется своим полным
  инлайн-определением.
- Доказательство владельца для пары `Command.<Имя>` состоит из регистрации в
  `ChildObjects` родителя; файл дескриптора не ищется. Команда — терминальный
  физический владелец: вложенных пар после неё нет. Незарегистрированный
  каталог `Commands/<Имя>/` остаётся неадресуемым (`not_found`), как и раньше.
- Фикстуры приведены к форме платформы; проверка «неправильный дескриптор
  дочернего объекта» сохранена на форме, у которой дескриптор есть.

## Что не менялось

Формы и макеты: регистрация текстом плюс matching descriptor; orphan и
wrong-owner доказательства для них прежние. Модули команд читаются по прежнему
пути `Commands/<Имя>/Ext/CommandModule.bsl`.

## Проверка

Тест парсера регистраций на инлайн-команду; реальная фикстура с инлайн-командой
у справочника: `view` владельца и команды, `find` находит адрес команды;
прежние проверки orphan/wrong-descriptor на формах.
