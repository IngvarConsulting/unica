# Целевой словарь раннера 1.0 в Unica 0.13

Владелец выбрал: «Перейти в 0.13 на целевой словарь раннера».
Реализован целевой словарь и ограниченный адаптер 0.11.
Доступность полного поведения раннера 1.0 этим не заявляется.

## Основание и граница выбора

Сайт описывает целевое состояние, а не возможности опубликованного бинаря:

- https://ingvarconsulting.github.io/v8-runner-rust/cli.html
- https://ingvarconsulting.github.io/v8-runner-rust/sources.html
- https://ingvarconsulting.github.io/v8-runner-rust/architecture.html

Изученный upstream master: `ef95d5c2ba5b7c048a359f8c3da01f03f65bcaea`;
источники сайта — `docs/site/cli.html`, `sources.html`, `architecture.html`.
CLI повторно сверен перед реализацией; при подключении 1.0 потребуется
повторная сверка с развивающимся upstream. Исполнитель переходного периода — опубликованный 0.11.0,
`e57f8459b61a9fb2c279b5e65c59b4f67e045dd9`, закреплённый tools.lock.json.

Выбор меняет прежнюю политику двух словарей: `source.import`/`build` и
`source.export`/`dump`. Цена сохранения прежнего решения — два языка у
пользователя и модели. Цена нового — изменение каталога, всех потребителей
имён, скиллов, проверок и архитектурных правил до первого пререлиза.

Решение не разрешает произвольный shell, второй публичный MCP-сервер,
автоматическую выдачу всей поверхности CLI или снятие защиты применения.
Заявление сайта о независимости словаря MCP допускает собственный словарь,
но не требует его: владелец выбирает согласовать runtime-названия.

## Публичная форма

Один инструмент `unica.run`; `op` — имя команды с точкой между частями,
`args` — закрытая типизированная структура. Например, `download`,
`infobase.dump`, `extensions.set`; CLI-строки и произвольные флаги не принимаются.
`unica.apply` остаётся писателем исходников; `unica.run` с `op: apply` —
применением основной конфигурации к конфигурации БД. Это различие обязательно
в описаниях и сценариях, иначе два разных действия окажутся неразличимыми.

Разделяются три уровня:

1. Целевой каталог: имя, предмет, схема, эффекты, обязательные гарантии.
2. Возможности установленного адаптера для операции и конкретных аргументов.
3. Готовность среды: база, платформа, полномочия, доступность исполнителя.

Наличие операции в каталоге не означает поддержку всех режимов. Недоступный
режим получает структурный отказ и дальнейшее действие, до платформенного
запуска. Отсутствие сведений о базе означает неизвестность, не синхронность.
Схема доступности Unica закреплена в CTR.WIRE.TOOL-SURFACE; она не
выдаётся за JSON будущего upstream.

## Матрица перехода

«Кандидат» ниже означает предмет проверки, а не подтверждённую совместимость.
Новая семантика не наследует доказательства старой только из-за похожего argv.

| Сейчас в Unica | Целевая операция | Переходный адаптер 0.11 / обязательное доказательство |
| --- | --- | --- |
| `infobase.create` | `infobase.create` | Кандидат: старый `init`; проверить создание с исходниками и памятью синхронизации. Нынешнее обещание «пустая база» не равно всей целевой семантике |
| `cf.export` | `download` | Кандидат: `infobase configuration export`; проверить состояния, выбор конфигурации/расширения, цель и файловую квитанцию |
| `cf.import` | `upload` | Недоступен: 0.11 `load` безусловно вызывает `update_db_cfg`; целевой upload должен останавливаться на основной конфигурации |
| `infobase.export` | `infobase.dump` | Кандидат: выгрузка DT; сохранить границу образа переноса, не называть резервной копией |
| `infobase.import` | `infobase.restore` | Кандидат: восстановление DT; сохранить явное разрешение замены данных и проверку цели |
| `artifact.build` | `make` | Кандидат: сборка пакета. Сейчас адаптер публикует CF/CFE; EPF/ERF не объявлять готовыми по одному описанию |
| `client.run` | `launch` | Кандидат: уже проверенные режимы клиентов. `web`, `mcp`, `via web` — отдельно доказать или отказать |
| `source.import` | `push` | Старый `build` не доказывает защиту non-fast-forward, создание отсутствующего расширения и `no-apply`. Обычный режим заблокирован до доказательства всей семантики |
| `source.export` | `pull` | Старый `dump` не доказывает сохранность локальных правок и требуемую выкладку. `full`/`incremental` не являются синонимами `force` |
| `extension.list`, `extension.info` | `extensions.list` | Кандидат: инвентарь установленного. Фильтр одного имени согласовать по целевой схеме; отдельное публичное `info` не сохранять по инерции |
| `extension.activate` | `extensions.set` | Кандидат: `active` через старый activate. Другие свойства отвергать до запуска, не игнорировать |
| `extension.create` | первая отправка расширения через `push` | Самостоятельное создание пустого расширения из публичного словаря убрать; нельзя выдать его за отправку исходников |
| `extension.delete` | `push` с удалением ссылки | Кандидат: старый delete. Нужны точная идентичность установленного расширения и явный план удаления данных; не смешивать удаление с отправкой |
| отсутствует | `apply`, `reset` | Целевые операции основной конфигурации и конфигурации БД; недоступны до появления проверенного исполнителя |
| отсутствует | `sessions.*`, `check`, `test`, `publish` | Целевые runtime-возможности; самостоятельные срезы, не обещание их реализации в рамках простого переименования |

Полнота CLI не равна составу `unica.run`: локальные `init`, `status`, `version`,
`tools download`, `mcp serve` автоматически сюда не добавляются. Для `status`
нужно спроектировать чтение состояния пары, с отличием памяти от live/deep.
`clone` и `pull --all` также пишут конфигурацию проекта; это пересекает
DEC.2026-09-09.PROJECT-CONFIG-IS-HANDWRITTEN и не разрешено одним выбором имён.
EDT/convert остаются за действующей границей поддерживаемого формата.

## Адаптеры и владение

Application определяет предметный запрос и результат, не знает argv версии.
Инфраструктурный Runner011Adapter переводит только поддерживаемое подмножество
в CLI 0.11 и валидирует его конверты. Runner100Adapter реализует тот же порт
после появления бинаря 1.0. Выбор адаптера — по проверенному пакету и версии,
не через пробный запуск команды с побочными действиями и fallback после ошибки.
Нет отдельного публичного инструмента или набора скиллов на версию раннера.

Unica владеет Tasks, отменой, admission, согласованием плана и проекцией ответа.
Раннер владеет платформенным исполнителем, сеансами, поколениями и памятью
синхронизации. Unica не строит временную копию нового sync engine.

`ifRev` связывает целевой запрос, эффективную конфигурацию, идентичность базы,
аргументы, версию адаптера/исполнителя и план. Изменение цели или версии
обесценивает preview. Этот забор не является проверкой, что база не менялась.
Результат частичного выполнения обязан различать загрузку основной
конфигурации и неудачное применение к БД; весь запрос нельзя повторять вслепую.

## Конфигурация

Целевые `infobases` и `providers.<новая-команда>` — отдельная часть миграции.
Чтение проекта в Unica и конфигурация, переданная старому бинарю, должны быть
согласованы. Изменить только CLI-аргументы недостаточно.

Адаптер может строить закрытую служебную проекцию конфигурации в формат 0.11,
но не переписывать файл пользователя на время команды. Относительные пути
сохраняют исходную базу разрешения, секреты не попадают в журналы и ответы,
локальный слой имеет ту же семантику наложения. Неизвестные ключи не теряются
молча. Если новый ключ влияет на эффекты и не представим в 0.11, запрос отклоняется.

Имя базы и фактическая идентичность цели — разные данные: смена connection
под тем же именем не должна переиспользовать память и preview предыдущей базы.
Многоцелевую работу нельзя включать, пока не доказана изоляция workPath,
блокировки и истории для каждой пары. До этого явный отказ на неподдерживаемую
цель лучше работы с origin вместо запрошенной базы.

## Что уточнить в контракте раннера до реализации соответствующих режимов

- Полные JSON-схемы запроса/квитанции/ошибок/плана, версия контракта и
  частичный успех. Сайт приводит отдельные примеры, а не полную схему.
- `push`: вводная отделяет отправку от применения, таблица включает применение
  по умолчанию. Принять явно: применение по умолчанию, `no-apply` останавливает
  после загрузки; отдельно определить результаты неуспеха второго шага.
- `pull`: точное поведение при изменённых отслеживаемых файлах, untracked,
  удалениях и каталоге без VCS. «Слияние» не должно обещать трёхсторонний merge,
  если фактически это защищённое наложение выгрузки.
- Адресация установленного расширения, которого нет в source-set, для
  `extensions.set` и удаления; не угадывать alias по имени в базе.
- Граница preview: что он может узнать без платформы и блокировки, какие
  проверки откладываются до исполнения, как связан план с поколением.
- Переход памяти 0.11 → 1.0: старые данные нельзя объявлять надёжным предком
  новой синхронизации без проверяемой миграции.

Это технические пункты договора двух компонентов, а не повторный вопрос
владельцу, какой словарь выбрать. Выбор словаря уже сделан.

## Архитектурные изменения при реализации

Заменить политику INV.WIRE.RUN-NAMES-ARE-LAYER-AND-DIRECTION её преемником,
обновить CTR.WIRE.TOOL-SURFACE, INV.APP.V13-RUN-DICTIONARY и правила
preview/apply затронутых операций. Обновить покрытие реализации, ведомость
поверхности, справку словаря и маршруты скиллов одним набором изменений.
Старые решения сохраняются как история. Planned-направление не делает
действующие проверки ложными до появления новой реализации.

Открытый PR #951 остаётся техническим основанием обновления зависимости;
его текущие имена расширений не являются целевым интерфейсом первого 0.13.
Готовность #951 не закрывает этот переход и не доказывает готовность пререлиза.

## Реализованный переходный срез

Публичный каталог содержит 13 целевых имён. Семь закрытых схем поддержаны:
`download`, `make`, `infobase.dump`, `infobase.restore`, `launch`,
`extensions.list`, `extensions.set` (только active). `push` ограничен
удалением установленного расширения. `pull`, `upload`, `infobase.create`,
`apply`, `reset` недоступны и отвергаются до admission/исполнителя.

Неэквивалентность upload подтверждена исходником закреплённого 0.11:
`src/use_cases/load_artifact.rs`, вызов `update_db_cfg` после загрузки,
квитанция `update_db_cfg_ran: true`. Переименование без этого отказа
скрывало бы от пользователя дополнительное изменение базы.

Целевой infobase задаётся отдельно от args; в переходном срезе принимается
только origin. Структура support публикует adapter, state, reason,
supportedInfobases и supportedArgs. Отказ по известной недоступной операции
возвращает unsupported_operation; старые имена не являются aliases.

Runner011ProcessRunner создаёт приватные копии двух слоёв конфигурации,
переводит infobases.origin, ключи providers, push-настройки и типы
configuration/extension. Пути, которые старый загрузчик разрешает от
конфигурации, сохраняются абсолютными; source-set пути также делаются
абсолютными, поскольку закрытая схема 0.11 отвергает basePath. Секреты local
остаются в local-копии. Копии удаляются при завершении, в том числе ошибочном.
Многобазовая конфигурация, смешение старой/новой цели, новый неподдерживаемый
provider и неоднозначный raw connection отклоняются, не упрощаются молча.

Адаптер 1.0 ещё не реализован. Версия, отличная от закреплённой 0.11.0,
не запускается этим адаптером. История синхронизации 0.11 не объявлена
мигрированной; обычные push/pull пока не исполняются.


## Проверка переходного среза

22 сентября 2026 года новый публичный путь проверен через MCP на macOS ARM64
с платформой 8.3.27.2074 и закреплённым бинарём 0.11.0. Проект использует
`infobases.origin`, вложенный `providers.infobase.create` и нижний регистр
`source-set.type`. Проверены preview/ifRev/apply для:

- `extensions.list`, `extensions.set` false/true, `push` delete;
  повторный список подтвердил отключение и затем отсутствие расширения;
- `download` CF, `infobase.dump` DT, `make` CF: опубликованы непустые
  артефакты с проверенными Unica размером и SHA-256;
- `infobase.restore` replace из полученного DT с успешным повторным чтением
  списка расширений. Изменение базы здесь засвидетельствовано провайдером.

Входной проект не переписывался во время вызовов. Приватная проекция и
очистка после ошибки дополнительно проверены тестовым исполнителем.
Live-приёмка на Windows/Linux в этой сессии не проводилась. `launch`
покрыт контрактными тестами; интерактивный клиент для этого среза не запускался.

Добавлены и наблюдались падающими до реализации проверки нового словаря,
проекции конфигурации, запрета неявного apply в upload и явного указания
удаления данных в preview push/delete. Старый обработчик загрузки CF остаётся
внутренним материалом с тестами; публичный capability gate его не допускает.
