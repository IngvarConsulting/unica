# Инициализационный контракт `unica.run`

## Цель

Первый агент без skills начинает с `unica.view {}` и не угадывает ни физические
пути, ни наличие платформы, ни последовательность runtime-команд. Ответ сообщает
одну главную проблему, наблюдаемые факты и только исполнимое следующее действие.
`unica.run {}` остаётся словарём двенадцати намерений, а не новым набором tools.

## Общий протокол изменяющего намерения

- Запись рабочего пространства всегда начинается с `dryRun: true`.
- Preview ничего не создаёт, не запускает и не загружает. Он возвращает полный
  план, `rev` и точный следующий вызов.
- Apply передаёт те же `op` и `args`, `dryRun: false` и полученный `ifRev`.
  Отсутствующий или устаревший fence — типизированный отказ без публикации.
- `unica.run {}` доступен до source admission и для каждого намерения сообщает
  назначение, `effects`, режим `execution`, `implemented`, необходимость
  preview/fence и terminal-семантику. Агент отличает файловое изменение,
  обращение к ИБ, read-only проверку и интерактивную сессию без skills.
- Наличие платформы проверяется только операцией, которой она действительно
  нужна. `source.attach` платформу не требует и не упоминает её отсутствие.
- `next` содержит только реально исполнимый сейчас вызов. Будущая возможность
  может быть названа как требование или выбор, но не как executable continuation.

## Матрица начальной маршрутизации

| Наблюдаемое состояние | Намерение пользователя | Канонический маршрут | Нужна полная платформа |
| --- | --- | --- | --- |
| Пустая папка | Начать новые исходники | `source.create` с выбранными kind/format/path | нет |
| Пустая папка | Создать ИБ из `.dt` | `infobase.create` → `artifact.load` | да, backend зависит от ИБ |
| Пустая папка | Создать ИБ из `.cf` | `infobase.create` → `artifact.load` → `source.dump` при необходимости исходников | да |
| Есть файловая, клиент-серверная или автономная ИБ | Подготовить исходники | `source.dump` с явным target source set и format | да |
| Есть EDT-исходники | Работать как EDT | `source.attach`, если все наборы EDT | нет для attach; EDT/toolchain для проверок |
| Есть EDT-исходники | Получить Designer XML | `source.convert` | зависит от выбранного converter |
| Есть Designer XML | Подключить к workspace | `source.attach` | нет |
| Есть Designer XML | Создать/обновить ИБ | `infobase.create`/`infobase.build` или `artifact.load` | да |
| Есть расширения | Подключить вместе с конфигурацией | `source.attach` сохраняет каждый source set и не теряет kind | нет |
| Есть EPF/ERF-исходники | Подключить или собрать | `source.attach` → `artifact.make` | attach — нет, make — да |

Комбинации конфигурации, расширений, EPF и ERF являются набором независимых
source sets. Нельзя сворачивать их в один effective source set или терять kind.
Один `v8project.yaml` имеет один глобальный `format`: смешанные EDT/Designer
наборы требуют явного выбора/конвертации и не получают автоматически выбранный
формат по базовой конфигурации.

## Доступность платформы

Runtime discovery различает `full`, `thin-only` и `absent`, а для полного
runtime — Designer, `ibcmd` и автономный сервер. Тонкий клиент достаточен только
для `client.run`; он не считается средством создания ИБ, загрузки `.cf/.dt`,
выгрузки исходников или сборки EPF/ERF. Отсутствие платформы не мешает
`view/find/search/apply/check/diff/docs`, `source.attach` и файловому
`source.create`.

Для файловой, клиент-серверной и автономной ИБ план показывает backend,
connection target, необходимые credentials без секретов и конкретную
недостающую capability. Общий текст «платформа не найдена» не заменяет эту
классификацию.

## Первый реализованный вертикальный срез

`source.attach` без operation-specific args присоединяет все source sets,
которые уже безопасно autodetected в известных layout. Он:

1. доступен до actor/source admission;
2. отказывает при отсутствии source roots, существующем `v8project.yaml`,
   unknown/invalid или смешанном формате;
3. preview возвращает точный YAML, source sets, `requiresPlatform: false`, fence
   и apply-вызов, не меняя диск;
4. apply повторно выполняет discovery, сравнивает fence и публикует только новый
   `v8project.yaml` через create-only atomic publication;
5. после публикации направляет в `unica.view {}`.

Следующий срез расширяет `source.attach.args` явными declarations/selections для
нестандартных путей и autodiscovery EPF/ERF. До этого такие случаи должны
отказываться как не найденные, а не маскироваться конфигурационным source set.

## Требования к ответам

- Пустой workspace: одна диагностика `source_roots_missing`, без Git-health,
  platform-health и готового YAML, ссылающегося на несуществующий каталог.
- Autodetected единый формат: `view {}` возвращает preview `source.attach` как
  первый executable `next`.
- Смешанный формат: одна причина выбора формата, без конкурирующего рецепта.
- Существующий config: `source.attach` никогда не перезаписывает его.
- Ошибка всегда содержит stable code, конкретную причину и следующий безопасный
  шаг; ветви одного смысла не публикуют взаимоисключающие рекомендации.

## Проверка следующих срезов

Каждое намерение получает таблицу аргументов в словаре `run`, preview/apply
паритет, fixture минимум для каждого затрагиваемого kind/format/backend и
негативные сценарии `thin-only`, `absent`, stale fence и concurrent target.
Сквозная матрица не означает декартово произведение тестов: одинаковая политика
доказывается один раз unit-тестом, а по одному wire-сценарию на каждую уникальную
ветвь выбора подтверждает маршрутизацию.
