# Типизированный JSON-результат BSL outline

- Date: `2026-07-30`
- Status: `approved`
- Decision: `ADR-0020`

## Задача

Исправление issue #262 уже переносит `unica.code.outline` с индексного снимка
на текущий BSL-файл, но первая реализация сохраняет прежний текстовый
`stdout`. Такой результат смешивает данные и представление: метка секции
становится частью неописанной грамматики, тип метода зависит от языка и
регистра исходного токена, а перевод строки внутри параметра разрушает одну
запись метода на несколько физических строк.

Публичный конверт `OperationResult` уже имеет поле `data` для типизированных
результатов. Outline должен использовать эту границу, а не сериализовать JSON
в строку `stdout`.

## Выбранный контракт

Успешный `unica.code.outline` возвращает структуру модуля только в поле `data`;
поле `stdout` отсутствует. Внутри `data` находится объект следующей формы:

```json
{
  "module": "CommonModules/Test/Ext/Module.bsl",
  "identity": {
    "category": "CommonModules",
    "object": "Test",
    "moduleType": "Module"
  },
  "totals": {
    "methods": 1,
    "exports": 1,
    "regions": 1,
    "loc": 3
  },
  "regions": [
    {
      "name": "Public",
      "line": 1,
      "endLine": 5,
      "regions": [],
      "methods": [
        {
          "name": "Run",
          "kind": "procedure",
          "parameters": [
            {
              "name": "Value",
              "byValue": true,
              "defaultValue": null
            }
          ],
          "export": true,
          "line": 2,
          "endLine": 4
        }
      ]
    }
  ],
  "methods": []
}
```

`regions` образует рекурсивное дерево. Корневой `methods` содержит только
методы, не принадлежащие ни одной области. Поля `methods` присутствуют и
остаются массивами при любом значении `includeMethods`; при
`includeMethods=false` они пусты, но `totals` по-прежнему описывает весь
модуль.

Неизвестные `identity.category`, `identity.object`,
`identity.moduleType`, имя области и `endLine` незакрытой области
представляются явным `null`, а не отсутствующим полем. Так потребитель отличает
доказанное отсутствие значения от другой версии схемы.

Дополнительный `schemaVersion` не вводится: публичный контракт принадлежит
версии инструмента и существующие типизированные результаты Unica не несут
параллельную версию внутри `data`.

## Методы и параметры

Тип метода определяется видом AST-узла и публикуется каноническим английским
значением `procedure` или `function`. Написание исходного ключевого слова,
локаль и регистр на результат не влияют.

Параметр строится из узла `Param`, а не из сырого `param.text()`:

- `name` берётся из токена `IDENT`;
- `byValue` определяется наличием `KW_VAL`;
- `defaultValue` равен `null`, если выражения по умолчанию нет;
- выражение по умолчанию представляется исходным текстом своего узла AST.

Соединение токенов через разделитель здесь не годится: разделитель нужно было бы
ставить по правилам, знающим, где он уместен, иначе `-1` превращается в `- 1`,
а `Новый Структура("к", 1)` — в `Новый Структура ( "к" , 1 )`. Платформа
допускает в качестве значения по умолчанию только литерал, а единственный
литерал из нескольких токенов — знаковое число, и это ровно тот случай, который
соединение через пробел портит. На проверенном корпусе таких параметров 23 в 15
модулях (`НомерКартинки = -1`, `Код = -1`, `ЖдатьОкончания = -1`). Исходный текст
узла и точен, и не может испортить пробелы внутри строкового литерала.

Так многострочная сигнатура и прикреплённые trivia не могут менять структуру
JSON или добавлять ложные поля параметра: строка `defaultValue` описывает только
выражение, а не весь параметр.

## Граница слоёв

Типы результата outline принадлежат нейтральной к поставщику модели анализа
кода. Инфраструктурный `bsl_outline` строит эту модель из текущего syntax tree,
а `BslAnalyzerProvider` возвращает её как типизированные данные
`ProviderReadOutcome`.

Слой application сериализует типизированный результат в
`OperationResult.data`. Он не разбирает JSON-строку поставщика и не знает
деталей `bsl-parser`. Транспорт продолжает сериализовать общий
`OperationResult` без отдельной ветки для outline.

`ProviderReadOutcome.stdout` остаётся для существующих текстовых операций
definition и profile, но успешный outline его не заполняет. Дублировать один
результат одновременно в `data` и `stdout` запрещено: два представления
немедленно стали бы двумя контрактами свежести и совместимости.

## Ошибки

Чтение, containment, диагностика парсера, отсутствие обязательного имени
метода или параметра, отмена и deadline сохраняют fail-closed поведение
выбранного текущего источника. При отказе `data`, `stdout` и `artifacts`
отсутствуют, причина находится в `errors`, а частичное дерево не публикуется.
Успешный вызов получает абсолютный путь артефакта из того же чтения, которое
построило outline, а не из отдельного разрешения аргумента.

Неизвестная метаинформация пути и незакрытая область не являются ошибками:
соответствующие поля равны `null`, потому что неопределённость представлена
внутри доказанного дерева.

## Изменения

- ADR-0020 объединяет выбор текущего BSL-файла с контрактом типизированного
  `data`; промежуточный текстовый вариант не становится отдельной исторической
  ADR;
- доменная модель анализа кода получает типы module identity, totals, region,
  method и parameter;
- `ProviderReadOutcome` переносит типизированный результат чтения до слоя
  application;
- `bsl_outline` строит дерево результата без отдельного текстового рендера;
- новый инвариант защищает JSON-форму outline, а
  `INV-APP-OUTLINE-SOURCE` ссылается на ту же ADR-0020;
- описание PR удаляет утверждение о сохранении компактной грамматики
  `stdout` и явно называет смену публичного результата.

## Проверка реализации

Сначала добавляются и запускаются красными:

1. модульный тест точного `CodeOutlineResult` для областей, сирот,
   канонического вида метода и структурированных параметров;
2. регрессия с русским ключевым словом смешанного регистра и многострочной
   сигнатурой, включая комментарий и выражение по умолчанию;
3. публичный интеграционный тест, который требует объект `data`, отсутствие
   `stdout` и неизменное отсутствие доступа к индексу;
4. тест `includeMethods=false`, который требует пустые массивы методов при
   неизменных totals;
5. тест отказа, который требует отсутствия и `data`, и `stdout`.

После реализации выполняются целевые тесты outline, code-intelligence и
публичного конверта, затем полные `cargo fmt`, `cargo clippy`, Rust-, CI- и
dev-наборы, строгая архитектурная проверка и `git diff --check`.

## Доставка

Контракт реализован красно-зелёными публичными регрессиями
`code_outline_answers_from_the_current_file_without_touching_the_index` и
`code_outline_without_methods_keeps_totals_in_typed_data`: до изменения они
падали на присутствующем `stdout`, после изменения проверяют точный объект
`data`, канонический вид метода, структурированные многострочные параметры и
сохранение totals при скрытых методах. Отдельная регрессия
`code_outline_failure_publishes_neither_typed_nor_text_partial_result`
удерживает отсутствие частичного результата при ошибке парсера.

Нормативным владельцем доставленного выбора остаётся ADR-0020, а проверяемое
следствие результата принадлежит `INV-MCP-OUTLINE-DATA`.
