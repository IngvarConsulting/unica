# Внешний кеш bsl-analyzer для наборов исходников

## Контекст

Unica 0.11.0 поставляет `bsl-analyzer` 0.2.62 и запускает постоянный MCP-процесс
анализатора с `--source-dir`, но без отдельного каталога кеша. Поэтому анализатор
создаёт `.build/bsl-graph.db` и `.build/bsl-search.db*` внутри каждого корня
исходников 1С.

Это поведение уже проявилось в пользовательском сценарии, описанном в
`IngvarConsulting/unica#412`: диагностика создала служебные файлы, а следующая
runtime-загрузка приняла их за часть XML-выгрузки и завершилась ошибкой о
неизвестном свойстве `bsl-graph` у `Configuration`. После удаления вложенного
`.build` также наблюдалось загрязнённое состояние инкрементального перечисления.
Фильтрация generated-каталогов в последующих инструментах остаётся полезной
защитой, но не устраняет первопричину — запись служебного состояния внутрь
source root.

В `bsl-analyzer` 0.2.67 появился поддерживаемый аргумент
`mcp serve --cache-dir <PATH>`. Для этой версии уже опубликованы проверяемые
артефакты `bsl-analyzer-v0.2.67-build.1` в
`IngvarConsulting/unica-toolchain` для всех поддерживаемых платформ.

ADR-0018 требует изолировать состояние поставщика нормализованной парой
`workspaceRoot + sourceRoot`. Каталог скрытого workspace-service не подходит
для постоянного кеша: сервис является процессной инфраструктурой и может быть
пересоздан, тогда как индекс анализатора относится к состоянию набора
исходников и должен переиспользоваться следующим экземпляром сервиса.

## Цели

1. Не допускать создания кеша `bsl-analyzer` внутри `src/cf`, `src/cfe/*` и
   других зарегистрированных корней исходников.
2. Сохранять и переиспользовать кеш после перезапуска или пересоздания
   workspace-service.
3. Изолировать кеши разных наборов исходников, рабочих пространств и связанных
   git worktree.
4. Соблюдать существующий корень кеша Unica, включая `UNICA_CACHE_DIR`, пока
   provider-каталог остаётся вне выбранного source root; иначе fail-safe
   использовать частный runtime-корень вне дерева без новой пользовательской
   настройки.
5. Оставить формат файлов и жизненный цикл индекса во владении
   `bsl-analyzer`; Unica назначает только корневой каталог.

## Неграницы

- Изменение обхода исходников или partial-load list в `v8-runner`.
- Перенос уже созданных `<sourceRoot>/.build` в новый каталог.
- Очистка устаревших provider-кешей.
- Публичная настройка отдельного каталога `bsl-analyzer`.
- Изменение публичной MCP-поверхности `unica.*`.
- Совместное использование индекса основной рабочей копией и git worktree.

## Рассмотренные варианты

### Кеш внутри `services/<service-id>`

Путь короткий и уже изолирован парой корней, но связывает постоянный индекс с
жизненным циклом процесса. Пересоздание или очистка сервиса может уничтожить
полезный кеш. Вариант отклонён.

### Один каталог `providers/bsl-analyzer` на workspace

Каталог переживает сервис, но разные `sourceRoot` получили бы одно частное
хранилище. Это нарушает ADR-0018 и создаёт риск одновременной работы нескольких
анализаторов с одной базой. Вариант отклонён.

### Provider-каталог со стабильным ключом набора исходников

Выбран путь:

```text
<cacheRoot>/providers/bsl-analyzer/source-<identity-digest>
```

Он отделяет состояние поставщика от процессных файлов `services/`, сохраняет
изоляцию и обычно следует существующей политике `cacheRoot`. Если `cacheRoot`
сам лежит внутри выбранного source root, например при `sourceDir="."`, тот же
ключ размещается под коротким частным runtime-корнем вне дерева: требование не
загрязнять индексируемые исходники старше предпочтительного расположения кеша.

## Идентичность и раскладка

`identity-digest` — полный SHA-256 в нижнем шестнадцатеричном представлении от
домен-разделённой последовательности:

```text
unica-provider-state-v1 NUL normalized-workspace-root-bytes NUL normalized-source-root-bytes
```

Корни нормализуются тем же механизмом, который используется для идентичности
workspace-service, а в digest передаётся явно версионированное стабильное
представление их файловой идентичности без lossy-преобразования через
`Path::display()` и без нестабильной кодировки `OsStr::as_encoded_bytes()`:
UTF-8 для обычных путей, tagged native bytes для не-UTF-8 Unix-путей и tagged
UTF-16LE для Windows-путей с непарными суррогатами. Поэтому разные допустимые
не-UTF-8 пути не получают общий кеш, а обновление toolchain не меняет адрес.
Доменный префикс и разделители не позволяют неоднозначно склеить компоненты и
оставляют явную границу для будущей версии алгоритма.

Полный digest выбран вместо текущего `svc-*`: ключ сервиса строится через
`DefaultHasher`, чей алгоритм не является долговременным дисковым контрактом.
Provider-кеш должен сохранять адрес после обновления Unica и пересоздания
сервиса.

Для стандартного корня кеша:

```text
D:\Repos\erp\.build\unica\providers\bsl-analyzer\
  source-<sha256(workspaceRoot=D:\Repos\erp,sourceRoot=D:\Repos\erp\src\cf)>
```

Для общего внешнего корня:

```text
UNICA_CACHE_DIR=E:\UnicaCache

E:\UnicaCache\providers\bsl-analyzer\source-<identity-digest>
```

В digest входит `workspaceRoot`, поэтому основная рабочая копия, каждый git
worktree и другой проект не смешивают кеши даже при общем `UNICA_CACHE_DIR`.

## Запуск анализатора

Unica вычисляет provider cache directory перед созданием MCP-процесса и
запускает встроенный анализатор так:

```text
bsl-analyzer mcp serve
  --profile workspace
  --source-dir <normalized-source-root>
  --cache-dir <provider-cache-outside-source-root>/source-<identity-digest>
  --mode stdio
```

Обычно `<provider-cache-outside-source-root>` равен
`<cacheRoot>/providers/bsl-analyzer`; для вложенного `cacheRoot` используется
частный runtime-корень. `bsl-analyzer` сам создаёт и канонизирует переданный
каталог. Ошибка подготовки кеша остаётся ошибкой запуска поставщика и
возвращается через существующий путь диагностики запуска MCP-процесса.

Перезапуск транспорта, инвалидация поколения исходников и пересоздание
workspace-service не меняют путь. Изменение `workspaceRoot`, `sourceRoot` или
`UNICA_CACHE_DIR` закономерно выбирает другой каталог.

## Изменения компонентов

### `workspace_services.rs`

- Добавляется узкая функция вычисления стабильного provider state key и пути
  кеша `bsl-analyzer`.
- Построение команды анализатора получает обязательные `--cache-dir` и
  вычисленный абсолютный путь.
- Процессные файлы по-прежнему остаются в `services/<service-id>`; provider
  cache туда не переносится.

### Контракт поставляемого инструмента

`plugins/unica/third-party/tools.lock.json` обновляется с `bsl-analyzer` 0.2.62
до 0.2.67 и ссылается на опубликованный набор
`bsl-analyzer-v0.2.67-build.1`. Для каждой платформы фиксируются имя артефакта и
его SHA-256. Workspace-зависимости `parser` и `syntax` обновляются до того же
source commit, чтобы встроенная parser-library и поставляемый анализатор
сохраняли единый контракт синтаксического дерева. Лицензионный набор не
ослабляется.

### Архитектурное описание

`spec/architecture/runtime.md` уточняет наблюдаемое поведение: частный кеш
анализатора обычно находится под provider-поддеревом `cacheRoot`, а при
вложенном `cacheRoot` — под частным runtime-корнем; в обоих случаях он
изолирован парой корней и не располагается внутри source root или каталога
процесса-сервиса.
Новое ADR не требуется: изменение реализует уже принятое решение ADR-0018 и не
переносит владение кешем между слоями.

## Обработка ошибок

- Невозможность вычислить нормализованную идентичность останавливает запуск
  анализатора до создания дочернего процесса.
- Невозможность создать или канонизировать `--cache-dir` возвращает ошибку
  запуска от `bsl-analyzer` через существующий stderr/readiness-контракт.
- Unica не пытается читать, ремонтировать или мигрировать частные базы
  анализатора.
- Старый `<sourceRoot>/.build` автоматически не удаляется, поскольку он может
  содержать артефакты других инструментов или пользовательские данные.

## Проверки

Разработка выполняется test-first.

1. Тест идентичности доказывает, что одинаковые нормализованные корни дают один
   путь, а другой source root и другой workspace/worktree — разные пути.
2. Тест пути доказывает обычное расположение под
   `cacheRoot/providers/bsl-analyzer`, в том числе для общего внешнего
   `UNICA_CACHE_DIR`, а отдельный regression-тест для `sourceDir="."` доказывает
   fail-safe размещение вне source root; оба пути не принадлежат `services/`.
3. Тест построения команды сначала падает на текущем коде, затем закрепляет
   ровно один `--cache-dir` с ожидаемым абсолютным путём.
4. Существующие тесты workspace-service подтверждают, что перезапуск,
   инвалидация и отмена постоянной сессии не изменились.
5. CI-тесты контракта bundled tools проверяют версию, артефакты и контрольные
   суммы 0.2.67.
6. Интеграционная проверка запускает diagnostics для тестового source root и
   подтверждает, что внутри него не появился `.build`, а базы анализатора
   созданы в provider cache.

## Критерии приёмки

- После `unica.code.diagnostics` для `src/cf` и каждого `src/cfe/*` внутри этих
  каталогов не создаётся `.build` анализатора.
- Каждый набор исходников получает отдельный стабильный provider cache.
- Новый workspace-service повторно использует тот же путь кеша.
- Основная рабочая копия и git worktree не используют общий индекс.
- Общий `UNICA_CACHE_DIR` безопасно обслуживает несколько рабочих пространств.
- Unica поставляет `bsl-analyzer` 0.2.67 и всегда передаёт ему `--cache-dir` в
  workspace-профиле.
