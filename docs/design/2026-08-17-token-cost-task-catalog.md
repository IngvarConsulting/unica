# Каталог фикстурных задач для метрики «токены на решение»

## Зачем

Целевая функция #479 — затратить на решение задачи пользователя наименьшее
возможное число токенов. Метрика существует только вместе с фиксированным
набором задач: этот каталог задаёт 12 репрезентативных сценариев с эталонным
решением и целевой стоимостью. Его потребители: приёмка отложенной доставки
(#479 §3, ADR-0070), эваль схем (#479 §2, включая выбор формы глубоких
union), когорты снятия скиллов (#524) и замер фазы 3.

## Определение метрики

**Токены на решение** — суммарная стоимость эпизода от постановки задачи до
подтверждённого результата, в токенах `o200k_base`:

- доля discovery-слоя: имена и краткие описания инструментов, попавшие в
  контекст (после schema-only baseline — только имена);
- полные определения инструментов, загруженные в эпизоде;
- аргументы всех вызовов;
- результаты всех вызовов, включая ошибки;
- все повторы до успеха — цена перегадывания не списывается.

Два разреза: **wire** (сериализованная форма кадров — хост-нейтральная
основа, воспроизводимая без модели) и **model-visible** (что фактически
увидела модель конкретного хоста; у Claude Code часть определений остаётся
отложенной, у Codex ожидаемо загружается всё — асимметрию меряет harness).

**First-call success** — эталонный вызов построен корректно с первой попытки:
без ошибки валидации, без повторного вызова того же инструмента с
исправленными аргументами, без подмены инструмента.

Правила прогона: свежая сессия на задачу; закреплённые commit, fixtures и
tokenizer; wire-разрез детерминирован и гоняется в CI, model-visible и
first-call — прогонami с моделью вне CI (отчёт, не гейт).

## Фикстуры

Референс-корпус — выгрузка БСП из замеров #479 (большая роль 1407 прав,
подсистема на 94 элемента, форма 26 КБ, MXL 119 КБ) плюс малая учебная
конфигурация для мутаций. Точные отпечатки фиксируются при постройке
harness (фаза 3); каталог ссылается на классы объектов, не на пути.

## Задачи

Целевая стоимость — wire-разрез, «предпочтительная / жёсткая». Первичная
калибровка: числа выведены из ограждений #479 (определение ≤2000 с
union-исключениями, обычный info ≤2000, квитанция ≤1500, манифест ≤800) и
замеров baseline; уточняются первым прогоном harness.

Замечания к составу:

- Задачи 1–2 сознательно оставлены дорогими до решения §2 по глубоким
  union — они и есть его эвал-материал: вариант «полный статический union»
  против «узких семейств» сравнивается парой «токены на решение ×
  first-call» именно на них.
- Задачи 4–6 не проходят в цель без реализации §3 — их текущая стоимость
  (39 148 / 11 561 / 6 498) и есть базовая точка «до».
- Задача 9 калибрует накладные расходы эпизода: discovery + один дешёвый
  вызов; рост этой цифры — деградация поверхности в целом, не инструмента.
- Первичные цели заданы до пере-формирования описаний: возврат прозы в
  схемы (после baseline) обязан окупаться first-call success, а не только
  влезать в ограждение — правило #479 §2.

## Протокол оценки first-call

Для каждой задачи фиксируются: выбранный инструмент, число вызовов до
успеха, класс первой ошибки (неверный инструмент / невалидные аргументы /
неверная адресация), итоговая корректность результата против эталона.
Эталон задаёт допустимые вариации (например, порядок операций в `meta.add`),
чтобы оценка не карала эквивалентные решения.
