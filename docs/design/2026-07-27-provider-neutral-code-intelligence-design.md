# Нейтральная к поставщику модель анализа кода

- Date: `2026-07-27`
- Status: `approved`
- Decision: `ADR-0017`

## Задача

`unica.code.search` должен объединить RLM, `bsl-analyzer` и буквальный поиск
`git grep`, сохранив один публичный MCP-сервер и понятную семантику частичного
результата. При этом слой application не должен знать команды процессов, схему
индекса RLM и место исполнения конкретного движка.

## Рассмотренные варианты

### Один адаптер с ветвлением по движкам

Самый короткий путь — оставить последовательные вызовы RLM,
`bsl-analyzer` и `git grep` в одном обработчике. Он сохраняет связь публичного
контракта с тремя транспортами: изменение одного движка требует правки общей
оркестрации, а отказ невозможно единообразно представить без знания его
частного ответа.

Вариант отклонён, потому что закрепляет текущее устройство движков в слое
application.

### Типизированный реестр поставщиков

Слой application видит один типизированный запрос и реестр возможностей.
Инфраструктурные поставщики преобразуют его в свои протоколы и возвращают
независимые секции. Поиск запускает все встроенные секции параллельно, но не
сравнивает их оценки и не скрывает отказ одной секции успехом другой.

Этот вариант выбран: он отделяет публичную семантику от транспорта и позволяет
проверять оркестрацию подменными поставщиками.

## Принятая граница

- Публичный инструмент — `unica.code.search`; отдельного
  `unica.code.grep` больше нет.
- Порядок секций фиксирован: `rlm`, `bsl-analyzer`, `git-grep`.
- Корень исходников разрешается один раз и передаётся всем поставщикам как
  типизированный контекст.
- Отмена MCP-вызова отменяет весь поиск и не превращается в частичный успех.
- Транспорт, процесс, индекс и разбор ответа принадлежат инфраструктурной
  реализации поставщика.

Политика индексов и сессий, включая рабочие деревья, вынесена в отдельную
[проектную записку](2026-07-27-worktree-scoped-provider-state-design.md) и
ADR-0018: место исполнения поставщика не является свойством нейтрального
контракта.

## Проверка проекта

Реализация должна доказать границу подменными поставщиками, фиксированный
порядок секций, ограниченный параллельный запуск, сохранение частичных отказов,
отмену и независимую идентичность связанного рабочего дерева. Пакетная проверка
должна заново подтвердить один публичный MCP-сервер и отсутствие зависимости от
частной схемы RLM.
