# Ядро в бюджете, движки по требованию

**Goal:** Убрать установку внешних движков из стартового бюджета хоста, чтобы
холодная сессия поднималась на любом канале, а оборванная загрузка
продолжалась, а не начиналась заново. Закрывает #585.

**Architecture:** Три записи реестра задают форму:
`DEC.2026-08-19.CORE-FIRST-ACQUISITION` — в стартовый путь едет только `unica`;
`DEC.2026-08-19.MISSING-ENGINE-WAITS` — вызов к недоставленному движку ждёт с
прогрессом, а не отказывает; `DEC.2026-08-19.ARTIFACT-VERSIONED-CACHE` — ключ
установки содержит версию артефакта, не версию плагина;
`DEC.2026-08-19.STARTUP-LEAVES-A-RECORD` — каждая стадия оставляет след,
переживающий убийство снаружи.

**Опорные замеры (из #585):** архив 98,6 MiB при 307 МБ распакованных, сжатие
≈ 3,1×; `unica` 19,2 МБ → ≈ 6 МБ в архиве. Канал пользователя 0,5–1,6 МБ/с.
Рантайм после установки: спавн 2 мс, `initialize` 28 мс, `tools/list` 42 мс.
Бюджет хоста 30 с тратится трижды по одному счёту.

| 2 | Загрузка движка по требованию: диапазоны, возобновление между сессиями, исключительная блокировка на артефакт, общий дедлайн загрузки | оборванная на середине загрузка продолжается в следующей сессии; две параллельные сессии качают один артефакт один раз |
| 3 | Ожидание вместо отказа: отправитель прогресса для загрузки, вызов дожидается и исполняется | вызов к недоставленному движку возвращает результат, а не отказ; прогресс виден на живых Claude Code и Codex |

| 5 | `prefetch` для образов и закрытого контура | команда доставляет все артефакты для цели и завершается кодом, пригодным для сборки образа |

Диагностика не отдельная фаза: **каждая фаза сдаётся вместе со своим отказом.**
Гейт любой фазы считается закрытым, только если её неудачный путь назван —
причина, место, лечение, различимый код выхода, — и убитый снаружи путь
диагностируется следующим запуском.

Фаза 4 закрывает вопрос, оставленный нерешённым в `MISSING-ENGINE-WAITS`; её
результат — отдельное решение реестра, а не деталь реализации.

## Baseline фазы 0 — снят 19.08.2026

Стенд `scripts/dev/measure-cold-start.py`, локальный сервер с отмеренной полосой,
настоящий `unica` в архиве, живые `initialize` и `tools/list`.

| Сценарий | В архиве | Канал | Всего | Из них скачивание |
| --- | ---: | ---: | ---: | ---: |
| Сегодняшняя поставка | 87,1 МБ | 0,5 МБ/с | **174,9 с** | 174,1 |
| Только ядро | 7,7 МБ | 0,5 МБ/с | **16,1 с** | 15,4 |
| Только ядро | 7,7 МБ | 1,6 МБ/с | **5,9 с** | 4,9 |

Два прогона каждого сценария разошлись на 0,11 с и 0,43 с — стенд повторяем.

**Три вывода, из которых один потребовал правки гейта.**

1. Сегодняшняя поставка превышает бюджет хоста в 5,8 раза. Дефект #585 —
   не невезение на медленной машине, а неизбежность на ней.
2. Скачивание составляет 99,6 % холодного пути. Всё остальное — сумма,
   распаковка, запуск, рукопожатие, перечисление — укладывается в 0,7 с.
   Оптимизировать что-либо кроме объёма бессмысленно.
3. **Ядро весит 7,7 МБ, а не 6, как я оценил из коэффициента сжатия
   полного архива.** Настоящее сжатие бинаря — 2,5×, а не 3,1×: у архива
   с внешними инструментами структура другая. Отсюда 15,4 с скачивания
   вместо 12, и прежний гейт «≤ 15 с» не проходил бы по факту.

Гейт исправлен на 20 с — это две трети бюджета хоста, то есть запас в треть
на машину медленнее замеренной. Число выведено из бюджета, а не из желаемого.

**Запас, если понадобится:** 19,2 МБ несжатого бинаря — не предел. Отрезание
символов и агрессивная оптимизация размера сокращают ядро, и это рычаг на
случай, если гейт станет тесным.

**Поправка к списку файлов.** При планировании сюда попал
`crates/unica-coder/src/infrastructure/workspace_services.rs` — сторона, которая

и `manifest.rs`: у установщика не было входа «поставь артефакт по имени», а без
него загрузки движка по требованию не существует вовсе.

- [x] **Step 1: Написать падающие тесты** — докачка диапазоном с середины;
  оборванная загрузка не теряется; вторая сессия ждёт первую, а не качает
  параллельно; общий дедлайн загрузки прерывает бесконечность.
- [x] **Step 2: Прогнать, убедиться в падении** — недокачка жила в транзакции с
  UUID и умирала вместе с ней, поэтому вторая сессия начинала с нуля.
- [x] **Step 3: Реализовать** — `Range`, недокачка по устойчивому пути
  `.partial/<артефакт>/<версия>-<цель>.tar.gz` рядом с `.locks`, общий дедлайн
  поверх существующих `timeout_connect` и `timeout_read`.
- [x] **Step 4: Commit** — `feat(bootstrap): resumable per-artifact acquisition`.

**Три развилки, решённые по ходу.**

1. **Сервер, забывший про диапазон.** Зеркала и прокси отвечают `200` с целым
   файлом на запрос с `Range`. Дописать такой ответ к недокачанному значит
   склеить мусор, который сойдётся по длине и не сойдётся по сумме. Продолжаем
   только после `206`; на `200` файл переписывается с нуля.
2. **Что переживает неудачу.** Недокачка остаётся лежать только после
   оборванного переноса. Байты, приехавшие целиком, дальше либо установлены,
   либо негодны — докачивать в обоих случаях нечего, и место они занимать не
   должны. Иначе отравленный архив докачивался бы вечно, вечно не сходясь по
   сумме.
3. **Брошенные версии.** Недокачка версии, которую больше не ставят, никому не
   нужна: манифест уехал вперёд. Установка артефакта убирает его же недокачки
   других версий — иначе десятки мегабайт лежали бы до конца времён.

Общий бюджет — полчаса, и это не «на всякий случай»: `timeout_read` ловит
замерший канал, но не ловит сочащийся. Сервер, отдающий байт раз в полминуты,
укладывается в каждый отдельный таймаут и не кончается никогда. Полчаса выведены
из худшего замеренного канала: 69 МБ при 0,5 МБ/с едут 138 с, и до получаса
остаётся запас на канал в тринадцать раз медленнее. Истёкший бюджет ничего не
теряет — полученное лежит на диске.
