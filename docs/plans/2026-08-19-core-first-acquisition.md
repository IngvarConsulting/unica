# Ядро в бюджете, движки по требованию

**Goal:** Убрать установку внешних движков из стартового бюджета хоста, чтобы
холодная сессия поднималась на любом канале, а оборванная загрузка
продолжалась, а не начиналась заново. Закрывает #585.

**Architecture:** Три записи реестра задают форму:
`DEC.2026-08-19.CORE-FIRST-ACQUISITION` — в стартовый путь едет только `unica`;
`DEC.2026-08-19.MISSING-ENGINE-WAITS` — вызов к недоставленному движку ждёт с
прогрессом, а не отказывает; `DEC.2026-08-19.ARTIFACT-VERSIONED-CACHE` — ключ
установки содержит версию артефакта, не версию плагина;
`DEC.2026-08-19.STARTUP-LEAVES-A-RECORD` — каждая стадия оставляет след,
переживающий убийство снаружи.

**Опорные замеры (из #585):** архив 98,6 MiB при 307 МБ распакованных, сжатие
≈ 3,1×; `unica` 19,2 МБ → ≈ 6 МБ в архиве. Канал пользователя 0,5–1,6 МБ/с.
Рантайм после установки: спавн 2 мс, `initialize` 28 мс, `tools/list` 42 мс.
Бюджет хоста 30 с тратится трижды по одному счёту.

- [x] **Step 4: Commit** — `feat(bootstrap): resumable per-artifact acquisition`.

**Три развилки, решённые по ходу.**

1. **Сервер, забывший про диапазон.** Зеркала и прокси отвечают `200` с целым
   файлом на запрос с `Range`. Дописать такой ответ к недокачанному значит
   склеить мусор, который сойдётся по длине и не сойдётся по сумме. Продолжаем
   только после `206`; на `200` файл переписывается с нуля.
2. **Что переживает неудачу.** Недокачка остаётся лежать только после
   оборванного переноса. Байты, приехавшие целиком, дальше либо установлены,
   либо негодны — докачивать в обоих случаях нечего, и место они занимать не
   должны. Иначе отравленный архив докачивался бы вечно, вечно не сходясь по
   сумме.
3. **Брошенные версии.** Недокачка версии, которую больше не ставят, никому не
   нужна: манифест уехал вперёд. Установка артефакта убирает его же недокачки
   других версий — иначе десятки мегабайт лежали бы до конца времён.

**Общий срок на загрузку отменён решением владельца 19.08.** Сперва он был
сделан — полчаса поверх `timeout_read`, против канала, который сочится по байту
и не кончается. Довод против оказался сильнее: счётчик в продукте один, и
принадлежит он запуску MCP. Доставка идёт после рукопожатия, ничьего таймера не
занимает, а движок качают, чтобы им пользоваться, — обрыв по сроку не даёт ни
байтов, ни работы. Отмеряется только тишина между байтами, и этого хватает:
замерший канал кончается отказом, ползущий доезжает.
Запись: `DEC.2026-08-19.DELIVERY-HAS-NO-BUDGET`. Цена названа там же — сервер,
отдающий байт раз в минуту, будет принят навсегда и удержит блокировку на
артефакт до отмены или перезапуска.

Вместе со сроком у доставки исчез и единственный источник `Failure::Timeout`.
Код 75 остался при настоящем таймауте — рукопожатии релизного шлюза, где вопрос
закрытый: рантайм либо ответил, либо нет.

**Почему `instructions`, а не уведомление.** Сервер объявляет одну возможность —
`tools`; `logging` не рекламируется, пока не реализовано (`CTR.WIRE.PROTOCOL`).
Заводить целую возможность ради одного сообщения дороже, чем оно стоит. Ответ на
`initialize` — первый провод, который вообще существует, и рассказ уходит по нему
обычным полем. Сессия, которой нечего рассказывать, платит за это ноль байтов:
поля просто нет.

**Почему рассказ собирает загрузчик, а не рантайм.** Формат журнала читал бы
тогда второй крейт, и у одного формата стало бы две реализации — то есть место,
где они разойдутся. Загрузчик и пишет, и читает; рантайму достаётся готовая
строка, а между ними стоит переменная окружения — та же форма, которой уже
передаются каталог состояния и кеш артефактов.

**Как симулируется убийство.** Настоящий `SIGKILL` в наборе не воспроизвести:
манифест прибивает адрес архива к релизам `IngvarConsulting/unica`, и подсунуть
загрузчику локальный сервер нечем — то же ограничение, из-за которого стенд
фазы 0 оркеструет шаги сам. Поэтому убийство выражено тем, чем оно является для
записи: `OpenAttempt` бросают, не закрыв. `Drop` у него намеренно пуст —
убитый процесс деструкторов не выполняет, и запись, закрывающаяся сама, солгала
бы ровно в том случае, ради которого заведена. Отдельный тест держит вторую
половину утверждения: посреди загрузки запись **уже** открыта, поэтому убийство
в любой момент стадии её оставляет.

**Полученный объём не пишется по ходу.** Убитый процесс не успевает записать,
сколько получил, — а недокачка на диске отвечает точнее любой записи по ходу и
не стоит ни одного обращения на горячем пути. Запись называет путь недокачки,
объём читается из неё при диагнозе.

**Замеченный отказ запись закрывает.** О нём уже сказано кодом выхода и потоком
ошибок; показывать его ещё раз следующей сессией значит показывать одно дважды.
Незакрытым остаётся только то, чего никто не рассказал.
