# PR #601 Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the core-first acquisition change as an independently verifiable PR, then migrate the normative architecture in a second non-stacked PR.

**Architecture:** Preserve `origin/pr/601` as the source of patches. Reconstruct delivery on `codex/pr-601-delivery` from current `origin/main`, translate its decisions into the current `spec/`, fix the review blockers, and merge it before creating `codex/pr-601-arch-v2` from refreshed `main`.

**Tech Stack:** Rust workspace, Python 3.12 CI scripts, GitHub Actions, JSON runtime manifests, Markdown ADR and architecture registries.

**Spec:** `docs/design/2026-08-20-pr-601-split-design.md`

## Global Constraints

- Both PRs base on `main`; no open PR may use another open PR's head as base.
- Preserve `origin/pr/601`; do not force-push, rewrite, or delete it.
- Delivery PR keeps the existing `spec/` architecture and all parity/harness contours active.
- Every defect fix starts with a regression test that fails for the intended reason.
- Cache readiness is proved by immutable delivery identity, not file existence.
- General MCP admission remains available while engine acquisition waits.
- Architecture PR starts only after delivery reaches `main`.
