# Unica v0.13 Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Завершить миграцию Unica с опубликованной поверхности v0.12.3 на один локальный MCP `unica` с private daemon, восемью предметными входами, native/compatibility Tasks profiles и атомарным RC cutover без сохранения legacy aliases.

**Architecture:** До cutover production остаётся на V12. PR #631 стабилизирует и сливает hidden V13 foundation; затем три worker-потока закрывают непересекающиеся семейства `apply` и три оставшихся группы entry points, а integrator один владеет общими application/domain/daemon/actor seams. Отдельный RC PR атомарно переключает package-selected surface, skill routing, bootstrap verification и архитектурные evidence records.

**Tech Stack:** Rust 2021, `rmcp 3.1.2`, Tokio, Serde/JSON, UUID v4, `fs2`, существующие platform facade и atomic publication primitives, Python 3.12 CI probes, GitHub Actions, пакеты Unica для Codex и Claude Code.

**Spec:** `docs/design/2026-08-28-v0-13-completion-wavefront-design.md`

## Global Constraints

- Источник baseline — опубликованный `v0.12.3`: 74 уникальных публичных имени, включая шесть `unica.runtime.job.*`. Текущие 71 имя в ledger `main` не заменяют release fixture.
- До Gate G6 package-selected production surface остаётся V12. Hidden V13 доступен только через уже существующие injected constructors и тестовые harnesses; новый CLI flag, environment switch или secret package mode запрещён.
- Единственный публичный MCP-сервер сохраняет identity `unica` и local stdio transport. Daemon остаётся private per-user mode того же versioned core.
- Целевой native Tasks profile содержит ровно восемь entry points: `view`, `apply`, `find`, `search`, `check`, `diff`, `run`, `docs`. Compatibility profile добавляет только `task.get`, `task.result`, `task.cancel`.
- Один предметный вызов создаёт одну Invocation и имеет ровно одно исполнение. Frontend не делает fallback, replay или retry предметной операции после handoff.
- Known-long operation materializes durable Task сразу. Остальные операции завершаются напрямую либо имеют durable receipt к абсолютной границе 7 000 мс от приёма `tools/call`; тесты используют fake clock.
- После receipt прогресс v0.13 наблюдается polling-ом status и `updatedAt`. Новый public progress/log API и generic resume protocol не создаются. После restart продолжение допустимо только для зарегистрированного typed owner; иначе Task получает terminal outcome без повторного исполнения mutation.
- Engines доставляются лениво из `unica-toolchain` по immutable identity; `prefetch` наполняет offline closure. `tools-download` и raw CLI passthrough не входят в `run`.
- `apply` сначала строит полный staged postimage и validation result, затем публикует Source и WorkspaceCache как закрытый transaction set. Ambient filesystem reads после actor admission запрещены.
- Domain layer не импортирует infrastructure. Типы validation target/finding/failure принадлежат domain; read port принадлежит application; persisted и staged adapters принадлежат infrastructure.
- Любой дефект сначала воспроизводится падающим тестом. Увеличение test/CI timeout не считается исправлением daemon hang или неверной ownership boundary.
- Любой новый Rust test filter сначала выполняется с `-- --list`; ноль найденных тестов является RED infrastructure failure, а не зелёным результатом slice.
- Изменение публичной поверхности, wire identity, task observation, packaging или границы слоёв вносит successor `DEC.*` и derived `INV.*`/`CTR.*` в том же PR. Уже merged product record не переписывается.
- `tests`, `features`, `log`, gRPC и platform 8.5 profile остаются вне v0.13.
- Публикация tag, prerelease, stable assets и marketplace promotion требует отдельного owner approval по `docs/release-runbook.md`; этот план не даёт такого разрешения.

```text

          \                |                /

                           v

                           |
                           v

                           |

                           |
                           v
                    G7 stable (S4)
```

- W0 changes are committed to the existing PR #631 head branch. A defect introduced by #631 is fixed there, not in a child PR.
- Workers may prepare local branches from an accepted W0 SHA, but no PR may use the open PR head as its base. After #631 merges, every W1/W3 PR starts from current `main`.
- W1A, W1B and W1C are three parallel lanes, not three mega-PRs. Each lane is a sequence of A1–A6, B1–B6 or C1–C6 short non-stacked PRs; W2 may integrate a slice only after that PR is merged into `main` and cannot finish before all eighteen slices are integrated.
- W2 is an incremental loop of short integrator PRs from updated `main`, not one long-lived branch accumulating all W1 work. A shared delta merges after the corresponding worker slice; the final W2 closure PR starts fresh after all prior worker/integrator PRs are in `main`.
- W3A, W3B and W3C are three parallel lanes opened only after W2 is merged into `main`. Each lane is a sequence of the named A7–A10, B7–B10 or C7–C9 short PRs; stable daemon adapters are integrator-owned.
- W4 mapping/tests may merge before cutover, but the 73 skill content patches remain unapplied until G6 because shipped instructions must continue matching production V12.
- G6 is one atomic RC cutover PR. G7 is a separate version-only stable PR after the RC host matrix.
- A slice lives no more than two working days without integration review. Long-lived divergent worker branches and stacked PRs are stop conditions.
