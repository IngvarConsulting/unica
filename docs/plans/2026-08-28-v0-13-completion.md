# Unica v0.13 Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Завершить миграцию Unica с опубликованной поверхности v0.12.3 на один локальный MCP `unica` с private daemon, восемью предметными входами, native/compatibility Tasks profiles и атомарным RC cutover без сохранения legacy aliases.

**Architecture:** До cutover production остаётся на V12. PR #631 сначала закрывает подтверждённый W0 blocker: отдельный private durable `ReceiptLedger` резервирует exact Invocation/Task/request identity до предметной работы, связывает promised Task и TaskStore recoverable write-ahead protocol с атомарным переключением projection, хранит terminal Direct до private ACK и не допускает replay после `Reserved::Begun`. После S1 три workers собирают schema-derived/behavior evidence v0.12.3 и классифицируют upstream-влияние на skills, пока integrator закрывает W2a-core. Затем integrator последовательно собирает content-addressed capability baseline и immutable provenance scope review и получает два независимых review; только этот join освобождает три непересекающиеся worker-линии W1. Параллельно integrator завершает W2a-seams до первого перехода любой линии в W3 и непрерывно выполняет W2b wiring. W4 превращает review в content-addressed cutover patch lock. Отдельный RC PR атомарно переключает package-selected surface, skill routing, bootstrap verification и архитектурные evidence records.

**Tech Stack:** Rust 2021, `rmcp 3.1.2`, Tokio, Serde/JSON, UUID v4, `fs2`, существующие platform facade и atomic publication primitives, Python 3.12 CI probes, GitHub Actions, пакеты Unica для Codex и Claude Code.

**Spec:** `docs/design/2026-08-28-v0-13-completion-wavefront-design.md`

## Global Constraints

- Источник baseline — опубликованный `v0.12.3`: 74 уникальных публичных имени, включая шесть `unica.runtime.job.*`. G6 атомарно снимает 71 текущую V12-регистрацию, а RC acceptance доказывает отсутствие всех 74 имён release fixture. Три baseline-имени уже отсутствуюют в текущей ведомости `main`: `unica.help.add`, `unica.template.add`, `unica.template.remove`; ведомость из 71 имени не заменяет immutable release fixture.
- До Gate G6 package-selected production surface остаётся V12. Hidden V13 доступен только через уже существующие injected constructors и тестовые harnesses; новый CLI flag, environment switch или secret package mode запрещён.
- Единственный публичный MCP-сервер сохраняет identity `unica` и local stdio transport. Daemon остаётся private per-user mode того же versioned core.
- Целевой native Tasks profile содержит ровно восемь entry points: `unica.view`, `unica.apply`, `unica.find`, `unica.search`, `unica.check`, `unica.diff`, `unica.run`, `unica.docs`. Compatibility profile добавляет только `unica.task.get`, `unica.task.result`, `unica.task.cancel`.
- В пределах bounded ReceiptLedger retention/deduplication horizon один exact `ReceiptKey` создаёт одну Invocation и допускает не более одной попытки `prepare`/`execute`; после `Reserved::Begun` replay запрещён. Frontend не делает fallback или replay; exact duplicate до expiry только reconciles уже существующий receipt/outcome. После physical expiry вечная idempotency, exactly-once outcome и exactly-once delivery не обещаются.
- Потеря submit session сама по себе не отменяет вызов, не меняет receipt и не форсирует Task: daemon продолжает original lifecycle/cutoff и ещё может durable завершить Direct. Только исходный cutoff либо current post-prepare `KnownLong` выбирают соответствующий Task handoff; reconnect/recovery не создаёт новый budget.
- Strict valid-submit boundary наступает после authenticated strict outer-envelope parse с каноническими `InvocationId`, `reservedTaskId`, tool/arguments/workspaceHint, budget `0..=7000` и daemon-side recomputation request identity, но до validation tool arguments/workspace, actor admission, `prepare` и `execute`. Неразбираемая envelope, budget выше 7000 или oversized workspaceHint не valid submit, поэтому не создаёт ledger row и не запускает предметную работу; clamp/truncate и caller-provided digest authority запрещены.
- `ReceiptLedger` атомарно резервирует exact пару IDs и secret-free digest immutable request scope, исключающий response budget. Same pair + same identity reconciles existing state; same InvocationId с другим TaskId, same TaskId с другим InvocationId или same pair с другим request identity закрыто отклоняются, не меняя original. Workspace-selector digest не является actor-derived workspace identity.
- Перед первым `service.prepare` ledger durable-фиксирует `Reserved::Begun`. Crash до terminal commit завершает receipt как distinct `V5SafeFailureReason::OutcomeUncertain` во v5 store/snapshot/native+compat projections, без replay; сворачивать его в `Interrupted` запрещено. Известный outcome после такого crash разрешён только операции с доказанной atomic coupling/idempotent recovery.
- Hidden-v5 terminal payload закрыт как `Completed(DomainResult) | Failed(V5SafeFailureReason) | Cancelled`. Terminal owner выбирается current durable state, не historical promise. Semantic validation и все `WorkspaceAdmissionError` происходят pre-ActorBound: `Reserved::Unbound` terminalizes Direct, `TaskPromisedUnbound` — receipt-backed Task. Invalid является Completed с `DomainResult.ok=false`; Capacity — durable `Failed(V5SafeFailureReason::WorkspaceCapacity)`, retryable новой invocation без callback/restart; RegistryFailed — durable `Failed(V5SafeFailureReason::WorkspaceRegistryFailed)`, затем `RestartRequested`/fail-stop. Prepare rejection post-Begun: Direct лишь в `Reserved::Begun`; pre-bind handoff stage-ит outcome, затем while handoff+live reservation остаются retained TaskStore создаёт/readback-ит terminal record и ledger одним commit переходит прямо в `TaskTerminalBound`, без промежуточного `TaskBound`; proven begun Link Capacity terminalizes receipt-owned; already TaskBound всегда terminalizes TaskStore. Receipt не откатывается. Failed не содержит DomainResult, Cancelled не содержит result/reason. Side-by-side `V5SafeFailureReason` содержит exact legacy `InvocationFailed`, `ResultTooLarge`, `Interrupted`, `ResumeUnsupported`, `PersistenceFailed` плюс `OutcomeUncertain`, `TaskCapacity`, `WorkspaceCapacity`, `WorkspaceRegistryFailed`, с total infallible conversion current `SafeFailureReason`→v5. `InterruptedBeforeExecution` — recovery classification, persisted v5 reason остаётся `Interrupted`; `TaskCapacity` означает только proven `LinkCapacity` до `Begun`. Current `SafeFailureReason`, schema-v2 `StoredInvocationRecord`, active v3 early-error mapping и их serde acceptance сохраняются буквально до и после W0c.
- W0a не добавляет variants/fields в active `ClientRequest`/`ServerResponse` или schema-v2 record. Он вводит distinct strict `V5ClientRequest`/`V5ServerResponse`, `V5StoredInvocationRecord` и `V5SafeFailureReason` (не aliases) в `crates/unica-coder/src/infrastructure/daemon/protocol_v5.rs`, `crates/unica-coder/src/application/invocation_store_v5.rs`, `crates/unica-coder/src/infrastructure/task_store_v5.rs`. V5 lifecycle/composition также distinct в `crates/unica-coder/src/application/invocation_v5.rs` и `crates/unica-coder/src/infrastructure/daemon/runtime_v5.rs`, projections — в versioned `interfaces/task_projection_v5.rs`/`application/v13/task_tools_v5.rs` либо exact equivalents. Current `application/invocation.rs`, v3 protocol/client/store/projectors и decoders остаются literally untouched. Before v5 wiring, private `CanonicalInvocationService`, `ActorBoundInvocation`, `ActorBoundExecution` and capability helpers move semantic-neutral from `daemon/server.rs` to shared `daemon/invocation_service.rs`; v3 server and `v13_service.rs` receive narrow import/impl-path edits guarded by byte-equivalent v3 JSONL/serde/behavior tests. Application-owned checked `CoreIdentityDigest` не импортирует infrastructure; infrastructure `CoreIdentity` wraps it and exposes its typed digest. `CoreIdentity` и state selector параметризуются protocol identity; default `production()` composition остаётся v3. W0c выбирает v5 composition, не переопределяя старые decoders.
- Freeze v5 serde before implementation: every newly introduced v5 envelope/record/selected internally tagged variant is camelCase + `deny_unknown_fields`, exact tags/variants are snake_case, and defaults/flatten/open maps are forbidden in those new types. Existing `DomainResult` inside Completed is reused with byte-for-byte unchanged serde acceptance; do not copy or mutate the active v3 type. Protocol uses `protocolVersion:5` and no `schemaVersion`. Client kinds/fields are exactly `hello(protocolVersion,token,coreIdentity,ownerLease)`, `ping`, `release`, `submit_invocation(invocation)`, `get_task(taskId)`, `wait_task(taskId,waitMs)`, `cancel_task(taskId)`, `recover_invocation_receipt(receiptKey)`, `acknowledge_invocation_receipt(receiptKey,terminalDigest)`, `cancel_invocation(receiptKey)`; invocation fields are `invocationId,reservedTaskId,tool,arguments,workspaceHint,responseBudgetMs`; full key fields are `invocationId,reservedTaskId,coreIdentityDigest,tool,normalizedArgumentsHash,requestScopeHash`. Server kinds/fields are exactly `ready(protocolVersion,coreIdentity,daemonPid,instanceId)`, `pong`, `released`, `invocation(outcome)` for submit/exact duplicate/recovery, `task(snapshot)`, `invocation_acknowledged(acknowledgement)`, `error(code)`. `V5InvocationResponse.resultType` is `receipt_pending|direct|task|acknowledged`; `V5TerminalOutcome.status` is only `completed{result}|failed{reason}|cancelled{}`. Code-only protocol errors are `invalid_request,handshake_required,protocol_mismatch,core_mismatch,unauthorized,duplicate_lease,overloaded,owner_capacity,receipt_not_found,receipt_expired,receipt_capacity,tombstone_capacity,invocation_identity_mismatch,task_not_found,task_expired,store_failed,durability_uncertain`; post-reserve semantic/admission/capacity/uncertain outcomes are terminals, not errors.
- Freeze strict `V5DaemonTaskSnapshot.status` as `queued|working|completed|failed|cancelled` with common exact `taskId,invocationId,receiptKeyDigest,createdAtEpochMs,updatedAtEpochMs,ttlMs,pollIntervalMs,version,cancelRequested`; Completed adds `terminalEpochMs,terminalDigest,result`, Failed adds `terminalEpochMs,terminalDigest,reason`, Cancelled adds `terminalEpochMs,terminalDigest`. Freeze distinct `V5StoredInvocationRecord` as `schemaVersion:1` plus exact `taskId,invocationId,receiptKeyDigest,tool,normalizedArgumentsHash,workspaceIdentityHash,createdAtEpochMs,updatedAtEpochMs,ttlMs,pollIntervalMs,version,cancelRequested,task`; nested task has the same closed terminal algebra without optional result/open failure. Nine failure strings are exact `invocation_failed,result_too_large,interrupted,resume_unsupported,persistence_failed,outcome_uncertain,task_capacity,workspace_capacity,workspace_registry_failed`.
- Freeze v5 projections: native Direct Completed is exact `CallToolResult`, Failed is `ErrorData(-32603,<closed message>,{code})`, Cancelled is `ErrorData(-32603,"daemon invocation was cancelled",{code:"invocation_cancelled"})`; ACK only after immutable final object. Native Tasks maps internal Queued/Working to MCP Working, Completed to Completed+exact CallToolResult, each of nine Failed reasons to Failed+typed ErrorData, Cancelled to Cancelled without invented payload. Compatibility preserves exact queued/working/completed/failed/cancelled and raw IDs/timestamps; Failed returns its reason code/message, not generic `task_failed`; Cancelled uses `task_cancelled`. Exact reason message table in daemon-receipt-ledger design is required test data. Active v3 projections remain literal unchanged.
- Application owns only `V5CanonicalTerminal` (typed outcome, one canonical payload and digest) and opaque owner-specific linear publication types. Sole `infrastructure/daemon/terminal_codec_v5.rs` builds `PreparedReceiptRecord`, optional `PreparedTaskRecord`, optional `PreparedTaskLifecycleLinkRecord` and transient `PreparedWireFrame`, never arbitrary adapter bytes. Direct/ReceiptTask binds `receiptExpectedVersion`; BoundTask binds independent `taskExpectedVersion`, `lifecycleLinkExpectedVersion` and exact link digest. Before the first HandoffStage mutation, the codec builds both a CAS/size-preflighted `PreparedStagedReceiptRecord` and typed `StagedTerminalTransferSizeCertificate`, exact-bound to protocol-v5/CoreIdentity, key/task/link, terminal digest+epoch and fixed schema/limit versions. The certificate covers the staged receipt and conservative upper bounds for every final terminal Task record, sole `TaskTerminalBound` lifecycle-link record and v5 Task frame across `Absent`/`ExactProvisional`, Queued/Working, both cancel values, max-width u64 values and newline, plus the `TaskTerminalReceiptBacked` record+frame for proven LinkCapacity without reservation. Certificate evidence persists inside the staged record and ledger returns opaque `CommittedStagedHandoffReceiptWithCertificate`; no wire frame is persisted. StagedHandoffTask later accepts only that committed readback, rehydrates the canonical terminal inside the sole codec and binds closed `StagedTaskPublicationExpectation::{Absent, ExactProvisional { taskId, invocationId, status: Queued|Working, version, cancelRequested, taskLinkDigest }}`, live reservation and embedded receipt version without requiring `TaskBound`. Late codec consumes the checked certificate and requires every exact size <= its certified bound; valid certificate makes late oversize unreachable, while mismatch/invariant fail-stops without mutation or terminal reclassification. Closed `StagedLinkCapacityEvidence` returns certificate authority untouched, preserves the staged winner and proves no reservation exists. Each store consumes only its piece/version; TaskStore creates terminal when absent, CAS-terminalizes only that exact provisional record, accepts exact same terminal and rejects every foreign/mismatch, then returns exact readback plus remaining lifecycle-link/wire pieces. Ledger consumes the sole lifecycle-link piece, removes the active receipt representation and returns committed publication carrying the untouched frame. Staged TaskStore terminal commit retains handoff+reservation until direct `TaskTerminalBound`; crash recovery performs only exact readback and that commit. Persist exactly one canonical terminal payload/digest/epoch per logical owner under the inclusive MAX entitlement, never a full response frame beside it. Immediate submit uses the prepared frame; duplicate/recovery freshly build/size/hash a frame before each write. After frame preflight reserialization/fallback is forbidden. Static ownership guard permits piece/certificate construction and envelope serialization only in codec/golden tests. Post-reserve catalog/schema, identity/proof, serialization, `TaskStoreCapacityInvariantViolation` and commit uncertainty retain durable intent/reservation and fail-stop with exact readback; binder keeps semantic Invalid, Capacity, RegistryFailed and technical faults distinct.
- `ReceiptKeyDigest` имеет одну application-owned authority: SHA-256 domain `unica.receipt-key.v1\0`, затем fixed-order InvocationId, reservedTaskId, core digest, tool wire name, normalized arguments hash, request-scope hash, каждый как u32 big-endian byte length + normalized bytes. Distinct `RequestScopeHash` helper hashes domain `unica.request-scope.v1\0` + u32-BE exact strict-parsed workspaceHint UTF-8 length + exact bytes, без filesystem canonicalization/case folding/trim; frozen `workspace-a` vector is `9f7a5a77bb6eb469cd20147a9aeee9d9769a8372f587bd89635d15684ee02b39`. Frontend/server/fixture use one helper; actor-derived `SafeIdentityHash` remains separate. Rebuilt uniqueness indexes `InvocationId -> exact ReceiptKey` и `reservedTaskId -> exact ReceiptKey` охватывают retained active/tombstone/link records; partial collision отклоняется до mutation, persisted collision срывает store open до listener.
- Distinct application-owned `TaskLinkDigest` helper SHA-256-hashes domain `unica.task-link.v1\0`, then u32-BE-length-prefixed lowercase ReceiptKeyDigest ASCII, canonical TaskId UUID text, canonical InvocationId UUID text and lowercase actor-derived workspaceIdentityHash ASCII in that order. It is link identity, not Task-record digest: mutable status/version/updatedAt/cancelRequested/terminal and ephemeral actor generation are excluded. Ledger, TaskStore, runtime recovery and terminal codec receive only the typed helper result; fixture calls the production export. Frozen vector with ReceiptKeyDigest=`0`×64, TaskId `11111111-1111-4111-8111-111111111111`, InvocationId `22222222-2222-4222-8222-222222222222`, workspaceIdentityHash=`a`×64 is `4c73d08219973c72e759a9f85e156fa42c9d8e61a56e704b70d1c7c042b73da0`.
- Cutoff внутри `Reserved::Unbound` validation/admission durable-создаёт receipt-backed `TaskPromisedUnbound` с exact TaskId. Один per-invocation two-second grace начинается при этом commit и передаётся validation→admission→bind без reset. Если pipeline ещё блокируется, projections уже возвращают durable queued Task, но TaskStore record не создаётся до actor bind. В `TaskPromisedUnbound` cancel/restart именно до actor bind terminalizes receipt-backed Task без callback и TaskStore. После actor bind `TaskPromisedActorBound` несёт actor-derived identity, exact promotion intent и durable cancel flag; до commit `TaskBound` этот flag остаётся под ReceiptLedger authority. Перед любой TaskStore mutation ReceiptLedger durable резервирует exact Task-link count/full 1 KiB byte entitlement; only then create/readback + materialized link + `TaskBound` переносят authority. Proven Link Capacity не касается TaskStore. Successful reservation уже гарантирует TaskStore count slot; post-reservation count `Capacity` становится только `TaskStoreCapacityInvariantViolation`, удерживает intent/reservation и fail-stop-ит без terminal/fallback/release. `CommitUncertain` также удерживает reservation до reconciliation, но остаётся отдельной commit-классификацией. Current `ExecutionClass::KnownLong`, cutoff во время `prepare`/`execute` и любой cutoff после `Reserved::ActorBound/Begun` создают `TaskHandoffActorBound { begun, exact intent }`; proven Link Capacity до `Begun` закрывает receipt-backed `Failed { V5SafeFailureReason::TaskCapacity }`, после `Begun` оставляет `TaskReceiptOwnedActorBound`. Общей физической транзакции между stores нет; projection меняется только после exact reconciliation. Граница остаётся 7 000 мс от приёма `tools/call`; тесты используют fake clock и barrier.
- Application `invocation_v5` owns only the pure lifecycle executor/state machine and `ActorBindingClaim { identity, generation }`/opaque token/port types. Infrastructure-private `runtime_v5::InvocationCoordinator` is the only owner of actual WorkspaceActor/resource lease, verifier, per-invocation gate and provider cancellation token. `bind_actor`/`bind_promised_actor` accept the claim and return committed receipt + one-shot `V5ActorBindingToken`. Direct begun consumes it after private live-lease verification. Task authorize consumes it and returns the single named `PostWorkingActorAuthorization`; TaskStore start takes `(TaskBoundLinkAuthorization, exactCurrentTaskBoundProof, taskIdentity, expectedVersion, deadline)` and its Working readback/link evidence plus the post-Working authorization are required by `mark_bound_task_begun`. Static import/constructor/call-site guard forbids application→infrastructure imports and any other verifier/token site; this is not cryptographic unforgeability. Restart cannot reconstruct tokens. Cancel commits durable authority before coordinator signals provider token; lease stays until terminal/PID death. Begun=false recovery is Cancelled only from flag, otherwise Interrupted; begun=true is distinct OutcomeUncertain.
- Protocol-v5 startup opens TaskStore inspect-only and separately rejects orphan Queued and orphan Working without exact receipt/link before mutation/listener. It materializes a link for an existing Task only from exact retained handoff intent + matching live `TaskLinkReservation`; absent/expired/mismatched reservation is corruption/fail-stop and cannot reconstruct entitlement or bypass 4096. Task-create `CommitUncertain` preserves the write-ahead intent and reservation for exact readback, never masquerades as proven Capacity and never blindly retries create.
- Direct terminal сначала durable-фиксируется в ReceiptLedger, затем пишется в private submit session как `V5PendingDirectReceipt { terminal, receiptKey, terminalDigest, terminalEpochMs }`. Потеря transport/restart возвращает тот же terminal до terminal+1h. Frontend полностью строит final immutable `CallToolResult` для Completed либо exact `ErrorData` для Failed/Cancelled и только затем ACK-ит; projection/drop/crash before final object sends no ACK. Tombstone содержит key+digest+first-ACK epoch, живёт 15 минут от first ACK и не содержит cutoff/budget/result. Premature/mismatched/Task ACK не мутирует state; потеря ACK retry-safe; full tombstone pool возвращает typed capacity и оставляет Direct unacked до retry/expiry. Это не public API.
- `TaskReceiptOwnedActorBound` остаётся в том же 64-record/541 065 216-byte live payload pool до receipt-backed terminal; proven `LinkCapacity` не вытесняет чужой Task и не повторяет link reservation/create после `Begun`. В этой branch reservation не существует; post-reservation TaskStore Capacity не может выбрать её.
- ReceiptLedger и TaskStore физически имеют separate storage/byte limits и retention, но v5 TaskStore count admission доминируется lifecycle-link pool. Один общий live count cap 64 охватывает `CancelReserved`, `Reserved`, promised/handoff, `DirectTerminalUnacked` и `TaskTerminalReceiptBacked`; actual-plus-reserved byte cap равен 541 065 216 (`64 × 8 454 144`). Для каждого payload-capable live record это один total entitlement: `encodedBytes + reservedResultBytes == 8 454 144`; terminal record persists exactly one canonical payload/digest/epoch, never a duplicate full response frame, and transient frame bytes are separately preflighted rather than charged again. During staged handoff, the receipt MAX share stays charged until direct `TaskTerminalBound`; link reservation guarantees the TaskStore count slot and the codec separately preflights the exact Task record against its per-record byte limit. The same canonical payload may physically exist in both stores only in that bounded transfer window, but no second receipt MAX admission/frame exists; final ledger commit releases the receipt share. Fixture entitlement не передаёт. `CancelReserved` занимает one count slot and ≤1 024 bytes actual metadata without result entitlement; exact submit atomically replaces that charge with the full entitlement. Direct и receipt-backed Task TTL идут from terminal epoch. Separate 4 096/4 194 304-byte lifecycle-link pool stores reservations and exactly one ≤1 024-byte `TaskLifecycleLinkRecord` whose closed state is `TaskBound | TaskTerminalBound | TaskRetirementPending`; those states are not duplicate active receipt records. For isolated v5 state every TaskStore record injectively/exactly matches one materialized lifecycle link or retained reservation, while Pending after Task delete may only increase links relative to Tasks; startup before listener and every mutation prove `taskStoreRecordCount <= materializedLifecycleLinkCount + liveLinkReservationCount <= 4096`. Successful new reservation therefore proves pre-create `taskStoreRecordCount <= 4095`. Materialization atomically removes the active receipt representation and redirects key/dual-ID indexes to the sole link record. Terminal bound retirement mutates that same record: live/nonterminal `TaskBound` never expires; `TaskTerminalBound` CAS-enters `TaskRetirementPending`, resolver becomes `task_expired`, coordinator-only opaque authorization exact-deletes TaskStore, and only `Deleted|AbsentExactWithPending` proof permits final link-record/dual-ID removal. No v5 lazy delete; uncertainty/mismatch or count/link invariant violation retains evidence and fail-stops. `28 864` key+digest+first-ACK-epoch tombstones have 14 778 368-byte cap and 900-second TTL from first ACK. W0 first runs 28 800 ACKed lifecycle with 32 retained terminals, ≤32 cycling Direct and 4 096 links, then separate 64-live/rejected-65th and full-tombstone overflow/reopen phases. Expected tombstone count/high-water is derived from raw ACK epochs; all 28 800 need not coexist exactly at `t=900s`. Each OS passes ≥1 920 lifecycle/60s with p99 ≤250ms and drain ≤2s; unexpired evidence is not evicted.
- После receipt прогресс v0.13 наблюдается polling-ом status и `updatedAt`. Новый public progress/log API и generic resume protocol не создаются. После restart продолжение допустимо только для зарегистрированного typed owner; иначе Task получает terminal outcome без повторного исполнения mutation.
- Engines доставляются лениво из `unica-toolchain` по immutable identity; `prefetch` наполняет offline closure. `tools-download` и raw CLI passthrough не входят в `run`.
- `apply` сначала строит полный staged postimage и validation result, затем публикует Source и WorkspaceCache как закрытый transaction set. Ambient filesystem reads после actor admission запрещены.
- Domain layer не импортирует infrastructure. Типы validation target/finding/failure принадлежат domain; read port принадлежит application; persisted и staged adapters принадлежат infrastructure.
- Любой дефект сначала воспроизводится падающим тестом. Увеличение test/CI timeout не считается исправлением daemon hang или неверной ownership boundary.
