# Implementation plans

Здесь лежат датированные планы реализации: разбиение работы на задачи, порядок
шагов, что и как тестировать. Их пишет скилл `writing-plans` (superpowers);
каталог задан проекту в [`AGENTS.md`](../../AGENTS.md) и переопределяет путь
плагина по умолчанию.

**archived planning material, not a source of truth.** План одноразовый: он
описывает намерение на свою дату и после реализации не поддерживается. Если
план и код расходятся — прав код. Если план и решение из `spec/decisions/`
расходятся — право решение.

План не является местом для архитектурных решений. Решение, обнаруженное во
время планирования, поднимается в проектный документ
([`docs/design/`](../design/README.md)) и, если оно меняет архитектурный
контракт, в запись `spec/decisions/` — порядок описан в
[`AGENTS.md`](../../AGENTS.md).

## Документы, на которые опирается CI

`tests/ci/test_dcs_naming_contract.py` исключает этот каталог из проверки
именования домена схем компоновки данных: планы написаны до переименования и
сохраняют исторические имена намеренно.
