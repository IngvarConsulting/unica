# План реализации ограниченного `git-grep` fallback

## 1. Зафиксировать архитектурный контракт

- Добавить ADR-0055, уточняющий ADR-0040 в части политики исполнения `git-grep`:
  нового скомпилированного бюджета, ограниченного потокового чтения, остановки
  дерева процесса по лимиту и исходов таймаута и отмены. Остальные правила
  операционного снимка остаются во владении ADR-0040.
- Сохранить статус ADR-0040 как `accepted`, обновить индекс решений и
  `INV-MCP-CODE-SEARCH-SECTIONS`/`INV-APP-CONFIG-SNAPSHOT`.
- Запустить проверки архитектурного реестра и проектных документов.

## 2. Добавить управляемую раннюю остановку потокового процесса

- Сначала добавить тесты на сигнал потребителя после шестой строки и на
  завершение дерева процесса без признаков timeout/cancellation; убедиться, что
  они падают на текущем API.
- Ввести закрытый тип решения `Continue/Stop`, протянуть его через
  `ProcessRunner` и `ManagedChild`, сохранить прежнее поведение диагностики.
- Запустить тесты процесса и внутреннего адаптера.

## 3. Перевести `GitGrepProvider` на ограниченный поток

- Сначала заменить fake-runner тестами, которые требуют остановки на шестом
  корректном результате, отсутствия `-m`, честного таймаута и естественного
  завершения с меньшей выдачей; подтвердить ожидаемое падение.
- Читать и разбирать строки потока, остановить процесс на `limit`, удалить
  полное накопление/сортировку/truncation-ветви.
- При таймауте и отмене отбрасывать накопленные попадания; при естественном
  завершении сохранять до `limit`.
- Запустить все тесты `git_grep` и координатора поиска.

## 4. Изменить скомпилированный бюджет

- Сначала изменить поведенческое ожидание конфигурации на 500 мс и подтвердить
  падение.
- Заменить скомпилированное значение, не меняя секундный формат явного
  переопределения и межполевые ограничения.
- Запустить тесты операционной конфигурации.

## 5. Проверить исправление и обновить задачу

- Запустить `cargo fmt --check`, целевые тесты, полный `cargo test -p
  unica-coder` и проверки архитектурной документации.
- Собрать debug-бинарь и повторить `unica.code.search` на Sendbox с `limit = 6`.
- Обновить критерии GitHub issue #467 фактической политикой «6 результатов или
  500 мс», приложить результаты проверки.

## 6. Закрыть замечания PR и холодный интеграционный контур

- Сначала добавить падающие тесты маршрутизации отдельного assessment-контура:
  затронутый code-search/process/index механизм и `ci:full` запускают BSP, а
  несвязанный Rust-код — нет.
- Добавить падающий тест условного ожидания: холодный индекс повторяется до
  `ok`/`empty` индексной секции, терминальный отказ и исчерпание дедлайна не
  маскируются.
- Добавить падающие регрессии для не-UTF-8 результата, раннего ненулевого выхода
  и незавершённого reap; исправлять каждую причину отдельно.
- Сверить lifecycle ADR-0040/ADR-0055 с историческим каталогом решений и явно
  разделить владение: ADR-0040 сохраняет правила операционного снимка, а
  ADR-0055 владеет ограничением и завершением `git-grep`.
- Запустить целевые тесты после каждого исправления, затем полный Rust/Python
  контур, обновить ветку PR и перепроверить GitHub Actions и review threads.
