# ADR-0053: Постоянная сессия поставщика не удерживает рабочее дерево

- Статус: `accepted`
- Дата: `2026-08-11`
- Задача: [#204](https://github.com/IngvarConsulting/unica/issues/204)

## Контекст

ADR-0006 делает сессию поставщика постоянной: она переживает вызов
инструмента, чтобы следующий вызов не платил за запуск процесса и построение
индекса заново. ADR-0018 изолирует состояние поставщиков рабочим деревом.

Из этих двух свойств вместе следовало третье, которого никто не выбирал.
Дочерний процесс анализатора запускался с рабочим каталогом внутри дерева
(`current_dir(&context.cwd)`), и пока сессия жива — то есть после возврата из
вызова, — процесс держит это дерево открытым. `git worktree remove` отказывает
спустя долгое время после того, как вызов завершился успешно.

`SessionTeardownLifecycle::drain` тут не помогает и не сломан: он ждёт
завершения процессов при выводе сессии из обращения, а сессия из обращения не
выводится — она живёт по замыслу.

Рабочий каталог при этом ничего не сообщает: дерево адресуется аргументом
`--source-dir` абсолютным путём. Каталог только удерживает.

## Решение

1. Постоянная сессия поставщика не удерживает рабочее дерево. Дочерний
   процесс запускается из каталога вне любого рабочего пространства.
2. Дерево адресуется аргументом, а не рабочим каталогом. Поставщик, которому
   для работы нужен рабочий каталог внутри дерева, обязан объявить это, и
   такое требование разбирается отдельно — молча наследовать `cwd` вызова
   нельзя.
3. Каталогом запуска служит тот же короткий приватный runtime-каталог, который
   сессия уже использует для своего сокета. Отдельной сущности не заводится.
4. Изоляция состояния поставщика рабочим деревом (ADR-0018) не ослабляется:
   она достигается адресацией и раздельным состоянием, а не тем, откуда
   запущен процесс.

## Неграницы

1. Решение не меняет время жизни сессии и не привязывает её к дереву. Сессия
   остаётся постоянной, как её определяет ADR-0006.
2. Решение не касается процессов, порождаемых на время одного вызова: их
   удержание заканчивается вместе с вызовом.
3. Решение не отменяет ожидание завершения при выводе сессии из обращения.

## Последствия

1. `git worktree remove` перестаёт конфликтовать с живой сессией анализатора.
2. Поставщик теряет возможность полагаться на рабочий каталог как на неявный
   адрес дерева. Сегодня ни один этого не делает — дерево уже передаётся
   аргументом, — но будущий обязан объявить такую зависимость явно.
3. Диагностика поставщика, писавшая относительные пути от рабочего каталога,
   начнёт писать их от runtime-каталога. Наблюдаемых потребителей у такого
   вывода нет: результат приходит типизированным.

## Верификация

- `cargo test --package unica-coder --lib bsl_analyzer_child_does_not_run_from_inside_the_workspace`
  — рабочий каталог дочернего процесса лежит вне рабочего пространства, в
  коротком приватном runtime-каталоге.
- `cargo test --package unica-coder --lib bsl_analyzer_runtime_directory_is_passed_to_the_child_and_fits_socket_budget`
  — тот же каталог продолжает удовлетворять бюджету `sun_path`.
