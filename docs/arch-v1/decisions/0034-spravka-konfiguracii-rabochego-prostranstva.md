# ADR-0034: Справка конфигурации рабочего пространства как корпус документации

- Статус: `accepted`
- Дата: `2026-08-10`
- Задача: https://github.com/IngvarConsulting/unica/issues/242

## Контекст

Прогон корпуса из ста запросов, выведенных из кода реальной конфигурации,
показал измеренный разрыв: доменные вопросы конфигурации — назначение
справочника, роль документа в учёте — не отвечает ни один подключённый
корпус (ноль из десяти), тогда как запросы о платформе закрываются почти
полностью. При этом выгрузка конфигурации уже несёт встроенную справку:
страницы `Ext/Help/<локаль>.html` рядом с каждым описанным объектом — ту же
раскладку пишет `unica.help.add`. На реальной конфигурации таких объектов
больше двух тысяч. ADR-0029 объявил реестр поставщиков документации
расширяемым, ADR-0032 добавил сетевые источники; локального источника о
самой конфигурации до этой записи не было.

## Решение

1. Реестр прирастает локальным поставщиком `configuration-help` с
   одноимённым корпусом. Смысл источника — новое значение
   `configuration-documentation` аргумента `sourceKinds`; авторитетность —
   вендор: страницы написал автор конфигурации.
2. Порядок реестра дополняет ADR-0032 п.8, специфичность убывает: справка
   самой конфигурации раньше справки платформы, локальные поставщики раньше
   сетевых, справка раньше стандартов.
3. Источник страниц — наборы исходников рабочего пространства (`source-set`
   настройки проекта или автообнаружение по `Configuration.xml`). Битая
   настройка проекта — отказ вызова, как и битая политика: неясность — отказ.
4. Локатор попадания — `configuration-help:<набор>:<путь страницы>`.
   Сегменты пути проверяются до обращения к диску: выход за корень набора
   исходников невозможен, чужой набор — отказ, пропавшая страница — отказ с
   её именем.
5. Локаль ответа — одна на корпус, как у справки установки: запрошенная,
   если хоть одна страница её несёт, иначе `ru`, иначе первая по алфавиту;
   секция называет ответившую локаль, страницы других локалей в выдачу не
   подмешиваются.
6. Применимая версия попадания — версия самой конфигурации из
   `Configuration.xml` набора исходников, а не версия платформы; без
   объявленной версии попадание честно несёт `unversioned`.
7. Поставщик локален: сети не требует, политика сетевого выхода его не
   ограничивает, кеша нет — источник правится тем же рабочим пространством,
   поэтому страницы читаются на вызов. Нечитаемая страница становится
   предупреждением секции, а не молчаливым пропуском.
8. Обход ищет страницы только в узаконенных выгрузкой местах — `Ext/Help`
   корня набора, объекта метаданных, формы и подсистемы, включая вложенные
   подсистемы, — и не спускается в остальное дерево: на реальной выгрузке
   это десятки тысяч каталогов модулей и макетов без справки, а страница вне
   узаконенного места — не страница справки.

## Неграницы

1. Решение не вводит полнотекстового индекса и ранжирования сложнее
   вхождения строки: заголовок дороже текста, порядок внутри ранга — путь.
2. Манифест `Help.xml` не разбирается: локаль определяется именем файла
   страницы, состав — обходом каталогов.
3. Справка внешних обработок и отчётов вне наборов исходников — неграница.

## Последствия

1. Доменные вопросы конфигурации получают локальный корпус — измеренный
   ноль закрывается содержимым самой выгрузки.
2. `sourceKinds` прирастает значением `configuration-documentation`, а
   `documentId` — форматом локатора `configuration-help:<набор>:<путь>`;
   ведомость инструментов перегенерирована.
3. Наполнение справки становится выгодным вдвойне: страница, добавленная
   `unica.help.add`, немедленно ищется `unica.documentation.search` в том же
   рабочем пространстве.

## Верификация

- `cargo test -p unica-coder configuration_help` — поиск по заголовку и
  тексту, локаль корпуса, версия конфигурации, предупреждения о нечитаемых
  страницах, получение по локатору, отказы на чужом наборе, сегментах пути и
  пропавшей странице.
- `cargo test -p unica-coder documentation_registry` — состав и порядок
  реестра из четырёх поставщиков; наборы исходников доезжают до поставщика
  автообнаружением по `Configuration.xml`.
- `python3.12 scripts/ci/generate-tool-surface.py --check` — синхронность
  ведомости с расширенными описаниями аргументов.
