# ADR-0072: Регистрация макетов и встроенная справка принадлежат `meta.edit`; `template.*` и `help.add` снимаются

- Статус: `accepted`
- Дата: `2026-08-17`
- Задача: [#375](https://github.com/IngvarConsulting/unica/issues/375)

## Контекст

`unica.template.add` и `unica.template.remove` — домен из двух глаголов
создания и удаления без чтения и редактирования. Ровно эту работу уже делает
`unica.meta.edit`: коллекция `templates` входит в его закрытый союз коллекций,
обработчик диспетчеризует вид макета и генерирует пустое содержимое, а
регистрация макета — работа владельца объекта. Наборы видов совпадают:
оба пути принимают пять значений (`HTMLDocument`, `TextDocument`,
`SpreadsheetDocument`, `BinaryData`, `DataCompositionSchema`). Пути создания
содержимого макета в публичной поверхности при этом три — та же дублирующая
развилка, которую волна убирает у форм.

`unica.help.add` — единственный глагол своего домена. Справка не является
коллекцией метаданных: она живёт в `Ext/Help/` как фасет объекта. Инструмент
приносит третий диалект селектора владельца: его `ObjectName` — не имя
объекта, а путь вида `Catalogs/МойСправочник` под `srcDir`. Развилка #375 —
растворить справку в `meta.edit` или дать ей собственные `info`/`edit` —
решается по заявленному в задаче умолчанию: растворение. Довод о богатстве
содержимого опирался на открытый тогда дефект HTML-страниц, закрытый в v0.12,
и собственных инструментов не оправдывает.

## Решение

1. `unica.template.add`, `unica.template.remove` и `unica.help.add` удаляются
   из `tools/list` и runtime без псевдонимов совместимости; вызов каждого
   отвечает `unknown unica tool`. Регистрацию и снятие регистрации макета
   выполняют операции `add` и `remove` `meta.edit` по коллекции `templates`.
2. Общий союз операций `meta.add`/`meta.edit` получает девятый вариант
   `{op: "addHelp", lang?}` — добавить владельцу встроенную справку. Семантика
   сегодняшнего `help.add` не меняется: создаются `Ext/Help.xml` и
   `Ext/Help/<язык>.html`, формам владельца добавляется
   `IncludeHelpInContents`; операция только создаёт, повтор — отказ. `lang`
   необязателен, по умолчанию `ru`, домен значений — прежний домен языков
   справки. Владелец адресуется `sourceSet + metadataPath`; третий диалект
   селектора исчезает вместе с инструментом.
3. Генерация содержимого макета получает одну точку входа: обработчик
   `template.rs` удаляется, эмиттеры остаются у своих доменов
   (пустой табличный документ — в `mxl.rs`), публичный маршрут — только
   `meta.edit`.
4. Скиллы `template-add`, `template-remove` и `help-add` снимаются вместе с
   инструментами; сценарии макета и справки ведут скиллы `meta-edit` и
   `meta-add`. Записи провенанса снятых скиллов уходят вместе с ними — индекс
   описывает только пакетные скиллы, а происхождение остаётся в истории
   репозитория.

## Неграницы

Решение не трогает `unica.mxl.*` и `unica.dcs.*` — содержимое макета мигрирует
своими срезами (#377, #378, #381); не меняет формат ни одного вида макета; не
меняет семантику справки — только адресацию и владельца маршрута.

## Последствия

- Публичная поверхность сокращается с 74 до 71 инструмента; исчезает третий
  диалект селектора владельца.
- Создание макета и справки становится операциями той же алгебры, которой
  агент уже владеет для реквизитов, форм и команд, — одной транзакцией с
  остальными изменениями объекта.
- Прямые вызывающие трёх снятых инструментов ломаются намеренно; таблица
  «снятый инструмент → операция `meta.edit`» живёт в README пакета и в
  заметках к релизу.

## Верификация

Контрактные тесты закрепляют союз из девяти вариантов и отказ снятых
маршрутов по образцу `retired_meta_routes_fail_as_unknown_tools`; тест
покрытия доказывает создание всех пяти видов макета через `meta.edit` и
паритет `addHelp` с прежним `help.add` на фикстуре с формой;
`test_tool_surface_ledger.py` и smoke-контур — опубликованную поверхность.
