# ADR-0051: Аргументы команды публикует тот инструмент, который её исполняет

- Статус: `accepted`
- Дата: `2026-08-11`
- Задача: [#318](https://github.com/IngvarConsulting/unica/issues/318)

## Контекст

Пять инструментов `unica.build.*` публикуют один общий список `BUILD_ARGS`.
Список собран по объединению, а не по тому, что читает конкретная команда,
поэтому он одновременно шире и уже нужного.

Уже: `v8-runner make` отказывает без `--output`, а экспорт cfe дополнительно
требует `--extension`. Внутренний маппер оба имени пробрасывает, но в
опубликованном списке их нет. Схема закрыта (`additionalProperties: false`),
значит передать `output` нельзя ни при каком вызове, и `unica.build.make` не
может выполнить свою единственную задачу.

Шире: тот же список несёт `unica.build.make` аргументы, которых её команда не
принимает.

ADR-0048 закрыл этот вопрос для восьми типизированных читателей: публичный
набор аргументов называет только то, что читает обработчик. Для `unica.build.*`
правило не было выведено, и общий список остался.

## Решение

1. Публичный набор аргументов инструмента `unica.build.*` называет то, что
   принимает исполняемая им команда. Общий список — база, а не контракт: имя,
   принимаемое только одной командой, публикует только она.
2. Аргумент, без которого команда отказывает, объявляется обязательным в схеме.
   Отказ на границе схемы наступает раньше и называет причину точнее, чем отказ
   внутри адаптера после запуска.
3. `unica.build.make` публикует `output` — обязательным — и `extension`.
   Остальные четыре команды их не публикуют.
4. Описание инструмента называет источник данных и работающий маршрут. Ссылка
   на инструмент, которого нет в реестре, — дефект: вызывающий, следующий
   описанию буквально, получает неизвестный инструмент.

## Неграницы

1. Решение не сужает остальные имена `BUILD_ARGS` до их команд. Это отдельная
   работа, пересекающаяся с #315.
2. Решение не меняет поведение адаптера: он оба имени пробрасывал и раньше.
3. Решение не переводит `unica.build.*` на логическую адресацию.

## Последствия

1. `unica.build.make` становится вызываемым через MCP. До этого решения
   собрать артефакт через публичную поверхность было нельзя.
2. Вызов `make` без `output` теперь отвергается схемой, а не адаптером. Это
   изменение наблюдаемого поведения: раньше отказ приходил позже и с другим
   текстом.
3. Публикация имени только у одной команды из пяти делает `BUILD_ARGS`
   неполным описанием любой из них. Читатель ведомости обязан смотреть на
   инструмент, а не на общий список.

## Верификация

- `cargo test --package unica-coder --lib build_make_publishes_the_arguments_its_command_requires`
  — `output` и `extension` опубликованы, `output` обязателен, документированный
  вызов принимается валидацией.
- `cargo test --package unica-coder --lib build_make_description_says_the_artifact_comes_out_of_the_infobase`
  — описание называет информационную базу и не ссылается на инструмент, которого
  нет в реестре.
- `python3 -m unittest discover -s tests/ci` — `test_ledger_matches_the_live_registry`
  удерживает соответствие ведомости живому реестру.
