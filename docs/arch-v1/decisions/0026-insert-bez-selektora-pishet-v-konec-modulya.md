# ADR-0026: `insert` без селектора пишет в конец модуля

- Статус: `accepted`
- Дата: `2026-08-07`
- Задача: #295

## Контекст

`unica.meta.add` законно создаёт объект в канонической раскладке Platform XML, но
BSL-файл его модуля может содержать только маркер порядка байтов. Существующие
операции `unica.code.patch` адресуются селектором — методом или якорем внутри
метода, — поэтому в модуле без единого метода выбрать нечего, и первое тело
записать нельзя.

Пустой модуль при этом не состояние предметной области, а артефакт выгрузки:
платформа просто не пишет `*.bsl` для пустых объектных и менеджерских модулей.
Замер на выгрузке 8.3.27 из 12290 BSL-файлов: 782 файла состоят из одного
маркера порядка байтов, а свыше тысячи модулей отсутствуют как файлы. Отдельная
операция под «пустой модуль» закрепила бы артефакт хранения в публичном
контракте и покрыла бы при этом меньшую часть случая.

## Решение

1. Аргумент `selector` инструмента `unica.code.patch` необязателен для операции
   `insert`. Отсутствие селектора означает единственное место, которое есть у
   любого модуля, — его конец.
2. Без селектора `position` не принимается: позиционировать не относительно
   чего. С селектором `position` по-прежнему обязателен.
3. Модуль без единого метода не является особым случаем. Его текст пуст, поэтому
   смещение равно нулю, разделитель не нужен, и тело пишется общим путём.
   Маркер порядка байтов содержимым не считается и сохраняется.
4. Повтор вызова без селектора до записи распознаётся как семантически пустой:
   конец модуля адресуется и после записи, а совпадение проверяется теми же
   байтами, что и для селекторной вставки.
5. Адрес модуля, файла которого нет, резолвится под отдельной политикой
   `ModuleOnlyAllowingAbsent`. Её просит только пишущий маршрут; чтение
   по-прежнему отказывает на отсутствующем модуле. Политика запоминается
   вместе с закрытым описателем цели, поэтому повторная проверка воспроизводит
   то же решение и цель не может ни приобрести, ни потерять эту терпимость.
6. Недостающий `*.bsl` создаётся только при применении записи и только когда
   роль допустима для вида по реестру `supports_direct_module_role`, а
   дескриптор владельца на месте. Предпросмотр файл не создаёт. Создание идёт
   через `create_bytes`, поэтому появившийся тем временем файл не затирается,
   а существующий модуль по-прежнему правится с проверкой точного преобраза.
7. Операция `initialize` не вводится.

## Неграницы

1. Решение не создаёт объект метаданных и не разрешает запись по физическому
   пути: материализуется только файл модуля у уже существующего объекта, чей
   дескриптор доказан.
2. Решение не вводит пакетную правку, произвольную замену модуля или обход
   стража поддержки.

## Последствия

1. Сценарий первого текста модуля получает MCP-first маршрут без новой операции
   на публичной поверхности.
2. Попутно закрывается обычная потребность «добавить метод в модуль», не называя
   соседа: раньше она требовала выдумать селектор.
3. Идемпотентность единообразна: все операции `unica.code.patch` доказывают
   семантическую пустоту повтора до записи, ни одна не отказывает после
   успешного применения.
4. Закрывается обе половины артефакта выгрузки: и модуль из одного маркера
   порядка байтов, и модуль, которого платформа не выгрузила вовсе. Реестр
   ролей при этом отделяет «пустой не выгружен» от «такой роли у вида нет»:
   у `Enum` и `DocumentJournal` объектного модуля не бывает, и адрес остаётся
   недостижимым.

## Верификация

- `cargo test -p unica-coder code_patch_without_a_selector_appends_to_the_end_and_proves_the_repeat -- --test-threads=1` — проверяет вставку в конец и семантически пустой повтор.
- `cargo test -p unica-coder code_patch_writes_the_first_body_of_an_empty_or_bom_only_module -- --test-threads=1` — проверяет пустой и BOM-only модуль, сохранение маркера и отсутствие лишнего разделителя.
- `cargo test -p unica-coder code_patch_schema_accepts_each_documented_selector_variant -- --test-threads=1` — проверяет опубликованную схему без селектора и отказ от `position` без него.
- `cargo test -p unica-coder direct_module_roles_match_the_platform_rather_than_the_filesystem -- --test-threads=1` — закрепляет реестр ролей модулей за платформой, а не за файловой системой.
- `cargo test -p unica-coder code_patch_creates_a_module_file_the_platform_never_exported -- --test-threads=1` — проверяет создание недостающего файла при применении и его отсутствие после предпросмотра.
- `cargo test -p unica-coder code_patch_refuses_a_module_role_the_metadata_kind_never_owns -- --test-threads=1` — проверяет, что недопустимая для вида роль остаётся недостижимой.
