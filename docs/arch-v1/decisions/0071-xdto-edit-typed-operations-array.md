# ADR-0071: `unica.xdto.edit` принимает типизированный массив операций одной транзакцией

- Статус: `accepted`
- Дата: `2026-08-17`
- Задача: [#374](https://github.com/IngvarConsulting/unica/issues/374)

## Контекст

ADR-0024 дал домену XDTO логический селектор `sourceSet + metadataPath` и
валидацию в предпросмотре, но форму полезной нагрузки оставил как есть:
`unica.xdto.edit` принимает `operation` в единственном числе — строку из
закрытого набора из пяти значений — и пять плоских сопутствующих аргументов
`base`, `name`, `property`, `propertyPath`, `typeName`. Обязательность каждого
зависит от значения `operation`: схема выражала это топ-уровневым `oneOf` из
пяти ветвей с `not`-запретами посторонних полей.

ADR-0025 §4 запретил ровно такую форму для `meta.edit`: хост, показывающий
модели только `properties`, видит у инструмента шесть независимых
необязательных строк вместо пяти предметных операций, а условная
обязательность остаётся знанием валидатора. Кроме того, одна операция за вызов
лишает связное изменение транзакции: «добавить тип и три его свойства» — это
четыре вызова с четырьмя публикациями, тогда как `meta.edit` публикует такую
последовательность одной.

Домен узкий, адресация в нём уже логическая, поэтому он дешевле всех проверяет
переносимость алгебры операций ADR-0025 за пределы `meta` — первый срез волны
адресации v0.13 (план #517, фаза 2).

## Решение

1. `unica.xdto.edit` принимает непустой упорядоченный массив `operations`.
   Предметный топ-уровень схемы — `sourceSet`, `metadataPath`, `operations` и
   мутаторный `dryRun`; общие для нативных инструментов `cwd`/`confirm`
   остаются как у всего класса, их судьба — общий вопрос бюджета схем, не
   этого решения. `required = ["sourceSet", "metadataPath", "operations"]`.
   Аргументы `operation`, `base`, `name`, `property`, `propertyPath`,
   `typeName` с топ-уровня удаляются; топ-уровневый `oneOf` удаляется.
2. Публичная схема представляет виды операций закрытым размеченным
   объединением непосредственно в `properties.operations.items.oneOf` — по
   правилу ADR-0025 §4, без `allOf`/`if`/`then`/`$ref`. Тег варианта — `op`,
   значения в стиле `camelCase`, согласованном с `meta.edit`; каждый вариант
   закрыт (`additionalProperties: false`) и называет свои обязательные поля:

   | `op` | Обязательные поля | Прежняя форма |
   | --- | --- | --- |
   | `addValueType` | `name`, `base` | `operation: add-value-type` |
   | `addObjectType` | `name` | `operation: add-object-type` |
   | `addProperty` | `typeName`, `property`; необязательный `propertyPath` | `operation: add-property` |
   | `removeType` | `name` | `operation: remove-type` |
   | `removeProperty` | `typeName`, `name`; необязательный `propertyPath` | `operation: remove-property` |

   Семантика каждой операции не меняется: поля варианта — это в точности
   аргументы, которые писатель пакета читал до этого решения.
3. Операции одного вызова применяются по порядку и видят результаты
   предыдущих: план операции `i` строится по тексту пакета после операции
   `i-1`. Публикация одна на вызов; отказ любой операции не оставляет
   частичной записи. Неявного «добавить с обновлением» нет: семантика дублей
   у операций не меняется — точный повтор существующего добавления остаётся
   `no-op` с информационной находкой, а дубль с иной формой остаётся отказом
   той операции, которая его вносит.
4. Результат несёт один эффект на входную операцию: `data.effects[]` с
   `operationIndex`, `op`, `noOp`, проекцией изменения и находками шага;
   `data.noOp` истинен, когда каждая операция — `no-op`. Ошибка, относящаяся к
   элементу массива, называет его как `operations[<индекс>]`. Байтовые
   диапазоны проекции каждого эффекта относятся к состоянию документа на
   момент применения этой операции.
5. Вызов в старой форме — с любым из снятых топ-уровневых аргументов —
   отказывает до диспетчеризации стабильным кодом
   `legacy_arguments_removed`, называющим `operations`. Псевдонимов
   совместимости нет.

## Неграницы

Решение не трогает `unica.xdto.info`, адресацию домена (ADR-0024 остаётся его
владельцем и не заменяется), формат `Package.bin` (#279) и corpus-верификатор
(#358). Набор из пяти видов операций не расширяется.

## Последствия

- Связное изменение пакета — тип плюс его свойства — становится одним вызовом
  с одной публикацией и одним предпросмотром.
- Форма контракта `xdto.edit` совпадает по устройству с `meta.edit` и задаёт
  образец для следующих срезов волны (`dcs`, `role`, `subsystem`, `mxl`).
- Прямые вызывающие старой формы ломаются намеренно; таблица
  «старое поле → новый элемент `operations`» живёт в README пакета и в
  заметках к релизу.

## Верификация

Контрактные тесты `tool_contracts.rs` закрепляют состав топ-уровня, форму
объединения и отказ старой формы; тесты обработчика — порядок применения,
единую публикацию и `operationIndex`; `tests/ci/test_tool_surface_ledger.py` и
smoke-контур — опубликованную поверхность.
