# Исследование — не тест: проводится один раз и в конвейер не попадает

**Решение.** Работа, доказывающая свойство, которое не меняется от правок
кода, — `research`, имя в одном ряду с размерами тестов, но вне конвейера. Её
проводят один раз по записанному методу — вопрос, входы, версии, команда, —
результат закрепляют артефактом в дереве и записью в реестре, а страж того,
что закреплённое на месте, остаётся обычным `small`-тестом. Код исследования
живёт целью, которая собирается только с фичей `research`, запуск — обёрткой
из `scripts/research/`; `#[ignore]` для этого не годится.

**Что чинит.** Три исследования жили в наборе тестов под `#[ignore]` —
снимок дерева `cf init`, корпус XML публичного инструмента, регенерация
каталога событий платформы. Они стояли в плане каждого прогона, попадали в
отчёт отключёнными и держали выключатель там, где нужен инструмент.

**Чем держится.** Цель с `required-features` не собирается без фичи, и ни
`nextest list`, ни ворота конвейера её не видят; обёртка записывает метод,
чтобы повторить исследование намеренно, а не случайно. Сверка с донором и
корпус 8.3.27 уже шли этим путём.

**Цена.** Помощники исследований остаются в тестовых файлах и видны им как
`pub(crate)`; переезд помощников в общий модуль — отдельная работа, если
исследований прибавится.
