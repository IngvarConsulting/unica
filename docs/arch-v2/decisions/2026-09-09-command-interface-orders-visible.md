# Порядок в командном интерфейсе виден, потому что его собираются писать

**Решение.** Узел командного интерфейса подсистемы объявляет три ветви:
`Command` — команды с видимостью и размещением, `Group` — группы панели в
объявленном порядке, `Subsystem` — дочерние подсистемы в порядке интерфейса.
Внутри группы лежат её команды в порядке `CommandsOrder`. Ссылка платформы в
порядке подсистем дополняется до адреса, по которому можно спуститься.

Заведён вид узла `Group`. Это группа панели — место, куда платформа кладёт
команду, — а не объект метаданных `CommandGroup`: последний может такую группу
завести, но группой не является.

**Что чинит.** Файл несёт пять секций, наружу выходили три. `CommandsOrder`
разбирался и в проекцию не попадал, `GroupsOrder` и `SubsystemsOrder`
подсистемы не разбирались вовсе. Правка порядка была невыразима: писать то,
чего инструмент не показывает, нельзя ни при каком устройстве писателя.

**Чем держится.** Три независимые причины, и хватило бы любой. Предпросмотр
`apply` показывает читателю правку, а правку невидимого факта показать нечем.
Забор ревизии сужается до прочитанного и записанного, и факт, которого чтение
не касается, в набор прочитанного не попадёт — забор над ним несостоятелен без
единого признака. Наконец, свёртка видимости до `Common` теряет значения по
ролям, и писатель, переписывающий элемент по прочитанному, снёс бы их молча;
пока запись не заведена, это цена ошибки, а не сама ошибка.

**Цена.** Порядок — последовательность, а `props` держат только ограниченные
скаляры, поэтому порядок лёг ветвями. Ветвь честно объявляет длину, значит
группы приходится перечислять при структурном чтении узла — обход секции
`GroupsOrder`, дешёвый рядом с чтением самого документа. Группа без единой
команды остаётся видимой: порядок объявляется отдельно от наполнения, и
скрывать пустую группу значило бы врать о составе панели.

Пятая секция — `CommandsVisibility` со значениями по ролям — по-прежнему
свёрнута до `Common`. Это осознанный остаток, названный в проекте отдельным
шагом: он меняет форму ответа и приходит со своим решением.
