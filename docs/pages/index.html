Установка

  1. Что понадобится

    • Агент. Codex или Claude Code с действующей подпиской. Unica подключается к нему как плагин.
    • Git. Через него ставится плагин. На Windows подойдёт Git for Windows.
    • Выгрузка конфигурации в файлы. Unica работает с каталогом, в который конфигуратор 8.3.27 выгрузил конфигурацию или расширение, а не с базой напрямую. Если выгрузки ещё нет, Unica сделает её сама из вашей базы: для этого нужна установленная платформа.
    • Платформа 1С только для запуска. Читать, проверять и править выгрузку можно без установленной платформы. Она нужна операциям, которые собирают базу или запускают конфигуратор.

    Работает на Windows, macOS и Linux. Ядро и движки докачиваются при первом запуске; что именно и откуда, описано в разделе «Сеть и данные».

  2. Поставить плагин

    Codex и Claude Code ставятся из одного маркетплейса.

    codex plugin marketplace add IngvarConsulting/unica-marketplace --ref main
codex plugin add unica@unica
    claude plugin marketplace add IngvarConsulting/unica-marketplace
claude plugin install unica@unica

    После установки начните новую сессию агента или выполните в нём /reload-plugins.

  3. Первый запрос

    Откройте агента в каталоге проекта и попросите подключить его. Дальше разговор идёт словами разработчика, а Unica отвечает планом до каждой записи.

    Подключи проект и покажи, что в нём есть
    Агент с Unica

    Нашёл выгрузку конфигуратора в каталоге src. Файла проекта ещё нет, план такой:

    • создать v8project.yaml с набором main, тип CONFIGURATION, путь src

Поддерживаемые версии платформы

Версия платформы задаёт формат выгрузки, а Unica читает и пишет ровно один формат. Каждая лишняя ветка это ещё один формат, который нужно держать в тестах, поэтому старые версии не поддерживаем намеренно: актуальные типовые конфигурации уже вышли на 8.3.27 и выше.

8.3.27.x2.20Поддержали

С чего начать

Порядок для того, кто хочет вносить вклад: сначала что Unica делает, потом как она устроена, потом по каким правилам её меняют.

  1. Что умеет

    Каталог задач разработчика, которые Unica проходит цепочкой вызовов. Тот же список гоняет приёмочный тест, поэтому в нём нет ничего, что не работает.
  2. Архитектура

    Кто приходит по MCP, две поверхности инструментов, тонкий процесс и демон, движки под ними.
  3. github.com/IngvarConsulting/unica/CONTRIBUTING.md

    Окружение: Python 3.12, Rust, rust-analyzer для кодового агента и навыки для Codex и Claude Code.
  4. github.com/IngvarConsulting/unica/AGENTS.md

    Порядок источников истины, куда смотреть и где менять, правила разработки и топология pull request.
  5. github.com/IngvarConsulting/unica/arch/

    Нормативный слой: решения, инварианты и контракты, одна запись — один файл. На них ссылаются тесты, поэтому спор о правиле решается здесь.
