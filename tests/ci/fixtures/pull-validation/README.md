# Проверка отказов полной выгрузки

Профиль `runtime-fault` исполняет пять сценариев S-1869 через стандартный
бинарь Unica. Он проверяет типизированный invalid_result, сохранность прежних
исходников, отдельную причину cleanup и доступный recovery. Управляемый
provider пишет только принадлежащий попытке stage; платформа не выполняет
его выгрузку. Настоящая локальная установка 8.3.27 нужна для обычной аттестации
платформы: обходов доверия и тестовых ветвей в продуктовом бинаре нет.

Запуск из корня репозитория:

```sh
UNICA_ACCEPTANCE_PLATFORM_ROOT=/opt/1cv8/8.3.27.2214 \
  python3.12 -m tests.ci.acceptance_pull_validation
```

Подготовка бинаря следует стандартному `scripts/ci/prepared_binary.py`.
Отсутствующая платформа или неподдерживаемый host завершают запуск ошибкой.
Управляемый Python provider сейчас исполняется на POSIX; Windows явно
отклоняется. Это локальный runtime-профиль, обычный Python CI проверяет его
регистрацию и закрытость без запуска платформы.

`producer.py` реализует только минимальный протокол публикации runner 0.15.2;
это не опубликованный v8-runner. Манифест помечен publishedArtifact=false и
содержит SHA исходника и исполняемого файла. Owner seed — буквальные байты
независимой native empty_configuration 8.3.27. Повреждённый XML, неизвестный
корень и остальные отказы намеренно создаёт controlled provider.
