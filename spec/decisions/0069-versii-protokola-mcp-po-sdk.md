# ADR-0069: Версии протокола MCP обслуживаются по документации SDK, гарантируются по матрице хостов

- Статус: `accepted`
- Дата: `2026-08-17`
- Задача: [#490](https://github.com/IngvarConsulting/unica/issues/490)

## Контекст

Гейт 2026-08-17 показал: ни один заявленный хост не говорит `2026-07-28`.
Claude Code 2.1.220/2.1.233 открывается legacy `initialize` с максимумом
`2025-11-25` и на `-32601` рвёт соединение, не пробуя `server/discover`.
Codex 0.148.0-alpha.9 всегда предлагает `2025-06-18`, принимает любую
непустую строку выбора сервера (матрица 38 сценариев, включая `banana`),
остаётся в legacy lifecycle даже при выборе `2026-07-28`, а ошибка на
`initialize` для него фатальна — fallback и discover отсутствуют. В
TypeScript SDK (npm latest 1.30.0) ревизии `2026-07-28` нет вовсе; из
клиентских SDK её несёт rmcp 3.x, чей Auto-режим открывается discover-first.

Прежние постановки #490 — «только 2026-07-28», затем «ровно два контракта с
exact-allowlist» — были исследовательскими ограничениями. Сверка rmcp 3.1.2
по исходникам показала, что SDK уже реализует всё нужное: гибридный
admission (`initialize` либо direct-first запрос с полным modern `_meta`,
частичный набор отклоняется до handler-а), negotiation «эхо известной версии,
иначе fallback из ответа handler-а», `-32022` со списком поддерживаемых
версий, версионное кодирование (`resultType` срезается для пиров старше
`2026-07-28`) и дефолтную реализацию `server/discover` из `get_info()`.
Собственная version-политика поверх SDK означала бы борьбу с транспортом,
которым по ADR-0013 владеет SDK.

## Решение

1. **Обслуживается всё, что знает SDK.** `supported_protocol_versions`
   остаётся дефолтом (`KNOWN_VERSIONS`); согласование версии, допуск первого
   запроса, `server/discover` и версионное кодирование — штатные механизмы
   `rmcp` без надстроек. Расширение обслуживаемого набора приходит подъёмом
   версии SDK и отдельного решения не требует. Ветвлений по хосту и имён
   хостов в `coder`-модуле нет.
2. **Гарантируются три версии**: `2025-06-18` (родная версия Codex),
   `2025-11-25` (Claude Code), `2026-07-28` (эталонный клиент: прямой первый
   запрос и `server/discover`). Гарантия означает проводную матрицу в тестах,
   верификацию обоих жизненных циклов при запуске и красную приёмку при
   красном статусе любой из трёх. Изменение состава гарантий — отдельное
   решение.
3. **Запасная версия согласования закрепляется явно** на `V_2025_11_25` в
   `InitializeResult`: подъём версии SDK, двигающий
   `ProtocolVersion::LATEST`, не вправе молча сменить ответ сервера на
   неизвестное предложение.
4. **Политика курсора**: `nextCursor` не выдаётся; предъявленный `cursor`
   — `Invalid params`, а не пустая страница.
5. **Кешируемый результат — только `server/discover`** (поля `ttlMs` и
   `cacheScope` обязательны в `DiscoverResult` и приходят из SDK);
   `tools/list` кешируемым не объявляется.
6. **Семантика SDK для смешанных случаев фиксируется как есть, без
   гарантий**: предложение `2026-07-28` через `initialize` SDK эхом
   принимает (сессионная модель с современным кодированием); запрос с полным
   современным `_meta` внутри `initialize`-сессии получает современно
   кодированный ответ, не переключая сессию. Оба пути существуют, не
   запрещаются и не входят в гарантируемую матрицу.

## Поправка ADR-0013

ADR-0013 остаётся действующей с одной поправкой: её «изменение контракта» №2
(«первым запросом обязан быть корректный `initialize`») снято — admission
расширил сам SDK, и direct-first запрос с полным modern `_meta` теперь
легальный opener. Следствие №5 ADR-0013 («переход на новую ревизию протокола
становится подъёмом версии SDK») этим решением подтверждено и возведено в
правило уровня 1. Владение транспортом, граница `interfaces/mcp.rs`,
ограниченный допуск и кооперативная отмена действуют без изменений.

## Верификация

- [x] Wire-матрица в `crates/unica-coder/src/interfaces/mcp.rs`: эхо
  `2025-11-25` и `2025-06-18`; fallback неизвестного предложения на
  `2025-11-25`; legacy-ответы без `resultType`; direct-first
  `server/discover` и `tools/list` с обязательным modern `_meta`;
  `resultType: "complete"` в modern-ответах; отказ admission на частичный
  modern-набор; `-32022` со списком supported; отказ по cursor; modern
  `_meta` внутри legacy-сессии — semantics SDK.
- [x] `crates/unica-bootstrap/src/verification.rs` проверяет оба lifecycle
  свежими процессами: legacy `initialize(2025-06-18)` → `tools/list` и
  modern `server/discover` → `tools/list`; discover обязан перечислить все
  три гарантируемые версии
  (`crates/unica-bootstrap/tests/platform/verification_contract.rs`).
- [x] `cargo tree` — одна версия rmcp (3.1.2).
