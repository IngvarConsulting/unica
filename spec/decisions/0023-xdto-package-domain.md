# ADR-0023: Домен XDTO правит пакет по логическому адресу

- Статус: `accepted`
- Дата: `2026-08-01`
- Задача: [#279](https://github.com/IngvarConsulting/unica/issues/279)

## Контекст

Пакет EnterpriseData хранит свою схему в ресурсе
`XDTOPackages/<Имя>/Ext/Package.bin`. Ручная правка этого XML выводит изменение
за MCP-границу и заставляет вызывающего знать физическую раскладку выгрузки.

## Решение

1. Домен публикует `unica.xdto.info` для чтения и `unica.xdto.edit` для
   мутации; отдельный инструмент валидации не вводится.
2. Оба инструмента принимают обязательные `sourceSet` и `metadataPath` вида
   `XDTOPackage.<Имя>`; физический путь к ресурсу не является публичным
   аргументом.
3. `unica.xdto.edit` по умолчанию выполняет предпросмотр и проверяет
   результирующий XML до публикации. В v1 доступны `add-value-type`,
   `add-object-type`, `add-property`, `remove-type` и `remove-property`.
4. Записыватель изменяет только выбранный ресурс, сохраняет маркер порядка
   байтов и наблюдённый стиль перевода строки, а публикацию выполняет атомарно.

## Неграницы

Домен не создаёт объект метаданных `XDTOPackage`, не меняет его дескриптор или
`targetNamespace` и не делает внутренние типы адресами метаданных.

## Последствия

Работа с EnterpriseData остаётся MCP-first, а вложенный `typeDef` выбирается
отдельным `propertyPath`, не расширяя модель `MetadataAddress`.

## Верификация

- `cargo test -p unica-coder xdto -- --test-threads=1` проверяет операции,
  no-op и сохранение текстового ресурса.
- `tests/ci/test_unica_skills.py` проверяет видимую MCP-маршрутизацию скилла.
