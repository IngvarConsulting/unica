# ADR-0059: Миграция читателя выбирает мост или прямое переключение явно

- Статус: `accepted`
- Дата: `2026-08-13`

## Контекст

ADR-0049 разделяет приобретение логического селектора и снятие физического пути
на два изменения. Это безопасное умолчание для читателя, чей результат не
меняется: сначала можно доказать эквивалентность двух входов, затем отдельно
снять старый.

У `unica.code.diagnostics` физическая модель находится не только во входе, но и
в каждой находке. Сохранение прежнего результата на первом шаге оставляет
агенту ту же задачу обратного угадывания объекта, а одновременная публикация
физической и логической идентичности создаёт две конкурирующие ручки. Для такого
контракта прямое переключение является отдельным осознанным классом миграции, а
не случайным нарушением общего правила.

Происхождение выбора записано в
[проектной записке](../../docs/design/2026-08-12-logical-provider-neutral-diagnostics-design.md).

## Решение

1. Предметный читатель явно выбирает один из двух режимов миграции:
   `bridge` или `directSwitch`. Необъявленного третьего режима нет.
2. `bridge` остаётся режимом по умолчанию. Читатель сначала добавляет логический
   селектор рядом с прежним, требует ровно один из них и доказывает одинаковый
   ответ; снятие пути выполняется следующим самостоятельно проверяемым
   изменением.
3. `directSwitch` разрешается только новой записью решения, которая называет
   один точный публичный инструмент и объясняет, почему мост создаёт две
   идентичности или сохраняет непригодный результат. Сам факт удобства или
   стоимость двух запросов на слияние основанием не являются.
4. Прямое переключение в одном изменении правит схему, обработчик, скилл,
   примеры, ведомость поверхности, миграционную таблицу, заметки к релизу и
   исполняемые проверки. Старый селектор не остаётся скрытым вторым маршрутом.
5. У `unica.code.diagnostics` снятые `mode`, `sourceDir` и `path` распознаются
   до обычной ошибки неизвестного аргумента и возвращают стабильный
   `legacy_target_removed` с канонической заменой; `config`, `format`, `detail`,
   `maxFiles`, `rangeStart` и `rangeEnd` снимаются без публичной замены.
6. Оба режима используют общий резолвер `SourceTarget` и явную политику вида
   цели. Они не создают собственного профиля адресов и не выводят объект из
   имени файла.
7. `unica.code.diagnostics` использует `directSwitch` по ADR-0057: старые
   селекторы и физические местоположения заменяются одним логическим контрактом.
8. Для остальных предметных читателей продолжает действовать `bridge`, пока их
   собственное решение не объявит и не обоснует иное.

После принятия эта запись заменяет ADR-0049. Правила идентичности адреса и
поинструментного снятия старого контракта остаются у ADR-0021.

## Неграницы

1. Решение не разрешает групповое снятие путей у нескольких инструментов.
2. Решение не меняет одношаговую миграцию мутирующих операций по ADR-0021.
3. Решение не назначает срок снятия мостов и не делает прямое переключение
   предпочтительным.
4. Решение не меняет грамматику `MetadataAddress`.

## Последствия

1. Обычный читатель сохраняет доказуемый двухшаговый переход.
2. Исключение становится узким, именованным и проверяемым, а не прецедентом для
   произвольного ломающего изменения.
3. Будущее изменение политики миграции заменяет одну эту запись и не требует
   пересматривать контракт diagnostics.

## Верификация

- `cargo test -p unica-coder bridged_readers -- --test-threads=1` проверяет
  сохранённый режим `bridge` и конфликт двух селекторов.
- `cargo test -p unica-coder diagnostics_legacy_target_removed --lib` проверяет
  прямое снятие старых полей diagnostics при их отсутствии в live-схеме.
- `tests/ci/test_architecture_registry.py` проверяет владельца каждого режима и
  связь миграционного решения с публичным инструментом.
