# ADR-0055: Поддерживаемая Platform XML конфигурация собирается полным runtime-путём

- Статус: `accepted`
- Дата: `2026-08-13`
- Задача: [#404](https://github.com/IngvarConsulting/unica/issues/404)

## Контекст

`v8-runner` выбирает частичную загрузку по собственному снимку изменений.
Точечное изменение формы или её модуля может образовать корректный файловый
список для `-partial`, но Конфигуратор отклоняет такую загрузку, когда объект
принадлежит конфигурации поставщика и правила поддержки не разрешают операцию.
Пользователь получает позднюю ошибку платформы, хотя повторный запуск с
`--full-rebuild` успешно загружает тот же набор исходников.

Состояние поддержки Platform XML уже доступно через доменный
`SupportStateReader` по ADR-0054. При этом снимком изменений и частным
хранилищем хешей владеет `v8-runner`: чтение этого хранилища из Unica нарушило
бы ADR-0003, а повторение алгоритма определения изменённых файлов создало бы
двух владельцев одной истины.

`unica.runtime.execute` и `unica.runtime.job.start` независимо отображают
типизированные аргументы в команду поставщика. Решение о безопасном режиме
сборки должно приниматься до обоих отображений, иначе показываемая команда,
синхронный процесс и сохранённый запрос задания могут разойтись.

Текущий reader состояния поддержки разрешает наборы только из основного
`<workspaceRoot>/v8project.yaml`. Другой файл, переданный через `config`, может
описывать иные наборы и корни исходников, поэтому этот reader не может
достоверно отвечать за него.

## Решение

1. Операция `build` обоих публичных runtime-входов проходит общую предпроверку
   до отображения аргументов и запуска `v8-runner`. Предпроверка возвращает одну
   нормализованную копию аргументов и предупреждения; из этой копии строятся и
   показываемая, и исполняемая команды, а `runtime.job.start` сохраняет её
   исполняемые аргументы в запросе задания.
2. Явный `fullRebuild: true` сразу выбирает полный путь и не требует чтения
   состояния поддержки. Для неявного либо ложного `fullRebuild` предпроверка
   разрешает эффективный `config`; инкрементальная сборка допускается только
   для основного `v8project.yaml` рабочего пространства. Другой файл
   конфигурации
   отклоняется до запуска с указанием повторить вызов с
   `fullRebuild: true`.
3. При указанном `sourceSet` предпроверка обрезает окружающие пробелы так же, как
   `v8-runner`, требует разрешить ровно один набор с таким именем и сохраняет в
   нормализованных аргументах каноническое имя; без селектора рассматриваются
   все наборы проекта. Режим сборки определяется глобальным `format` так же, как
   в `v8-runner`: только явный `EDT` идёт по EDT-пути, а отсутствие значения
   означает режим Конфигуратора. В режиме Конфигуратора недоказанный,
   EDT-подобный или противоречивый физический формат выбранного
   `CONFIGURATION` завершает предпроверку отказом; в EDT-режиме состояние
   поддержки Конфигуратора не читается.
   Для `CONFIGURATION` с доказанным форматом платформенного XML каждый набор
   представляется логической целью `ResolvedTarget` вида `SourceRoot` и
   передаётся в `SupportStateReader::configuration_support`; физический файл
   состояния не читается runtime-адаптером напрямую.
4. Если хотя бы одна выбранная конфигурация имеет состояние `Supported`,
   нормализованные аргументы получают `fullRebuild: true`. Публичный результат
   предупреждает, какие наборы перевели сборку на полный путь. Состояния
   `NotSupported` и `Removed` сами по себе режим не меняют. Состояние `Extension`
   для цели, уже доказанной как `CONFIGURATION`, считается противоречивым
   свидетельством и завершает предпроверку отказом.
5. Ошибка чтения карты проекта или состояния поддержки, включая нечитаемое или
   повреждённое свидетельство, завершает предпроверку до запуска поставщика.
   Отказ называет причину и предлагает явный `fullRebuild: true`, а не выдаёт
   отсутствие доказательства за разрешение частичной загрузки.
6. Предпроверка не читает частное хранилище, снимок хешей или список изменений
   `v8-runner` и не пытается вывести поддержку конкретного изменённого объекта.
   Граница Unica принимает только консервативное решение по доказанному
   состоянию всей выбранной конфигурации.
7. Разрешение оставить инкрементальный режим переносится в запрос фонового
   обработчика как типизированное описание и повторно проверяется перед
   фактическим запуском `v8-runner`. Если состояние поддержки или идентичность
   рабочего пространства изменились, процесс не запускается, а результат
   требует повторного вызова с `fullRebuild: true`.
8. Отмена после файловой предпроверки проверяется перед запуском процесса и
   перед постановкой долговременного задания в очередь. Отмена между постановкой
   в очередь и запуском фонового обработчика завершает запись как `Cancelled` и
   освобождает блокировку активного задания.

## Неграницы

1. Решение не добавляет reader состояния поддержки для EDT и не читает
   порождённое Designer-дерево из рабочего каталога `v8-runner`.
2. Решение не меняет `unica.build.load`: этот унаследованный вход использует
   отдельный `CliAdapter` и не входит в общую предпроверку семейства
   `unica.runtime.*`.
3. Решение не меняет алгоритм частичной загрузки, формат частного состояния или
   исполняемый файл `v8-runner` и не добавляет повторную попытку после уже
   запущенной команды платформы.
4. Решение не добавляет публичный аргумент, инструмент или поле результата.
   `fullRebuild`, `warnings` и оба runtime-входа сохраняют существующий
   контракт.
5. Решение не обещает оптимальный режим для каждого поддерживаемого объекта:
   активно поддерживаемая конфигурация выбирает полный путь даже тогда, когда
   конкретное изменение могло бы пройти частично.

## Последствия

1. Поддерживаемая Platform XML конфигурация не доходит до заведомо
   недоказанного частичного вызова Конфигуратора через публичные runtime-входы.
2. Предпросмотр, синхронный запуск и долговременное задание сообщают и исполняют
   один режим сборки.
3. Консервативный полный путь может быть медленнее допустимой частичной загрузки,
   но не требует вторжения в состояние поставщика или дублирования его анализа
   изменений.
4. Для альтернативного project config вызывающая сторона обязана явно выбрать
   полный rebuild, пока для такого config не появится собственная доказанная
   привязка логических целей к reader-у поддержки.
5. Нечитаемое свидетельство становится ранним объяснимым отказом вместо поздней
   необработанной ошибки платформы.

## Верификация

- `cargo test -p unica-coder runtime_adapter_ -- --test-threads=1` — проверяет
  выбор полного режима, предупреждение, явный обход, отказ при нечитаемом
  свидетельстве и границу основного config.
- `cargo test -p unica-coder runtime_job_ -- --test-threads=1` — проверяет ту же
  нормализацию для показываемой команды задания; исполняемые аргументы строятся
  из той же нормализованной копии непосредственно перед созданием запроса
  задания.
- `cargo test -p unica-coder infrastructure::application_ports::tests -- --test-threads=1`
  — проверяет внедрение `SupportStateReader` в оба runtime-входа.
- `tests/ci/test_architecture_registry.py` — проверяет выведенный инвариант,
  решение-владелец и исполняемые цели проверки.
