# ADR-0033: Роль подсистемы выводится из доказанного зарегистрированного дерева

- Статус: `accepted`
- Дата: `2026-08-09`
- Задача: #384

## Контекст

Подсистемы решают две разные задачи (v8std 543 п.1.1–1.3): образуют разделы
командного интерфейса и группируют объекты по функциональному признаку для
разработки. Библиотечный корень по v8std 705 п.1 командного интерфейса не
содержит. В XML обе разновидности лежат в одном `Content`, и различает их только
`IncludeInCommandInterface`.

Свойство «быть разделом» принадлежит всей цепочке до корня, а не одному
дескриптору: подсистема со снятым флагом закрывает раздел и для всех потомков.
На конфигурации УТ-класса (458 дескрипторов) 328 подсистем несут снятый флаг,
шесть несут установленный под исключённым предком, две из них выводят регистры.
Проверка по одному локальному флагу пропускала оба случая.

Членство подсистемы в конфигурации доказывают регистрации
`Configuration/ChildObjects` и `ChildObjects` родителя. Раскладка файлов их не
заменяет: посторонний XML под `Subsystems/` не входит в конфигурацию, но при
проверке по каталогу подавлял диагностику.

Вложенную подсистему нельзя адресовать общим `MetadataAddress` (ADR-0021): там
вид цели выводится из чётности числа сегментов, поэтому `Subsystem.Родитель.Потомок`
читается как модуль.

## Решение

1. Роль подсистемы — производное понятие из двух значений. `Interface`:
   собственный флаг `true` и у всех зарегистрированных предков `true`.
   `Functional`: иначе. Совпадение функциональной и интерфейсной структуры
   третьего вида не образует — такая подсистема интерфейсная.
2. Дерево строится по регистрациям, а не по раскладке файлов. Файлы
   подтверждают ресурсы зарегистрированного дерева.
3. Доказательство либо полное, либо отсутствует. Пропавший зарегистрированный
   дескриптор, имя, не совпавшее с регистрацией, значение
   `IncludeInCommandInterface` вне `true`/`false`, его отсутствие, обрыв
   цепочки, отмена и превышение вложенности дают недоступность, а не пустое
   дерево и не доказанное отсутствие раздела.
4. Адрес подсистемы — отдельный доменный тип в плоском диалекте БСП
   (`СтандартныеПодсистемы.Обсуждения`), тот же, что принимает
   `ПодсистемаСуществует`. Общий `MetadataAddress` не расширяется. Платформенные
   формы (`Subsystem.A.Subsystem.B` в `Rights.xml`, в `Content/xr:Item`, в
   объектной модели BSL) остаются на границе XML.
5. `unica.subsystem.info` при чтении дерева возвращает два взаимоисключающих
   списка адресов, `interfaceSubsystems` и `functionalSubsystems`. Оба поля
   отсутствуют, когда дерево доказать нельзя: недоказуемое не выражается двумя
   достоверно пустыми списками.
6. Построитель дерева один, и его результат переиспользуют публичный ответ
   `unica.subsystem.info` и проверка регистра в `unica.meta.info`.

ADR-0021 продолжает действовать без изменений: адрес подсистемы им не
описывается и его грамматику не расширяет.

## Последствия

Проверка регистра больше не выносит вердикт там, где дерево не построено, —
в частности на входе `meta.add` и `meta.edit`, что согласуется с границей
ADR-0030 для межобъектных условий.

Правило перестало предупреждать о регистре, лежащем в подсистеме с
установленным флагом под исключённым предком, — прежнее поведение было
ложноотрицательным.

## Проверка

- `cargo test -p unica-coder` — роли, доказанное дерево, отказы на
  незарегистрированном дескрипторе, несовпавшем имени, неканоническом флаге и
  превышении вложенности.
- `python3.12 -m unittest discover -s tests/ci` — реестры и достижимость
  документов.
