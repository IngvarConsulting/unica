# ADR-0055: Дымовая проверка исполняет извлечённый проверенный архив runtime

- Статус: `accepted`
- Дата: `2026-08-13`

## Контекст

ADR-0010 закрепил локальную упаковку runtime на каждом платформенном раннере,
но поставил дымовую проверку MCP перед `package-unica-runtime.py`. Такой порядок
проверяет исходный набор инструментов, а не архив и метаданные, которые затем
становятся байтами релиза. Он допускает расхождение: файл может отсутствовать,
измениться или получить неверный режим только в архиве, тогда как дымовая
проверка уже завершилась успешно.

Обновление `bsl-analyzer` до `v0.2.67` сделало этот разрыв наблюдаемым: исходный
набор инструментов не содержит сгенерированный `third-party/manifest.json`, а
детерминированный runtime содержит его по контракту упаковщика. Проверка
исходного каталога поэтому не доказывает работоспособность публикуемого runtime.
Остальные решения ADR-0010 о единой сборке Cargo, точных ключах кеша, узких
артефактах и локальной платформенной проверке остаются необходимыми.

Происхождение выбора и рассмотренные альтернативы записаны в
[проектной записке](../../docs/design/2026-08-12-bsl-analyzer-v0-2-67-design.md).

## Решение

1. Каждый платформенный раннер собирает `unica` и `unica-bootstrap` одним
   обязательным `cargo build --locked` в отдельном для цели каталоге Cargo.
   Ключ кеша включает ОС, цель, разрешённый тулчейн и `Cargo.lock`; префиксные
   ключи восстановления не используются, а исход кеша и длительность сборки
   публикуются в сводке задания.
2. Раннер проверяет контракты полного набора инструментов, затем создаёт
   детерминированные архив и метаданные runtime и проверяет эту пару через
   `verify-release-assets.py` до выгрузки или удаления.
3. Дымовая проверка MCP извлекает уже проверенный архив в чистый каталог и
   запускает `unica` с корнем плагина из этого каталога. Исходный набор
   инструментов не является заменой этой проверке: успешно выполняются именно
   байты, состав и режимы которых одобрены для публикации.
4. Каталоги Cargo и полные наборы инструментов не пересекают границы заданий.
   Между заданиями передаются только метаданные runtime, полезная нагрузка
   bootstrap и требуемые архивы runtime; промежуточные артефакты хранятся один
   день, а тонкая полезная нагрузка маркетплейса — девяносто дней.
5. Запрос на слияние и ручной запуск выгружают только Linux runtime, необходимый
   оценке релиза. Запуск по тегу выгружает все три runtime, публикует их и
   повторно проверяет заново скачанные байты. Публикация, размещение и
   продвижение остаются раздельными явными действиями.
6. Ошибка кеша не обходит сборку, проверку архивов или дымовую проверку.
   Отсутствующий артефакт, несовпавшие метаданные, ошибка извлечения или отказ
   MCP на любой поддерживаемой платформе блокируют весь агрегирующий шлюз.

## Неграницы

1. Решение не меняет состав публичных инструментов `unica.*`, идентичность
   MCP-сервера или формат runtime-архива.
2. Решение не требует выгружать полные наборы инструментов и не возвращает
   отдельное задание `package-runtime`.
3. Решение не заменяет повторную проверку опубликованных ассетов после тега и
   дымовую проверку тонкого плагина на поддерживаемых хостах.
4. Решение не объявляет попадание кеша доказательством пригодности сборки.

## Последствия

1. Платформенный раннер распаковывает собственный архив перед MCP smoke, но
   проверяет тот же материал, который будет опубликован, а не похожий каталог.
2. Ошибка упаковщика или неполный runtime проявляются до пересечения границы
   задания и до публикации.
3. ADR-0010 сохраняется как история исходного потока и заменяется этой записью;
   выведенные правила CI ссылаются на ADR-0055.

## Верификация

- `tests/ci/test_unica_workflow.py` проверяет порядок
  `package → verify → extract → smoke` и запуск из извлечённого runtime.
- `scripts/ci/verify-release-assets.py` сверяет архив, метаданные, состав,
  контрольные суммы, режимы и временные метки.
- `.github/workflows/unica-plugin-release.yml` выполняет сборку, проверку,
  извлечение и MCP smoke на `darwin-arm64`, `linux-x64` и `win-x64` до выгрузки.
- `scripts/ci/evaluate-ci-gate.py` блокирует агрегирующий шлюз, если обязательная
  платформенная сборка или следующий этап упаковки не завершились успешно.
