# ADR-0076: Имена новых методов проверяются до публикации BSL

- Статус: `accepted`
- Дата: `2026-08-20`
- Задача: [#591](https://github.com/IngvarConsulting/unica/issues/591)

## Контекст

`unica.code.patch` доказывал синтаксическую корректность конечного BSL, но не
показывал, что имя добавленного или переименованного метода противоречит
стандарту 647. Уровень `hint` диагностики `FunctionNameStartsWithGet` при этом
не попадал в обычный порог `warning`, а skills, которые пишут BSL, не имели
общего справочника выбора имени. Дополнительный разрыв проявлялся в фасаде
стандартов: цифровой локатор `647` передавался поставщику как есть, хотя его
канонический псевдоним — `std647`.

Полная проверка стандарта по одному AST невозможна без ложных срабатываний:
различие функции-значения, конструктора, предиката и функции-действия задаёт
бизнес-смысл, а не синтаксис. Значит, автоматическая граница должна сообщать
только доказуемое нарушение, а семантический выбор имени должен принадлежать
общей инструкции skills.

## Решение

1. `unica.code.patch` сравнивает синтаксические деревья модуля до и после патча и проверяет по
   стандарту 647 только новый или явно переименованный метод. Изменение тела
   существующего метода не переоткрывает его имя для автоматического ревью.
2. Типизированный результат всегда содержит
   `data.validation.methodNaming`: канонический идентификатор `std647`, статус
   `passed` или `warning`, список `automatedChecks` с кодом проверки и связанным
   пунктом стандарта, структурные диагностики и
   `semanticReview` со всеми новыми или переименованными методами и обязательными
   семантическими проверками. `passed` относится только к перечисленным
   автоматическим проверкам. Предупреждение не блокирует публикацию и одновременно
   попадает в общий массив `warnings`.
3. Детерминированная проверка v1 покрывает функцию с префиксом `Получить` или
   `Get`: правило 6.1 и предложение имени результата без префикса. При этом
   предпросмотр перечисляет каждый метод, который AST-разница считает новым или
   переименованным, и явно требует для него семантическую проверку. Остальные
   различия стандарта — инфинитив процедуры, конструктор, предикат, допустимая
   функция-действие и избыточный тип результата — не угадываются по
   синтаксическому дереву и остаются обязательным шагом общего справочника
   именования.
4. Каждый навык, который направляет запись через `unica.code.patch`, читает
   один поставляемый справочник именования до выбора нового имени. Справочник
   запрещает неявно переименовывать обработчики платформы и существующий
   публичный API и требует hint-уровень последующей диагностики.
5. Фасад `unica.standards.explain` нормализует цифровое значение, `#`-форму и
   регистронезависимый псевдоним в `std<номер>` до обращения к поставщику;
   полный веб-адрес остаётся без изменения.

## Неграницы

- Решение не добавляет аргументы `unica.code.patch` и не делает naming-warning
  блокирующей ошибкой.
- Решение не вводит морфологический анализ русского языка и не объявляет
  семантически корректным имя только потому, что детерминированная проверка не
  нашла префикс `Получить`.
- Решение не переименовывает существующий метод, не меняет вызывающие места и
  не расширяет одну операцию патча до пакетного рефакторинга API.
- Решение не меняет общий порог `unica.code.diagnostics`: полная проверка именования
  явно запрашивает `filter.minSeverity: hint` для затронутого модуля.

## Последствия

- Предпросмотр показывает доказуемое нарушение до записи файла и сохраняет ту же
  форму данных при применении.
- Отсутствие автоматической диагностики не выдаётся за полную проверку
  стандарта: результат отдельно перечисляет точные автоматические проверки и методы,
  требующие семантической проверки.
- Существующий публичный API и платформенные обработчики не получают шумных
  предупреждений при правке тела.
- Семантические правила стандарта живут в одном достижимом справочнике, а не в
  восьми расходящихся пересказах.
- Цифровые номера стандартов из skills разрешаются так же, как канонические
  псевдонимы.

- `tests/ci/test_reference_reachability.py` — новый справочник достижим из
  поставляемых skills.
