# ADR-0021: `unica.code.outline` возвращает типизированную структуру текущего BSL-файла

- Статус: `accepted`
- Дата: `2026-07-30`
- Задача: [#262](https://github.com/IngvarConsulting/unica/issues/262)

## Контекст

ADR-0020 закрепила текущий BSL-файл как источник `outline`, но одновременно
сохранила компактную текстовую грамматику `stdout`. Первая реализация показала,
что эта грамматика не имеет устойчивой границы: метка секции стала частью
контракта без версии, вид метода унаследовал локаль и регистр исходного токена,
а сырой текст многострочного параметра добавил физические строки внутрь одной
записи метода.

Общий конверт `OperationResult` уже разделяет диагностический текст `stdout` и
типизированный результат `data`. Сериализация JSON в `stdout` создала бы
JSON-строку внутри JSON-конверта и оставила бы два способа представить один
результат.

## Решение

1. `unica.code.outline` строит полный доказанный результат из BSL-файла,
   лежащего в выбранном корне исходников на момент вызова, через закреплённый
   `bsl-parser`; снимок `bsl_index`, готовность индекса, скрытый сервис `RLM` и
   состояние рабочего пространства в этом пути не участвуют.
2. Успешный вызов публикует `outline` только как типизированный объект
   `OperationResult.data`; `stdout` отсутствует, и параллельное текстовое
   представление результата не поддерживается.
3. Объект `data` содержит путь модуля, идентичность, итоги, рекурсивное дерево
   областей и отдельный массив методов вне областей. Неизвестные доказуемо
   необязательные значения представлены `null`, а не отсутствующим полем.
4. Метод несёт канонический вид `procedure` или `function`, имя, массив
   структурированных параметров, признак экспорта и диапазон строк. Локаль,
   регистр и `trivia` исходного объявления на эти поля не влияют.
5. Параметр несёт имя, признак передачи по значению и нормализованное выражение
   по умолчанию либо `null`; значение выводится из узла `Param`, а не из сырого
   текста всего параметра.
6. `includeMethods=false` оставляет массивы методов пустыми, сохраняя дерево
   областей и полные итоги модуля.
7. Ошибка чтения, выход за корень исходников, диагностика парсера, отмена,
   исчерпанный срок или недоказуемое обязательное поле завершают вызов без
   `data`, без `stdout`, без частичного дерева и без изменения кеша.

Эта запись заменяет ADR-0020.

## Неграницы

Решение не меняет имена и аргументы `unica.code.outline`, общий конверт
`OperationResult`, формат ошибок и cache-report.

Решение не типизирует в этой работе результаты `unica.code.definition`,
`unica.code.search`, `unica.code.graph` и `unica.meta.profile` и не запрещает
им существующий диагностический `stdout`.

Решение не добавляет отдельную версию схемы внутрь `data`: контракт поставляется
версией публичного инструмента.

## Последствия

- Потребитель читает поля JSON и не разбирает заголовки, отступы и строки
  специальной грамматики.
- Форматирование исходной сигнатуры не меняет структуру результата.
- Смена текстового `stdout` на `data` является намеренной несовместимостью
  первой реализации PR #265 и должна быть явно названа в описании PR.
- Результат outline проходит через нейтральную к поставщику типизированную
  модель; детали синтаксического дерева остаются в инфраструктуре.
- Для definition и profile временно сохраняется другой путь представления
  результата; их типизация требует отдельного решения.

## Верификация

- `cargo test -p unica-coder --lib bsl_outline` — точная структура JSON,
  канонические виды методов, структурированные параметры, дерево областей,
  сироты, `includeMethods=false` и fail-closed ошибки.
- `cargo test -p unica-coder --lib code_intelligence` — типизированный результат
  проходит через выбранного поставщика без текстового дубля.
- `cargo test -p unica-coder --test platform_code_intelligence` — публичный
  конверт содержит `data`, не содержит `stdout`, читает текущий файл и не
  касается индекса.
- `python3.12 scripts/ci/check-architecture-sync.py --base origin/main --strict`
  — ADR, запись реестра и публичный контракт меняются одним набором правок.
