# ADR-0077: Внешний источник данных входит в типизированную ветку метаданных

- Статус: `accepted`
- Дата: `2026-08-22`
- Задача: [#506](https://github.com/IngvarConsulting/unica/issues/506)

## Контекст

Четыре инструмента `unica.meta.*` по ADR-0025 публикуют закрытый перечень видов,
в котором нет `ExternalDataSource`. Валидаторы конфигурации и расширения
поэтому считают зарегистрированный внешний источник неизвестным объектом, а
логический резолвер не связывает таблицы, кубы, таблицы измерений и их модули с
физической раскладкой выгрузки.

Выгрузки платформы `8.3.27` формата `2.20` и реальные `Rights.xml` доказывают
форму корневого дескриптора, вложенные каталоги и права источника, таблицы и её
поля. Происхождение выбора и граница работы записаны в
[проектной записке](../../docs/design/2026-08-22-external-data-source-design.md).

## Решение

1. `ExternalDataSource` становится двадцать четвёртым значением закрытого
   перечня видов существующих `unica.meta.info`, `unica.meta.add`,
   `unica.meta.edit` и `unica.meta.remove`. Набор и имена инструментов не
   меняются.
2. Минимальный дескриптор профиля `8.3.27/2.20` содержит базовые свойства,
   `DataLockControlMode`, `ChildObjects` и сгенерированные категории `Manager`,
   `TablesManager`, `CubesManager`. Один и тот же профиль обслуживает создание,
   чтение, изменение и внутреннюю проверку.
3. Адрес внешнего источника продолжает общую грамматику чередующихся пар
   «вид — имя»: после источника допустимы `Table` или `Cube`, а после куба —
   `DimensionTable`. Только полный адрес объекта может завершаться доказанной
   ролью модуля; физическое и логическое представления преобразуются взаимно
   однозначно и проверяют цепочку дескрипторов всех предков.
4. Таблица и куб допускают `ManagerModule` и `RecordSetModule`; таблица
   измерения допускает `ObjectModule` и `ManagerModule`. Другие роли остаются
   закрытыми.
5. `cf.validate` и `cfe.validate` получают `ExternalDataSource` из общего
   канонического реестра видов и не держат отдельное исключение.
6. Профиль роли допускает `Use` для `ExternalDataSource.<Имя>`, `Read`,
   `Insert`, `Update`, `View`, `InputByString` для его таблицы и `View`, `Edit`
   для поля таблицы. Неподтверждённые права не принимаются записывающим
   компонентом.

## Неграницы

1. Решение не добавляет создание или изменение таблиц, кубов и таблиц
   измерений через коллекции `unica.meta.edit`.
2. Решение не моделирует составные объекты и `CommonForm` внешнего источника.
3. Решение не добавляет конкретные цели внешнего источника в отношение
   `EventSubscription.Source`.
4. Решение не меняет исходную информационную базу и не делает runtime-проверку
   обязательной при наличии доказанной платформенной выгрузки.

## Последствия

1. Публичные схемы `kind` и `details` расширяются согласованно, поэтому
   потребители должны принять новое значение закрытого перечисления.
2. Каталог раскладок поддерживает третий именованный уровень только для таблицы
   измерения куба; произвольная рекурсивная вложенность не открывается.
3. Форматная спецификация прав исправляет прежнее утверждение, опровергнутое
   реальными файлами платформы.

## Верификация

- `cargo test -p unica-coder external_data_source --lib` — проверяет адреса,
  раскладки модулей, формы прав и разбор вида.
- `cargo test -p unica-coder external_data_source_is_created_read_and_edited_through_typed_meta_tools --lib` — проверяет публичный цикл создания, чтения и изменения.
- `cargo test -p unica-coder cfe_borrow_generated_type_profile_is_total_for_the_metadata_registry --lib` — проверяет полноту общего реестра для расширений.
- `python3 -m unittest tests.ci.test_meta_surface_contract tests.ci.test_architecture_registry` — проверяет публичную схему и нормативный реестр.
