# ADR-0014: Знание о хосте живёт за host-фасадом инфраструктуры

- Статус: `accepted`
- Дата: `2026-07-29`

## Контекст

Unica обслуживает двух хостов из одного каталога плагина (ADR-0012). Хосты
расходятся в трёх местах: каждый читает свой каталог манифеста — `.codex-plugin`
или `.claude-plugin`; каждый по-своему разрешает корень плагина; и у каждого
свой каталог данных, из которого выводится корень кеша runtime.

Всё знание об этих различиях сегодня лежит в одном файле —
`crates/unica-bootstrap/src/main.rs`. Проверка установленного пакета перебирает
пару литералов `(".codex-plugin", true)` и `(".claude-plugin", false)`, где
второй элемент означает «этот хост обязан объявить указатель `skills`».
`runtime_cache_root` перечисляет источники корня кеша по порядку:
`UNICA_RUNTIME_CACHE_DIR`, затем `CLAUDE_PLUGIN_DATA`, затем `codex_home_root`.
`codex_home_root` знает про переменную `CODEX_HOME`, про откат к `HOME` и
`USERPROFILE` и про сегмент пути `.codex`.

В `crates/unica-coder/src/` знания о хостах нет ни в одном из четырёх слоёв: ни
имён хостов, ни каталогов манифестов, ни переменных `CODEX_HOME` и
`CLAUDE_PLUGIN_DATA`. Оркестратор доходит до корня плагина через
host-нейтральную `UNICA_PLUGIN_ROOT` и признаки самого каталога. То есть
требуемое свойство уже выполняется — но оно нигде не названо и ничем не
удерживается: единственное, что мешает следующему изменению уронить имя хоста в
домен или в адаптер, это внимательность ревьюера.

Само знание разложено не как описание хоста, а как условия в местах вызова.
Список хостов ниоткуда не читается целиком, и цена третьего хоста — правка
каждого такого ветвления, причём набор затронутых мест приходится искать
поиском по литералам.

Цепочка `runtime_cache_root` и `codex_home_root` не покрыта ни одним
юнит-тестом. Косвенно её удерживают только упакованное значение
`UNICA_RUNTIME_CACHE_DIR` в `tests/ci/test_package_unica_plugin.py` и упоминание
пути `$CODEX_HOME/unica/runtimes` в README, проверяемое
`tests/ci/test_product_contracts.py`. Порядок отката, отбрасывание значения с
неразвёрнутой подстрокой `${`, сегмент `.codex` и жёсткая ошибка при отсутствии
всех переменных сейчас держатся на ручном перечитывании кода — это записано в
`INV-CACHE-07` как проверка класса `manual`.

Прецедент, который закрывает ровно такую задачу, в проекте уже есть. ADR-0009
вынес зависимость от операционной системы за платформенные фасады и удерживает
границу стражем `scripts/ci/check-rust-platform-boundary.py`, у которого нет
исключений по конкретным путям: разрешено только структурное расположение.

## Решение

Знание о хосте получает такую же границу, как знание об операционной системе.

1. Host-специфичное продуктивное поведение живёт только под
   `crates/unica-bootstrap/src/host/**`. Host-маркеры — имена хостов, каталоги
   манифестов `.codex-plugin` и `.claude-plugin`, переменные окружения
   `CODEX_HOME`, `CLAUDE_PLUGIN_DATA` и `CLAUDE_PLUGIN_ROOT`, сегменты путей
   вида `.codex` — вне этого фасада не встречаются.
2. `crates/unica-coder/src/**` host-нейтрален целиком: домен, приложение,
   инфраструктура и интерфейсный слой не содержат ни одного host-маркера.
   Оркестратор получает корень плагина и корень кеша как обычные пути, не зная,
   какой хост его запустил.
3. Наружу host-фасад выставляет только host-нейтральные типы. Проверка
   манифестов и разрешение корня кеша попадают в остальной код через этот фасад.
4. Хост описан дескриптором-данными, а не ветвлением. Места вызова перебирают
   реестр дескрипторов; условий по конкретному хосту в них нет. Образец —
   `HostTarget` платформенного фасада, где выбор сведён к данным и `match` по
   варианту.
5. Поддержка нового хоста добавляется дескриптором внутри фасада вместе с его
   тестами. Места вызова в `crates/unica-bootstrap/src/main.rs` при этом не
   меняются.
6. Host-нейтральный override остаётся вне дескрипторов.
   `UNICA_RUNTIME_CACHE_DIR` и правило «значение с неразвёрнутой подстрокой `${`
   отбрасывается и цепочка продолжается» принадлежат самому разрешению корня
   кеша: переменную выставляет пакет, а не хост, и хост, не подставивший токен,
   не должен создать каталог, названный этим токеном.
7. Границу удерживает тот же архитектурный страж в отслеживаемых исходниках, что
   удерживает платформенную границу. Host-маркер вне host-фасада — отказ.
   Послаблений по конкретным путям у стража нет, исключение только структурное.
8. Тесты фасада живут рядом с ним, а host-специфичный тест верхнего уровня —
   под `crates/<crate>/tests/host/**`, по образцу платформенных тестов
   ADR-0009. Порядок разрешения корня кеша, отбрасывание значения с `${`,
   сегмент `.codex` при незаданном `CODEX_HOME`, жёсткая ошибка при отсутствии
   всех переменных и правило «достаточно одного манифеста хоста, но каждый
   присутствующий обязан пройти свой контракт» закрепляются юнит-тестами
   фасада.
9. Выделение фасада — рефакторинг, а не изменение поведения. Наблюдаемые
   контракты остаются теми же, что нормированы `INV-CACHE-07`, `INV-PKG-05` и
   `INV-PKG-06`, и правятся только вместе с ними.

## Неграницы

Сборочные инструменты остаются вне фасада. `scripts/ci/package-unica-plugin.py`
написан на Python, под Rust-стража не попадает и обязан знать имена хостов: он
собирает пакет для обоих. Часть различий он уже берёт из данных — отображение
`HOST_MANIFEST_DIRS` задаёт каталоги манифестов, и проверка присутствия
манифестов перебирает именно его. Часть по-прежнему выражена условиями в местах
вызова: `write_local_debug_mcp_launcher` и `package_local_debug` ветвятся по
`host == "claude"` и `host == "codex"`, а каталоги маркетплейса пишут разные
функции. Решение не требует привести это к дескриптору прямо сейчас; до тех пор
сценарий удерживают тесты `tests/ci/test_package_unica_plugin.py`, а не страж.

Рабочие процессы GitHub Actions и скрипты разработчика — в частности
`scripts/ci/smoke-unica-bootstrap.py` и `scripts/dev/install-local-unica.sh` —
продолжают называть хосты по именам. Они настраивают окружение конкретного
хоста, а не реализуют продуктовое поведение, и под правило пункта 1 не
подпадают.

Тип `HostTarget` в `crates/unica-bootstrap/src/platform/target.rs` описывает
операционную систему и архитектуру, а не хост-агента. Решение его не
переименовывает и не переносит: это платформенный фасад ADR-0009.

Список поддерживаемых хостов, контракт манифестов и порядок разрешения корня
кеша этим решением не меняются. Оно отвечает только на вопрос, где это знание
живёт и что мешает ему расползтись.

## Последствия

- Путь к исходнику становится входом для вопроса «затрагивает ли изменение
  поддержку хостов» — ровно так же, как ADR-0009 сделал это для операционной
  системы.
- Список хостов впервые читается целиком в одном месте, а стоимость третьего
  хоста становится обозримой: дескриптор и его тесты вместо поиска по литералам
  и правки каждого найденного ветвления.
- Цепочка разрешения корня кеша становится юнит-тестируемой, потому что уезжает
  из `main.rs` в модуль с чистыми функциями. Ручная проверка `INV-CACHE-07`
  заменяется тестом; это единственная ручная проверка, которую решение снимает.
- Страж роняет имя хоста в новом месте безоговорочно — в том числе в
  диагностическом сообщении или в тестовой фикстуре вне фасада. Обойти его можно
  только структурно, перенеся код за границу; пофайлового исключения не будет.
- Словарь на время становится двусмысленным: `HostTarget` платформенного фасада
  означает операционную систему и архитектуру, а типы host-фасада — хост-агента.
  Пока имена не разведены, читателю приходится смотреть на модуль.
- Публичная поверхность не меняется: набор инструментов `unica.*`, контракт
  пакета, порядок установки runtime и поведение проверки манифестов остаются
  прежними.

## Верификация

- `scripts/ci/check-rust-platform-boundary.py` — падает, когда host-маркер (имя
  хоста, каталог манифеста хоста, переменная окружения хоста) встречается вне
  `crates/unica-bootstrap/src/host/**`.
- `tests/ci/test_rust_platform_boundary.py` — проверяет правила стража на
  образцах путей: исключениями признаются только host-фасад и
  `crates/<crate>/tests/host/**`, и оба признака структурные, а не пофайловые.
- Юнит-тесты `crates/unica-bootstrap/src/host/runtime_cache.rs` — закрепляют
  порядок разрешения корня кеша, отбрасывание значения с неразвёрнутой `${`,
  сегмент `.codex` при незаданном `CODEX_HOME` и жёсткую ошибку при отсутствии
  всех переменных.
- Юнит-тесты `crates/unica-bootstrap/src/host/plugin_manifest.rs` — закрепляют
  правило «достаточно одного манифеста хоста, но каждый присутствующий обязан
  пройти свой контракт» и оба контракта указателя `skills`.
- `cargo test -p unica-bootstrap` — существующие контрактные наборы
  `crates/unica-bootstrap/tests/cli_contract.rs` и
  `crates/unica-bootstrap/tests/runtime_install.rs` проходят без изменения
  ожиданий; первый выполняется с изолированным `CODEX_HOME` и требует, чтобы
  каталог остался пустым. Неизменившиеся ожидания — и есть доказательство, что
  перенос знания за фасад не изменил поведения.
- `tests/ci/test_package_unica_plugin.py` — упакованный `.mcp.json` по-прежнему
  выставляет `UNICA_RUNTIME_CACHE_DIR` в `${CLAUDE_PLUGIN_DATA}/runtimes`, то
  есть парный конец цепочки на стороне сборки не разошёлся с фасадом.
