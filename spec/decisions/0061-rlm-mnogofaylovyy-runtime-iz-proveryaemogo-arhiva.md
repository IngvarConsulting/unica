# ADR-0061: Многофайловый RLM входит в runtime замкнутой полезной нагрузкой

- Статус: `accepted`
- Дата: `2026-08-14`
- Задача: [#505](https://github.com/IngvarConsulting/unica/issues/505)

## Контекст

`rlm-bsl-index` и `rlm-bsl-mcp` сейчас поставляются как два прямых
однофайловых asset PyInstaller. Такая форма соответствует загрузчику сборки,
который копирует только объявленный бинарник, но при каждом запуске index CLI
распаковывает встроенный Python.

Nuitka standalone устраняет повторную распаковку, но его executable зависит от
соседнего `libpython` и расширений. Копирование только бинарника не является
работающей поставкой. Nuitka multidist может объединить оба entrypoint в один
скомпилированный runtime и выбрать entrypoint по имени запуска.

Конечный runtime Unica уже является многофайловым архивом: ADR-0008 требует
проверять внешний SHA-256 и каждый файл, а ADR-0055 требует запускать
извлечённые публикуемые байты. Разрыв находится раньше — между архивом
стороннего toolchain и упаковщиком Unica, который сейчас знает только отдельные
бинарники.

Происхождение выбора, варианты, формат архива и последовательность поставки
записаны в
[проектной записке](../../docs/design/2026-08-14-rlm-nuitka-standalone-multidist-design.md).

## Решение

1. Многофайловый сторонний инструмент принимается в runtime только как полная
   полезная нагрузка одного закреплённого архива цели. Файл закрепления фиксирует
   неизменяемую идентичность релиза и SHA-256 внешнего архива; внутренний
   манифест фиксирует идентичности исходника и цели, точки входа и каждый файл с
   SHA-256, размером и режимом.
2. Архив `RLM` строится одной компиляцией `Nuitka standalone multidist`. Один
   исполняемый файл `multidist` материализуется обычными файлами под именами
   `rlm-bsl-index[.exe]` и `rlm-bsl-mcp[.exe]`; обе копии обязаны быть
   побайтово равны и используют один соседний набор зависимостей. Ссылки и
   платформенные обёртки запуска не являются частью поставки.
3. Сборщик Unica скачивает общий архив цели ровно один раз, до публикации
   проверяет внешний SHA-256, безопасно извлекает только обычные файлы в новый
   промежуточный каталог и сверяет точные идентичности, набор файлов, SHA-256, размеры,
   режимы и отображение точек входа внутреннего манифеста. Небезопасная запись,
   ссылка, повтор пути, коллизия или расхождение прекращает сборку без
   частичной публикации.
4. `tools.json` раздельно описывает идентичности инструментов и полную
   `runtimeFiles`. Упаковщик включает все и только объявленные файлы runtime,
   сохраняет их относительное соседство и требует, чтобы каждый `binaryPath`
   входил в эту замкнутую полезную нагрузку.
5. Пути команд остаются
   `bin/<target>/rlm-bsl-index[.exe]` и
   `bin/<target>/rlm-bsl-mcp[.exe]`. Схема конечного манифеста `runtime`,
   алгоритм `unica-bootstrap`, публичный MCP `unica` и контракты `unica.*` не
   меняются.
6. Поставка идёт сначала через `unica-toolchain`. Unica сохраняет прежний файл
   закрепления, пока новый неизменяемый релиз не собран, не проверен на трёх
   платформах и не скачан повторно. После переключения у runtime отсутствует
   резервный маршрут на прежний артефакт `PyInstaller`.

## Неграницы

1. Решение не выбирает Nuitka onefile и не вводит пользовательский кеш
   распаковки.
2. Решение не меняет upstream RLM, поколение индекса, состояние рабочего
   пространства или семантику скрытого сервиса.
3. Решение не разрешает исключать найденную Nuitka зависимость ради размера.
4. Решение не утверждает окончательное ускорение по предварительному прогону с
   нарушенным порогом свободного места; опубликованный кандидат измеряется
   повторно.
5. Решение не меняет правила публикации и отката релиза ADR-0008 и ADR-0055.

## Последствия

1. Установленный runtime существенно увеличится: предварительная верхняя
   оценка Darwin RLM payload составляет около `228.5 MiB` вместо `42.7 MiB` у
   текущей пары PyInstaller. Точные размеры и время скачивания становятся
   обязательным evidence PR и release.
2. Повторный CLI-запуск больше не распаковывает Python, а обе команды делят
   один набор соседних библиотек.
3. Формат lock и `tools.json` получает явное представление многофайлового
   инструмента; сборка и упаковка несут дополнительные отрицательные проверки
   архива и file-set closure.
4. Bootstrap остаётся нейтральным к происхождению файлов и проверяет
   расширенный runtime существующим механизмом.

## Верификация

- `tests/ci/test_build_unica_tools.py` проверяет закрепление, единственное
  скачивание, безопасное извлечение и полный payload archive asset.
- `tests/ci/test_package_unica_runtime.py` проверяет замкнутый `runtimeFiles`,
  детерминированную перепаковку и отказ при потере зависимости.
- `tests/ci/test_product_contracts.py` проверяет обе команды RLM из полного
  многофайлового runtime.
- `crates/unica-bootstrap/tests/runtime_install.rs` проверяет существующую
  схему и атомарную установку расширенного набора файлов.
- `.github/workflows/unica-plugin-release.yml` выполняет package, verify,
  extract и MCP smoke на всех поддерживаемых платформах.
