# ADR-0056: `unica.project.status` публикует типизированную готовность проекта

- Статус: `accepted`
- Дата: `2026-08-13`

## Контекст

`unica.project.status` сейчас сообщает корни workspace/cache и карту наборов
исходников. Отказ discovery и результат проверки отслеживаемого
`ConfigDumpInfo.xml` попадают в строковые warnings. Ту же Git-проверку запускает
`unica.project.map`, хотя назначение карты — сообщать топологию и формат
источников.

Такая форма не отвечает на два разных вопроса: может ли Unica безопасно
работать с source sets и переносимы ли настройки Git для другого clone. Git не
является обязательным runtime-условием нативных Platform XML операций, но
отсутствие repository policy нельзя считать готовностью командной разработки.

Разрешённый сегодня `sourceSet.path: .` смешивает workspace-служебные файлы и
выгрузку 1С в одном корне. Отдельный перенос provider cache не устраняет эту
топологическую причину.

Рекомендации 1C-Company GitConverter требуют LF в repository, исключение
служебных файлов и явную классификацию binary. Их нельзя переносить в Platform
XML по расширению: XDTO `Ext/Package.bin` является текстовым XML, а
`ConfigDumpInfo.xml` может быть как runtime sidecar, так и законным metadata
descriptor.

Происхождение решения, каталог диагностик, публичная форма и тестовая матрица
записаны в [проектной записке](../../docs/design/2026-08-13-project-source-health-design.md).

## Решение

1. `unica.project.status` является единственной публичной полной проверкой
   рабочего пространства, репозитория и каждого объявленного набора исходников.
   Проверка только читает состояние, выполняется по явному вызову и не
   запускается из предметных инструментов.
2. `unica.project.map` сообщает только карту источников и не выполняет Git
   проверки готовности. Новый публичный инструмент не добавляется.
3. Успешная инспекция возвращает типизированные `checks[]`, `diagnostics[]` и
   два независимых флага. `ready` означает, что топология рабочего пространства
   и наборов исходников полностью проверена и безопасна для операций Unica.
   Неразобранная карта или отсутствие наборов исходников делают `ready=false`.
   `repositoryReady` означает, что полностью проверен переносимый Git-контракт.
4. Отсутствие репозитория Git или исполняемого файла Git делает
   `repositoryReady=false`, но само по себе не делает `ready=false`. Зависимые
   Git-проверки получают `notRun`, а не выдуманный успешный результат.
5. Корень исходников является строгим потомком корня рабочего пространства.
   Равенство после нормализации или разрешения идентичности, включая `path: .`,
   `./` и псевдоним через символическую ссылку или точку повторной обработки,
   является ошибкой `source_set.root_is_workspace`.
6. Общие правила топологии и репозитория применяются ко всем наборам исходников.
   Первый форматный профиль проверяет `Platform XML`; EDT получает только общие
   результаты, пока отдельная политика не доказана.
7. Переносимый контракт исключений доказывается отслеживаемым `.gitignore`.
   Глобальные исключения и `.git/info/exclude` не достаточны. Проверяются и
   отсутствие правила до появления служебного файла, и наличие уже
   отслеживаемого служебного пути.
8. Ресурсы `Platform XML` классифицируются по доказанной роли. Текст в индексе
   нормализован в LF, рабочее дерево может единообразно иметь LF или CRLF, а
   смешанные окончания строк и единообразный одиночный CR являются ошибкой.
   Переносимость правил атрибутов доказывается отслеживаемым `.gitattributes`;
   локальные атрибуты из `.git/info/attributes`, глобальные и системные правила
   недостаточны.
   Доказанный текст не помечается двоичным, доказанный двоичный ресурс имеет
   `-text`, а широкое правило `*.bin binary` не имеет приоритета над текстовой
   ролью `XDTO Package.bin`.
9. `ConfigDumpInfo.xml` удаляется из индекса только после классификации
   подготовленного содержимого как служебного файла среды исполнения.
   Неоднозначность возвращает отдельную диагностику ручной проверки без
   команды удаления. Действующий доменный классификатор переиспользуется.
10. `LFS` является необязательной рекомендацией `info`, агрегированной только по
    доказанным большим бинарным ресурсам. Она не изменяет ни один флаг и не
    предлагает широкое правило `*.bin`.
11. Ошибка области `workspace` или `sourceSet` закрывает `ready`; ошибка области
    `repository` закрывает `repositoryReady`. Предупреждения и сведения не
    закрывают флаги. Неполная обязательная проверка имеет `notRun` и закрывает
    только свой контур; доказанная неприменимость имеет `notApplicable`.
12. Найденная проблема проекта является успешным результатом инспекции:
    конверт сохраняет `ok=true`, а ошибка находится в `data.diagnostics`.
    Отмена всего вызова или внутренний отказ без достоверного снимка дают
    `ok=false`.
13. Диагностика содержит стабильные `code`, `severity`, `scope`, необязательный
    `sourceSet`, ограниченные примеры `paths` и `evidence`, полный `count`,
    `message` и `remediation`. Исправление объясняется, но не выполняется.
    Команда публикуется как
    `program`/`argv`/`cwd` только при доказанных предусловиях; неоднозначная или
    потенциально разрушительная операция команды не получает.
14. Сборщики фактов ограничены сроком, отменой и бюджетом вывода, используют
    разделители `NUL` и `argv` без интерпретации оболочкой, не запускают скрытые
    сервисы и не выдают усечённый или неразобранный результат за `passed`.

## Неграницы

1. Решение не делает Git обязательным условием всех операций Unica.
2. Решение не меняет Git config пользователя, `.gitignore`, `.gitattributes`,
   index, working tree или историю.
3. Решение не проверяет branch, remote, dirty state, server policy и историю
   больших объектов.
4. Решение не выбирает обязательное значение `core.autocrlf`,
   `core.safecrlf`, `core.quotepath` или GUI encoding.
5. Решение не вводит специальную EDT policy и не считает рекомендации
   GitConverter готовой спецификацией Platform XML.
6. Решение не владеет размещением кеша `bsl-analyzer`; его меняет отдельный PR
   #473. Корневая ошибка `sourceSet.path: .` остаётся недопустимой независимо от
   состояния этого PR.
7. Решение не превращает диагностику в скрытую мутацию: даже опубликованная
   команда остаётся объяснением возможного исправления, а не разрешением её
   выполнить.

## Последствия

1. AI получает одно детерминированное место для preflight и не разбирает prose
   warnings.
2. Проект без Git остаётся доступен нативным операциям, но явно не считается
   готовым к переносимой командной работе.
3. Репозитории с source root в `.` должны отделить выгрузку от workspace root и
   обновить `v8project.yaml`; это намеренно несовместимое ужесточение health
   policy, а не автоматическая миграция.
4. Bounded Git/file-system inspector с точным provenance ignore rules,
   attributes, EOL и staged blobs вызывается только явным `project.status`.
5. Публичный payload `project.status` расширяется; operation descriptor,
   tool-surface, skill и package contracts должны измениться синхронно в
   implementation PR.
6. Строковый `GitTrackingAdapter` заменяется общей typed pipeline; его
   содержательная классификация сохраняется как доменный факт.

  ровно в секции принятых решений, а записи реестра ссылаются на существующие

  существующую ADR-0056.

  проверяет два контура готовности, каталог первичных причин, полноту фактов и
  безопасную remediation.
- `python3.12 -m unittest tests.ci.test_unica_mcp_smoke` — проверяет
  публичную typed форму `unica.project.status` и отсутствие Git health warning

  — принятие ADR, выведенные правила и изменение публичного контракта входят в
  один implementation PR.
