# ADR-0015: Узкие границы `unica.code.patch` v1

- Статус: `accepted`
- Дата: `2026-07-21`
- Обновлено: `2026-07-29`
- Задача: #73

> Запись выделена `2026-07-29` из документа `spec/architecture/code-patch-v1.md`,
> который совмещал решение, действующие правила и пересказ схемы аргументов.
> Содержание решения не менялось; правила переехали в реестр инвариантов, схема
> осталась там, где ей и место, — в коде.

## Контекст

Задача #73 просила одну точечную мутацию модуля BSL через публичный MCP. Общий
контракт записи для всех изменяющих инструментов проектировался отдельно (#74) и
на тот момент готов не был.

Соблазн был сделать сразу редактор произвольного текста: принимать любой файл,
любую операцию, пакетные изменения. Цена такого шага асимметрична. Публичный
инструмент MCP — это контракт: расширить его позже дёшево, сузить после того,
как им начали пользоваться, нельзя. Ошибка в сторону широты становится
обязательством навсегда, ошибка в сторону узости стоит одного следующего
решения.

При этом узкий инструмент не означает слабых гарантий: мутация исходников должна
быть безопасной побайтово, иначе платформа откажется загружать конфигурацию, а
причину придётся искать в невидимых различиях переводов строк и BOM.

## Решение

1. `unica.code.patch` v1 делает ровно одну вставку в ровно один существующий
   файл `*Module.bsl` внутри набора исходников платформенного XML вида
   `CONFIGURATION`, выбранного обычной политикой выбора набора.
2. Единственная операция — `insert`, с одним из двух селекторов: `method` или
   `anchor`. Отсутствующий, двусмысленный или пересекающий закрывающую лексему
   селектор — ошибка, а не пустая операция.
3. Предпросмотр остаётся значением по умолчанию. Применяющий вызов требует
   явного `dryRun: false` и проходит обычные политики путей рабочего
   пространства и стража поддержки.
4. Результат возвращается объектом в `OperationResult.data` и доказывает
   мутацию: хеши до и после, изменённые диапазоны, унифицированный diff из того
   же образа, что и хеш, и завершающая валидация разбором BSL. `stdout` не
   используется как контейнер сериализованного JSON.
5. Расширение любой из этих границ — новое решение, а не правка этой записи.

## Неграницы

1. Решение не вводит `replace`, `delete`, переименование, создание модуля,
   `allowMissing`, пакетную правку и каскадные изменения.
2. Решение не распространяется на внешние обработки и отчёты, EDT и расширения
   конфигурации: для них выбор набора исходников и раскладка другие.
3. Решение не определяет общий контракт записи для остальных изменяющих
   инструментов — это предмет #74, и v1 не должен его предвосхищать.
4. Результат v1 не утверждает, что модуль загружен в информационную базу.
   Связывание события мутации с устойчивым состоянием «источник грязный» ждёт
   контракта доставки #76.
5. Решение не нормирует схему аргументов: её объявляет
   `application/tool_contracts.rs`, и дублировать её прозой запрещено
   (`INV-MCP-05`).

## Последствия

- Сценарий из #73 закрыт, а площадь совместимости осталась маленькой: каждое
  последующее расширение обсуждается отдельно и по своей цене.
- Побайтовые гарантии, которые потребовались этому инструменту, оказались общими
  для всех изменяющих операций и вынесены в разделяемый снимок текста. Правила
  живут в реестре (`INV-SOURCE-06`, `INV-SOURCE-08`, `INV-SOURCE-09`), а не в
  контракте одного инструмента.
- Отказ от одиночных CR в исходном модуле — осознанное сужение: v1 умеет
  сохранять LF, CRLF и их смешение, а исходник с одиночным CR отклоняет до
  мутации, вместо того чтобы молча его нормализовать.
- Пользователь, которому нужна замена или пакетная правка, получает явный отказ,
  а не частично применённое изменение.

## Верификация

- `crates/unica-coder/src/infrastructure/native_operations/code.rs` — поведение
  селекторов, границы методов, отказ `resolve_target` для набора исходников, не
  являющегося платформенным XML вида `CONFIGURATION`, и отклонение операций вне
  v1.
- `crates/unica-coder/src/infrastructure/native_operations/tests.rs` —
  типизированный путь диспетчеризации: `code-patch` не проходит через общий
  путь, теряющий `data`.
- `crates/unica-coder/src/application/mod.rs` — предпросмотр по умолчанию и
  форма результата на уровне вызова инструмента.
- `crates/unica-coder/src/infrastructure/format_guard.rs` — вызов внутри набора
  исходников более старого формата выгрузки блокируется.
