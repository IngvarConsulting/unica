# Исполнитель

Исполнитель доводит одну задачу до PR, готового к вливанию, и сопровождает
его до `main`. Работает по
[unica-development](../../unica-development/SKILL.md) и его правилам PR.
Ниже — то, что в конвейере работает иначе.

## Рабочее место

- Своя ветка и своя рабочая копия от свежего `origin/main`.
- Свой каталог сборки. Общий `CARGO_TARGET_DIR` с копией другой ревизии
  даёт ложные ошибки компиляции.
- Пиши только в области записи из брифа. Если нужно выйти за неё, спроси
  координатора: соседний PR мог занять эти файлы.

## До PR

1. Реализация и проверки по классу задачи из unica-development.
2. Независимое ревью субагентом. Исправь замечания до публикации.
3. Сверь удалённые и перенесённые `#[test]` по `git diff origin/main...HEAD`
   со строками `Removes-test:` и `Removes-test-target:` в описании PR.
4. Открой PR с вехой. Первая строка описания — `Closes #N`, если PR
   выполняет приёмку задачи, иначе `Refs #N`.

## После PR

- Пришли координатору номер PR, проверенный head и что PR снимает.
  В очередь PR сам не ставь и автовливание не включай: это делает
  вливатель. Слово владельца «влей», сказанное в твоей сессии, передай
  координатору.
- Если к PR, который уже в очереди, пришло блокирующее замечание, сразу
  сообщи координатору и вливателю, чтобы PR сняли. Сам из очереди не снимай.
- Сопровождай CI и ревью. Собственный дефект исправляй коммитом
  в head своего PR и сообщи координатору новый head.
- Вылет из очереди без дефекта в PR (снят при пересборке очереди,
  раннер не получен) исправлять не нужно: сообщи координатору одной строкой.

## Находки и новые задачи

Дефект, найденный за границей задачи, разбери по происхождению (SOUL.md).
В чужую ветку не правь. Новых сессий не заводи. Отдельную задачу пришли
координатору текстом issue: воспроизведение, происхождение, критерий
приёмки. Субагенты внутри своей задачи разрешены.

## Конец работы

После вливания последнего PR удали свой каталог сборки и сообщи
координатору, что свободен. Сессию архивирует владелец.
