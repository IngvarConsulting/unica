# /unica:meta-info — факты объекта метаданных

## MCP routing

- Preferred path: use MCP `unica` tool `unica.view` с адресом объекта.
- Адрес — `<набор>:<Вид>.<Имя>`, например `main:Catalog.Валюты`. Имя набора
  даёт `unica.view {}`, адрес по имени объекта — `unica.search {corpus:
  "names"}`, адрес по пути файла — аварийный `unica.resolve`. `"main"` ниже
  только пример, а не значение по умолчанию.
- Вердикт о готовности объекта спрашивает `unica.check {at}`, а не читатель:
  факты и суждение о них разошлись по разным входам намеренно.
- Адрес принимает русские и английские псевдонимы вида и отвечает канонической
  английской формой в `at`.
- Код объекта читают по адресу модуля (`…Module.Object.Method.<Имя>`), а не
  этим скиллом.

## Что отвечает узел

`props` несут свойства объекта под именами платформы — `Hierarchical`,
`CodeLength`, `Comment` и прочие из закрытого словаря наблюдаемых имён, — а
рядом с ними лежат собственные ключи узла: `kind`, `synonym`, `support`.

Составной факт вида разложен по ролям, а не спрятан объектом: обработчик
регламентного задания приходит как `handlerModule` и `handlerMethod`,
расписание регистра расчёта — как `scheduleRegister`, `scheduleValueField` и
`scheduleDateField`. Тип константы, определяемого типа и плана видов
характеристик приходит ключом `type` компактной строкой; восстанавливать из
неё строковый DSL не нужно — она и есть прочитанное значение.

`branches` перечисляет состав: реквизиты, табличные части, измерения,
ресурсы, перерасчёты, значения перечисления, графы, формы, макеты и команды.
Шаблоны URL HTTP-сервиса приходят ветвью `URLTemplate` с вложенной ветвью
`Method`, операции веб-сервиса — ветвью `Operation` с вложенной `Parameter`.

Все ссылки объекта наружу собраны в одну ветвь `Relation`: владельцы,
движения по регистрам, основания, ввод по строке, поля блокировки, источник
события подписки, зарегистрированные документы журнала, базовые виды расчёта
и пакеты XDTO веб-сервиса. Элемент несёт имя связи в `relation`, адрес цели в
`at` и её вид в `kind`. Элемент показывает наружу, поэтому спуск в него
отказывает: цель читается по своему адресу.

Корневые декларации приходят ветвями `StandardAttribute`, `Characteristic` и
`StandardTabularSection`. Стандартная табличная часть носит имя и адресуется,
а внутри несёт свою ветвь `StandardAttribute`. Характеристика прикладного
имени не носит — она названа парой источников типов и значений, — поэтому её
элементы остаются строками данных без адреса.

«Представление типа», «Представление объекта» и представления списка
ссылочного объекта лежат в `props` под именами платформы —
`ExtendedObjectPresentation`, `ListPresentation` и прочими: проекция их не
переименовывает и не сводит в одно поле.

`filter` с `sections` снимает лишние срезы ответа, `limit` ограничивает число
элементов ветви.

## Поддержка

Состояние поддержки объекта приходит в `props` ключом `support`. Оно прочитано
через Unica из `Ext/ParentConfigurations.bin` поставщика; разбирать этот файл
самостоятельно не нужно и нельзя. `Поддержка: на замке` или состояние только
для чтения — решение о выпуске, а не препятствие к обходу: правку такого
объекта веди расширением либо явным планом смены состояния поддержки.

## Чего этот вход пока не отвечает

Три факта прежнего читателя канонического дома ещё не имеют, и подменять их
догадкой нельзя:

- **предопределённые элементы** объекта: писатель у них есть
  (`predefinedItem.add`, `predefinedItem.set`, `predefinedItem.remove`), а
  канонического читателя у предопределённых элементов нет;
- **использование** объекта ролями, подписками и функциональными опциями;
- **членство** объекта в функциональных и интерфейсных подсистемах.

Если нужен один из них, скажи об этом прямо, а не выдавай за него соседний
факт.

## MCP examples

### Факты объекта

```json
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "unica.view",
    "arguments": {
      "at": "main:Catalog.Валюты"
    }
  }
}
```

### Ссылки объекта наружу

```json
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "unica.view",
    "arguments": {
      "at": "main:Document.Заказ.Relation"
    }
  }
}
```

### Вердикт об объекте

```json
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "unica.check",
    "arguments": {
      "at": "main:Catalog.Валюты"
    }
  }
}
```
