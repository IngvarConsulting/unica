# Как агент получает контекст для разработки Unica

Этот обзор нужен при настройке процесса и изменении маршрутов чтения.
Порядок работы задают [AGENTS.md](AGENTS.md) и проектные скиллы.

## Вход в работу

Общий вход — применимый `AGENTS.md` вместе с инструкциями хоста.
Для Claude Code [CLAUDE.md](CLAUDE.md) подключает его через `@AGENTS.md`.

Используй каталог имён, описаний и путей скиллов, переданный хостом.
Если проектных скиллов в нём нет, по AGENTS.md прочитай поля `name`
и `description` в `.agents/skills/*/SKILL.md`, выбери нужные и открой их тела.
References дочитывай по задаче, когда выбранный скилл направляет к ним.

## Нужный контекст

Разработку самого Unica начинай с `unica-development`; остальные навыки
подключаются по работе:

| Работа | Скилл |
| --- | --- |
| Исследование, изменение и ревью Unica | [unica-development](.agents/skills/unica-development/SKILL.md) |
| Выбор, написание, запуск и разбор проверок | [unica-testing](.agents/skills/unica-testing/SKILL.md) |
| Правило продукта или расхождение с кодом и тестами | [unica-rules](.agents/skills/unica-rules/SKILL.md) |
| Создание, редактура и ревью текста | [unica-writing](.agents/skills/unica-writing/SKILL.md) |
| Выпуск версии или проверка состояния релиза | [unica-release](.agents/skills/unica-release/SKILL.md) |

Навыки в `plugins/unica/skills/` описывают работу с 1С через готовый продукт.
При разработке Unica читай их по затронутой возможности. Общие внешние
скиллы выбирай по задаче и текущему каталогу хоста.

Для выбора исходников и проверок используй
[карту кода](.agents/skills/unica-development/references/code-map.md).
Применимые правила и фактическое поведение сопоставляй по
[AGENTS.md](AGENTS.md#источники-и-расхождения); согласование противоречия
с принятой гарантией описано [там же](AGENTS.md#противоречие-принятому-правилу).
Место планов, решений и других материалов задачи задаёт
[unica-development](.agents/skills/unica-development/SKILL.md#материалы-работы).

## Проверка настройки

Чтобы подтвердить работу маршрута на конкретном хосте, открой новую сессию
из проверяемого checkout. Для Claude Code в worktree учитывай
[настройку общего каталога скиллов](CONTRIBUTING.md#claude-code-в-worktree).

Проверь отдельно:

1. **Обнаружение.** Какие проектные скиллы хост предоставил в каталоге
   и с какими путями; при отсутствии каталога — доступен ли вход через AGENTS.md
   и чтение шапок.
2. **Выбор.** Какой скилл агент выбрал по задаче и прочитал ли его тело.
3. **Применимое правило.** Нашёл и прочитал ли агент нужную запись
   до решения; при разборе падения используй маршрут
   [unica-rules](.agents/skills/unica-rules/SKILL.md#расхождение-с-кодом-или-тестом).
4. **Исполнение проверки.** Какой тест действительно выполнился и с каким
   результатом; подтверждение запуска задаёт
   [unica-testing](.agents/skills/unica-testing/SKILL.md).

Выбирай сценарий по изменённому маршруту: локальная правка, MCP-вызов,
разбор падения с `check` или продолжение работы после передачи контекста.
Вывод об обнаружении, выборе, чтении правила и исполнении теста подтверждай
отдельным наблюдением в этой сессии. Результат субагента относится к его
окружению; поведение нужного хоста проверяй в самом хосте.

Для MCP-сценария используй сборку проверяемого checkout с нужным рабочим
каталогом и отдельным состоянием демона по
[CONTRIBUTING.md](CONTRIBUTING.md#mcp-inspector-локально).
Актуальную поверхность сверяй с [docs/tool-surface.md](docs/tool-surface.md)
и схемой инструмента используемой сборки.

В результате проверки укажи хост, checkout, выполненный сценарий и границы
вывода: какие из этих переходов проверены, а какие ещё требуют проверки.
